# `m2f` 不再和 person 的 trace 并跑：他那一局到了就是检查点；harness 有了验收行和一个完整包位

你的修正是对的，而且钱和判断两头都省：**person 自己的 trace 落进 `docs/evidence/m1.5-checkpoint/` 时，`m2f` 不跑。** 我上一轮把它写成「两端都会跑、他那一局排前面」，那等于用模型的判断替换他的判断，花的还是额度。今天改在规则所在的三个地方，没有改别的。

## 这条规则现在怎么写，它禁止什么

- **① 路：person 的 trace 到了** → `m2f` **不跑**。他那一局就是检查点，目录里只有 `person-<日期>.md` 一个记录文件；记录里写明「person 的 trace 已到，`m2f` 因此未跑」。
- **② 路：2026-10-25T12:28Z 到点仍没有他的 trace** → `m2f` 跑一局，模型 `github_copilot/gpt-6-luna`，写 `rerun-<日期>.md`，记录里写明「到点无 trace，故 `m2f` 代跑」。
- **它明确禁止三件事**：他跑过之后再让模型跑一遍；把两局并排摆成「对照」；为「完整性」花这笔额度的任何说法。
- **理由写在规则旁边，不只记成一句话**：重跑的唯一目的是不让 M2 盖在一扇没人关过的门上；person 跑过并给出判断，门就关了。再跑是拿模型的判断替换他的判断，而检查点要的正好是反过来的东西。

落在：`docs/plan.md` 的 `## 当前推进状态`（两条互斥的路 + 为什么）、`## M2 的工作包与依赖`（包表那行改成「只在没有 person 的 trace 时跑」，验收命令前加上「只有走到第 ② 路才跑」）、`## 恢复入口`（到点怎么跑那一条加了前置条件）；`docs/evidence/m1.5-checkpoint/README.md` 的等待窗段与「trace 先到」段，并写清两条路各产出哪个文件。

## harness：验收行已经写死，包位也占了，代码没写

它今天只有一行「仅完成设计讨论」，20 分钟的窗口给不了它一个能通过自己验收的版本。所以我没有写半个骨架，只把标准先写下来，下一轮的会话不用再定一次标准：
