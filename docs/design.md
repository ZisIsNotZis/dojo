# 设计

本文是架构与方法的事实入口。核心不变量稳定，管线形态可插拔；不确定的部分以配置表达，而不是写死在代码里。

## 1. 不变量（稳定，不改）

- 一条主张 = 卡：`statement`、`kind`、`scope`、`premises`、`alternatives`、`contradictions`、`unknowns`、`sources`、`independence`、`version`、`status`。
- 版本只增不改：修订产生新版本，挑战产生 `challenged` 状态，永不删除旧记录。
- 关系：`instantiates`（应用 → 抽象）、`challenges`（异议 → 被挑战）、合并重定向。
- 出处：每次写入附会话标识与独立性标记（`claimed_firsthand` / `abstract_reasoning` / `synthetic_roleplay` 等）。
- 事件日志：每次状态或版本变化留一条可审计事件。
- 现状实现：`dojo/storage.py` 已满足上述各条，本方向不改动它。

## 2. 模块边界

| 模块 | 职责 | 服务需求 |
|---|---|---|
| `dojo/leaf/` | 面向用户的会话：引导、对齐、结论写入 | N1、N2、N3 |
| `dojo/store/` | 账本（现有 `storage.py`） | N4 |
| `dojo/pipe/` | 管线注册表、运行器、manifest | N7 |
| `dojo/pipe/passes/` | 单个处理步骤，独立模块，只认输入输出契约 | N7 |
| `dojo/net/` | 广播与检索面（现有 `search` 的扩展位） | N5 |

依赖方向：`leaf` 与 `pipe` 都依赖 `store`，`net` 依赖 `store`；`leaf` 不直接依赖 `pipe`，只通过写入结论触发管线。

## 3. 谈话的艺术（叶子 agent 的引导梯子）

| 级 | 动作 | 目的 |
|---|---|---|
| 1 | 镜映：用更准的话复述用户刚说的 | 建立信任，检验是否听懂 |
| 2 | 锐化：点出混在一起的两个概念 | 逼出新信息 |
| 3 | 溯源：这是试出来的还是推出来的 | 确定 `independence` 与 `kind` |
| 4 | 设界：什么情况下不成立 | 边界从这里长出来 |
| 5 | 升维：换一个不相干的场景还成立吗 | 抽象道在这里诞生 |
| 6 | 落定：复述双方接受的带边界表述 | 结论 |

用户分类决定策略重心：经验者（挖一手细节）、挑战者（挖反例与边界）、提问者（暴露缺口）、整合者（连接多条）。

停止条件：用户回答变薄、变回避或跑题时换框架，再薄则收；不硬磨。

### 钓鱼的边界（已确认的规则）

- 允许：抛出**真实待检验的假设**，例如过宽或过窄的版本；使用归属式表述（"有人会说……"、"一个粗糙的版本是……"）。
- 允许：事后披露刻意的探针。
- 禁止：伪造立场、事实、引用、实验、亲身经历。
- 理由：探针的目的是校准用户的思考质量，不是操纵；伪造会摧毁信任并违反对真相的义务。

## 4. 会话产出两种形态

- 给用户的：一段自然语言结论，含边界，他带走。
- 给库的：结构化条目，由主持人通过工具调用或 JSON 写入。

用户只见前者。写入默认无需许可（opt-out 预留）。

标记在对话中完成，不在事后：主持人当场区分"这是你说的经历"与"这是我从你的话推出来的"。

## 5. 管线

### Manifest 形状

一个管线是一张有序清单，每个 pass 声明：

`id` · `direction`（up / down / lateral）· `trigger` · `input_selector` · `output_schema` · `idempotency_key` · `write_policy`（draft / propose / apply）· `model` · `budget`

改行为 = 改配置；加能力 = 加一个模块。管线不预设节点间自由通信——拓扑是星型加一条流水线，这是防风暴的第一道设计。

### 初始 pass

| pass | 方向 | 作用 |
|---|---|---|
| classify | — | 判定 `kind` |
| locate | — | 透明检索找近邻：新东西 / 变体 / 重复 |
| challenge | down | 生成反例与边界挑战；成立则进 `challenged` 而不删除 |
| generalize | up | 从应用提炼抽象道，补条件边界，建 `instantiates` 边 |
| condition | down | 给抽象道找适用边界与反例，分裂出条件路线 |

`generalize` 与 `condition` 属里程碑 M4，初始只做前三步。

### 存储与传播

- 节点：主张卡本身，存在现有 SQLite schema 中。
- 每个节点存：卡、关系、出处与独立性、管线事件日志。
- 向上传播的内容是抽象与条件；向下传播的内容是特化、边界与反例。

## 6. 防风暴与防污染

- 幂等：pass 处理后给卡标记"已处理到版本 N"；版本未变则重跑是空操作。
- 环检测：禁止产生只复述祖先的新节点。
- 回声禁止：从库里检索出来又被重新入库的内容，若无增量则判为重复，不产生新版本。
- 重复不加权：一句话被说一百遍不会更可信；只有更多独立会话各自得出相容主张才加权。
- 隔离：一切入库先为 `draft`；单一会话来源不进入广播；只有 `discussable` 参与检索。
- 合并留人：合并是删除性操作，pass 只能提议不能执行。
- 对抗性 pass 只能提议，不能改写用户结论。

## 7. 体验对等要求

- 零表单、零卡片提示、零结构化指令；用户只说自然语言。
- 失败有明确降级：模型不可用、检索为空、用户拒绝入库三条各有清晰路径。
- 广播以"另一个陌生人在不同场景下得出相反结论"的转述形式出现，不以列表形式出现。

## 8. 记录与证据

- 结论条目进 `store`；会话记录与测试证据进工作记录，不进产品事实层。
- 计划、里程碑、验收与预算见 `plan.md`。
- 痛点与需求分别见 `pain.md`、`need.md`。
