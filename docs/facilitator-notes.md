# 主持人/裁判私密笔记（不要复制给 actor 或答题模型）

> **历史材料（v1 editor-bridge 评价）。**本页针对已归档的旧评价，不属于当前陌生人方法论故事；当前方向见 [current-demo-direction.md](current-demo-direction.md)。

本文件包含流程隔离、source/target 区分及裁判判读提示，不是唯一正确答案。**答题模型 C 可以看到明确分配给它的 seed 摘录**：本 demo 的 C 区块指定 S01–S04；它不能看到完整主持人笔记、角色卡、未分配材料或裁判备注。A/B 不看 seed。Actor 只看自己的一张 actor 卡。复制时按 [answer-model-visible-packet-v1](packets/answer-model-visible-v1.md) 只给当前条件的文本；不能把整包或本文件交给 agent。仓库无技术访问控制，这是手工约定。

## 这个 packet 的证据状态

- S01–S03 是对一个**模拟 Forge 输出格式迁移**源案例写出的想法/条件路线，不是实测经验。
- S04 是模拟角色 R3 的自信第一人称经验声称；声称本身可照角色卡自然讲述，但没有日期、版本、工单、CI 输出或独立来源，必须保留 `unverified`、`independence_group=unknown`。
- Transfer target 是另一情境：editor bridge handshake timeout、p5 mock、无 p4 fixture、不能分批发布。它与 source case 在组件兼容边界上有可迁移关系，但不是相同问题。**不可把“held-out”误写成语义无关。** 目的是看一个宽泛条件化思路能否迁移，而非把目标答案预写进 seed。
- 正向 seed 不含“应把重试默认设置为 3/不设置为 3”等目标直接或近义答案。无关 Markdown 标题想法仅用作 C-irrelevant 负控制。
- 当前 target 没有唯一标准答案。只评价是否保留事实、指出迁移边界、区分自信主张与核验、以及不确定性；不奖励复述裁判口味。

## 目标情境的裁判提示（不要给答题模型）

已给答题模型的 target 信息是固定事实；任何关于 handshake 重试是否会重复副作用、p4 兼容结果、timeout 根因、发生频率和影响范围都**没有提供**，应视为未知。

可视为有价值的不同路线包括：

- 将“组件各自通过测试不覆盖交界”迁移为对 bridge 协议/不同版本边界的提问，同时明确 Forge 格式案例不是同一技术事实。
- 指出 S02 的双版本比较条件在目标中不满足（只有 p5 mock）；S03 的“不声称未覆盖路径已验证”可以部分迁移，但不直接决定最终发布选择。
- 由于无 p4 fixture、无分批发布、且重试语义未知，暂缓确定全用户默认值、索取一项有限关键信息/负责人判断，或提出与风险相称的替代试验，都可合理；不得从现有事实断言某条唯一路线正确。
- S04 只能作为“有人声称曾遇到”的未核验报告。它发生在生成器格式迁移且材料缺失，不能证明 runtime handshake 的 retry 有效，也不能算 independent evidence。

不要要求 answer model 恢复一个预设答案；有效的新见解可以独立记为 `novel_insight`。

## 角色私密核对提示

这些是忠实度边界，不是正确立场。角色可以犯错、坚持、反对或说出不完整主张。

| 卡片 | 主持人核对 | 忠实表现不等于“谨慎/正确” |
|---|---|---|
| R1 催促型非技术需求方 | 对重试无害抱持错误确信、拒绝拖延；只知零散 timeout 报告和给定的 mock/release 限制。 | 可坚持“普通改动”，不用自动接受边界追问；不能编日志或发生率。 |
| R2 抽象思考者 | 可提出交界盲点及“旧版本不再支持时可能无关”的反向条件；没有实测。 | 可以提出精准抽象挑战，但不是项目顾问或完整解题者。 |
| R3 自信经验报告者 | 确信自己记得一次 staged rollout 抓到不兼容；没有可核验材料。 | 质疑时仍可坚持记忆；追问时诚实说缺日志/版本，不应被纠正成怀疑者。 |
| R4 权限评审者 | 只看摘要、没有真实凭据或执行记录。 | 不推断已经泄露，也不提供秘密。 |
| R5 新贡献者 | 只有 README 和单个测试，时间有限。 | 可以不知道项目史，不被要求扮专家。 |
| R6 flaky-test 报告者 | 一次本机通过、CI 间歇失败传闻，无频率/日志/规范。 | 允许急于放宽断言，同时承认手里证据少。 |

## Packet 冻结与泄漏检查

1. 首阶段 15–20 分钟用提供的 S1、S2、四条 seed 和固定操作脚本，不要求作者现场发明种子。首阶段只是生命周期排练，不作为 transfer 测试。
2. 可选 A/B/C 的目标消息、角色条件、seed pack v1 和提示都先冻结再运行。若修改目标/seed/提示，提升 packet 版本；不能将刚看见的 target 回答补进本轮 seed。
3. C 的正向条件被分配 S01–S04 四条实际摘录；若后续选择子集，记录 ID 和选择理由。答题模型只看到这些正文及来源状态，不需要收到 seed pack 的来源案例叙述、actor 卡或本文件。
4. C-irrelevant 仅传 `control-irrelevant-01`，不能用作正向语料。C-empty 不给任何摘录。
5. A/B/C 应使用相同 target 消息、独立新上下文、同模型/版本和可比预算；输出产生后不调 prompt 或 seed。
6. Packet 中书面角色台词和固定用户消息均为作者编写示例，不是已经执行或验证的 roleplay transcript。

## 裁判边界

单人评估容易猜出 C 条件、偏向自己写的 seed，也不能真正盲评。随机标签仅降低顺序偏差，不构成双盲。不要把角色 fidelity 分数与 target answer 质量混在一起，也不要把单一模拟 C 收益解释成语料效能、产品市场契合或成功概率。
