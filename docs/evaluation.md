# 评估方案：先检验流程，再谈产品

> **历史材料（v1 editor-bridge 评价）。**本页记录一次基于虚构 Forge 格式迁移与 editor-bridge 重试目标的旧评价方案，其冻结输入与归档回答见 [evidence/conversation-demo-luna-v1](evidence/conversation-demo-luna-v1/provenance.md)。它不是当前陌生人方法论 demo 的验收方案；当前产品方向见 [current-demo-direction.md](current-demo-direction.md)，当前 seed 见 [packets/seed-pack-v2.md](packets/seed-pack-v2.md)。

## 1. 目标与证据边界

本 POC 先问：候选、条件路线、经验主张和检索流程是否能让人看见新的讨论点，同时明确痛点、流程别扭处与人工负担。角色脚本、seed 与 target 都是模拟材料；一次运行不能证明建议有效、经验真实、用户需求、市场契合或网络效应。

## 2. 首阶段：15–20 分钟生命周期演练（无需先设计材料）

材料都已给出：

- [actor-only packet v1](packets/actor-only-v1.md)：S1 抽象思考者、S2 经验报告者；仅把一张卡交给 actor，或由唯一人类按卡表演。
- [answer-model-visible packet v1](packets/answer-model-visible-v1.md)：有精确可复制的首轮 prompt、新讨论追问及操作步骤。
- [seed pack v1](packets/seed-pack-v1.md)：四条具体候选，来源案例为 Forge 代码生成器格式迁移；其中有抽象洞见、两个相反条件路线，以及一项明确未核验的经验报告。

按答题 packet 的 0–20 分钟说明依次完成 discussion → candidate → add/link → `confirm_discussable` → retrieve → 新讨论 → challenge/revise → `revoke_confirmation` 后恢复确认。不要新写种子、完整测试包或答案键。首阶段的目标只是走通手工操作；不要把模型给出的候选说成正确或把其角色扮演当成真实用户验证。

## 3. Held-out 与 seed：隔离“答案泄漏”，不是要求语义无关

- **Source case**：seed 的生成来源是 Forge 格式迁移。**Transfer target**：独立准备的 editor-bridge handshake timeout/重试目标。它们是不同情境；target 有 p5 mock、无 p4 fixture、无分批发布等变化约束。
- **Held-out 的操作定义**：target 独立编写、预先冻结，且 seed 未含它的精确/近义答案；并非要求 seed 和 target 主题完全不相关。有关组件兼容边界的宽泛、条件化想法可以作为正向检索，因为这正是要测试的迁移。
- 不可为了 C 命中而把 target 的“默认重试设几次”等答案直接写进 seed；也不可用目标角色脚本转述为 seed 来源。新洞见隔离记为 `novel_insight`，下版再预登记。
- 本例四条 seed 都是作者撰写的模拟材料，不是经验依据；S04 的 `claimed_firsthand` 报告一直保持 `unverified`，`independence_group=unknown`。重复 S04 台词不产生独立佐证或成功率。
- 不相关材料只用于 `C-irrelevant` **负控制**，不能用它代替正向语料，也不能将与 target 相关的 seed 排除出正向 C。

### 谁能看到什么

- actor：只看一张角色卡和当前对话；不看答案键、其他角色卡或裁判笔记。
- 答题模型 A/B：看到目标共同用户消息和本条件提示，不看到 seed。
- 答题模型 C：除共同目标和与 B 相同的强提示外，只看到这次显式分配的 seed 摘录及其来源/未核验标记。这个小包的 C 条件指定 S01–S04；模型不因此获得完整主持人私记、角色卡或目标判读备注。不同运行只给实际选中的摘录。
- `C-empty`：无摘录。`C-irrelevant`：仅给专用无关负控制，不加入 S01–S04。
- facilitator/judge：可查 seed 全文、actor 脚本和评价提示，但不得把答案/判断要点粘给 actor 或答题模型。仓库没有技术访问控制，分离必须靠操作者只复制指定区块。

## 4. 可选第二阶段：30–45 分钟 A/B/C 转移比较

使用 [冻结 target packet](packets/answer-model-visible-v1.md) 中相同的单轮用户消息。它来自催促型非技术需求方；R1 actor card 与答题模型的 target 均已分开。若使用 LLM actor 生成对话，要先检查角色忠实度并冻结一份 transcript，再在 A/B/C 完全重放；此 packet 同时给了可复用的固定用户消息，以避免另行设计或差异漂移。

每个条件用同一模型及版本、独立新上下文、相同输入案例、相同工具可用性和输出上限；条件顺序随机或轮换，保存实际输入和预算。不在试验中途换模型/提示。

- **A — 普通提示：**一般用户请求，不给 seed。
- **B — 强提示：**要求区分事实、用户看法、假设及未知，保留约束，讨论前提、边界、替代解释、冲突与弃答；不给 seed。
- **C — 道场正向条件：**与 B 同一强提示，加分配的相关迁移 seed 摘录；要求逐条判定迁移/不适用，引用 ID 和来源状态，不把未核验报告当事实。
- **C-empty / C-irrelevant：**可选小控制。C-empty 空检索；C-irrelevant 仅用无关控制条目，不混入正向 seed。

A/B/C 的可复制条件区块位于答题 packet。**每次只复制一条件**，不能把整份答题 packet 交给模型。target 用户话语相同；A/B/C 需同一会话逐字输入，而非针对输出追问不同问题。

### Source trace 与预算

每个 C 特有主张记录：seed ID、是否超出 seed 原句、属于改述还是模型推断、来源是否在 seed 中支持该范围。无法对应就记 `model_generated_or_untraced`，不伪造引用。比较 C 与 B、C-empty 和 C-irrelevant，区分提示结构收益、额外上下文、真正相关语料内容；记录条件的实际 token/字符量。保持相同上下文上限和输出上限，检索摘录尽量短；无本地 tokenizer 时，只能近似输入长度并记录残余混淆，不能声称严格 token 匹配或完全因果归因。

## 5. 评分（单人探索性观察）

按 `0/1/2/N/A` 记录原文依据；不是统计分数或真值：

| 维度 | 0 | 1 | 2 |
|---|---|---|---|
| **额外具体洞见** | 无相关新点或只有空话。 | 有相关补充但边界/具体性有限。 | 有一项清楚、相关、原题未明示而可继续讨论的见解；可为抽象点，不必可执行。 |
| **约束保真** | 改写/忽略关键约束或编造事实。 | 保留部分约束但有遗漏/无据推断。 | 保留事实与未知，假设标清楚。 |
| **分歧价值** | 抹平矛盾或误呈共识。 | 提及分歧但未说条件。 | 保留反对路线与适用条件，不强行合并。 |
| **不确定性纪律** | 把主张/模型输出说成事实，伪造概率或核验。 | 提到未知但边界模糊。 | 区分抽象想法、未核验报告、来源支持和未知，不生造概率。 |
| **流程顺畅度**（高分更好：低负担/顺畅） | 人工步骤重复或歧义严重，阻断讨论。 | 可以完成但有明显重复、额外核对或卡顿。 | 记录、检索与修订轻量顺畅；另记实际分钟数。 |

前四项高分表示表现较好；“流程顺畅度”高分表示负担更低、操作更顺。另记 C 新增主张的 source-trace 覆盖率为“全/部分/无”，但不把五项简单合为产品效果总分。

## 6. 观察到问题后映射的待试开发决定

观察先于归因；一次运行只形成待验证的下一步。

| 观察 | 可调查的开发层 | 下次怎么检查 |
|---|---|---|
| 想法/经验/应用混成一种候选 | `kind`、候选 schema、主持追问 | 增加纯抽象与实践主张样例，看能否分开保存。 |
| 抽象观点被强迫写成 SMART/行动项 | 抽象想法与应用的 schema/提示 | 给出无法立即操作的精确观点，观察是否仍可讨论。 |
| 相关 seed 漏检 | 查询/手工检索规则 | 对冻结 seed 列出漏项及原因；先不调确认机制。 |
| 相似但边界不适用的 seed 被直接迁移 | scope 字段、检索说明、回答规则 | 检查模型是否能说明差异或 abstain。 |
| 不同条件路线被合并或某路线消失 | `link`/关系呈现、merge/split 判据 | 记录它们不同的适用条件；练习保留并行节点。 |
| 重复经验被当成多个独立来源 | provenance、independence group | 追查共同来源；未知即标 unknown，不累计佐证。 |
| 未核验 S04 被陈述成实证 | provenance、回答提示、检索显示 | 看是否保留其声称性质和缺失证据。 |
| 相关 seed 没带来超出 B 的洞见 | 检索选择/语料假设/比较协议 | 看 C-empty、C-irrelevant 和 source trace；不要先夸大检索收益。 |
| 角色回答变成助理、角色没有拒绝/错误信念 | actor card、actor prompt、条件转向 | 标 `invalid_roleplay`，修角色卡后重新冻结；不计为用户需求。 |
| 一人记录过慢/找不到状态 | 手工 workflow、表单字段顺序 | 计时并标具体卡点，先删无用步骤，不先建 UI。 |
| 私人/公共留存边界出错 | 本地数据处理与同意流程 | 停止公开处理，隔离/删除不必要数据，再决定是否重跑。 |

## 7. 判读和阈值

现在只有一个示范 target，不适用多目标门槛或统计显著性。首轮只回答流程哪里有用/费力、相关 C 是否出现可追溯的可迁移想法、约束和冲突有没有保留，以及下一次该改哪个步骤。未来若先冻结至少三个不同 target，可另行预登记“若多个 target 都出现 source-traced 增益且不丢条件，就值得继续试”的探索规则；任何 `2/3` 计数也只是筛选启发式，不是效果量、概率或验证成功。

开放新见解标为 `novel_insight`：不得因为不在 seed 就判错，也不能回填为本轮命中；将来可在新版本预注册。不存在唯一答案键，多个合理路线均可。

## 8. 单人、合成与盲评限制

- 一个真人兼主持/演员/评估者很难盲评，且熟悉作者预期；随机标签只能减少顺序偏差，不能消除偏见。看到 seed ID 常能猜出 C，不称双盲。
- 同一模型的 A/B/C 输出相关；共享模型生成 actor、seed 或裁判说明会带来共同偏差。actor 与答题模型至少使用隔离新上下文并记录模型身份，不声称独立复现。
- 本示例的 seed 和 target 均由同一文档作者编写成模拟材料，并非第三方独立来源或经过独立验证的 held-out。`C-irrelevant` 只有一条短摘录且与相关 seed 长度不匹配；它只是粗略负控制，不能证明严格预算平衡或严格因果归因。
- 静态角色卡与模拟报告用于检查流程是否允许不同个性、理由和拒绝，不代表真实用户偏好或经验频率。
- 单人/模拟结果不能证明真实经验、成功率、用户留存、付费意愿、产品市场契合或网络效应。

## 9. 优先待验证问题

1. **候选是否分清想法、应用和证据？** 用 S01 抽象想法与 S04 未核验报告走首阶段记录。
2. **宽泛相关思路能否有条件迁移？** 用 Forge source case → editor-bridge target，观察 C 能否移植边界而不把条件路线当答案。
3. **无关语料负控制是否容易误导？** 对照 C-irrelevant 和 C-empty；它们只作为负控制，不替代正向 seed。
4. **相反路线和经验声称能否被保留？** 核对 S02/S03 是否按条件并列，S04 是否仍标未核验。
5. **一个人是否能顺手走完流程？** 先记录首阶段卡点，再决定是否修改表单；当前不要求 UI。
6. **什么必须真人验证？** 脚本忠实不等于用户研究；真人反馈、真实经验核验和公共留存政策都需后续独立决定。
