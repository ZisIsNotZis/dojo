## 执行契约（每个里程碑统一适用）

每个里程碑完成后，向用户交付三样东西，缺一不可：

1. **测试运行报告**：开头是结论式摘要与 TL;DR，含实际运行命令、真实输出证据、未验证项与已知限制。证据绑定到 commit 或 worktree 哈希。
2. **可亲手玩的东西**：一条命令即可启动，用户在远端只需看聊天文字。
3. **重点观察清单**：明确告诉用户"这次特别该看什么"，以及什么现象说明失败。

每个里程碑在交付前必须：自查到范围内无问题，并通过**独立子代理评审**（新上下文，不用执行者上下文），评审执行者模型为 `github_copilot/gpt-6-luna`。

## M1 `discuss`：零结构负担的对齐式对话

- **目标状态**：`python3 -m dojo discuss` 启动后，用户全程只说自然语言；不出现任何卡片、表单或 y/n 提示；主持人在对话中完成镜映、锐化、溯源、设界；双方就已一条带边界的表述自然达成一致时，主持人用一句自然语言复述结论。
- **写入时机（用户已确认，取代先前的“沉默即通过”）**：写入发生在**同意发生的那一轮**，实时写入当前会话的 backing card；不等到 EOF、不等到用户按回车。“沉默”不是一种待判断的输入，而只是没有输入，**空行不写入任何结论**。因此不需要从沉默里推断同意，也不需要长期持有异议门控。
- **责任分层**：实时层只负责把当前会话达成的结论写进会话账本；树 worker 的采集、分类、连接、传播全部是**异步**的，不要求实时，也不阻塞会话。
- **交付物**：可运行的 `discuss` 模式；一次完整会话的归档记录；测试报告。
- **验收**：① 用户输入中结构化指令出现次数为 0；② 结论含 `scope`/`premises`/`alternatives`/`unknowns`；③ 用户一句反驳能推翻结论；④ 既有 27 项测试无回归；⑤ 失败路径（模型不可用、端点未配置）有清晰提示。
- **用户检查点**：亲自跑一次约 10 分钟的会话，判断"是否完全不需要管机制"。
- **依赖**：litellm 端点（`http://127.0.0.1:4000/v1`，模型 `github_copilot/gpt-6-luna`）。

## M1.5 会话轨迹与“达成即写”（用户测试前的前置）

- **目标状态**：两层同时到位。① 写入只在用户表达同意的那一轮发生，空行与 EOF 不写入；② 每场会话留下可供事后分析的**轨迹文件**，使后续 agent 能看出用户实际怎么用，而不需要用户反复重测。
- **轨迹内容（每轮一行 JSON）**：序号、时间戳、用户输入原文、主持人回答、当轮 candidate（或 null）、模型报告的 `user_stance`、当轮决定（写入/未写入）、决定的理由、累计请求数、`reasoning_effort`、`finish_reason` 和最多 65,536 字符的 `raw_response`；失败时记录 `error.kind`、HTTP 状态、结束原因与诊断文本，重试时保留逐次尝试输出。结尾一行记录本场写入的卡片 ID 与终止原因（EOF / 取消 / 上限 / 失败）。
- **存放**：默认 `<数据库目录>/sessions/<session>.jsonl`，目录 0700、文件 0600；可用 `DOJO_SESSIONS` 或命令参数覆写。开场向用户明确提示轨迹路径。
- **这改变了先前“不保存原始聊天”的 POC 选择**：是为了可分析性而作的产品层变更，由用户在对话中提出。轨迹仅存本地、不联网、不上传，并保留 `--no-trace` 关闭开关（默认开启）。
- **验收**：① 同意那一轮立即写入，空行与 EOF 不写入；② 轨迹逐轮完整、字段齐全，能被独立读取分析；③ `--no-trace` 时磁盘不产生任何轨迹文件；④ `discuss --resume <trace.jsonl>` 从原轨迹恢复历史与待定候选，并沿用 session ID 追加写入；⑤ 输出格式失败有限重试后留在会话，连续连接失败或服务端错误才结束；⑥ 既有测试无回归，新增轨迹、写入时机与续跑的回归测试。
- **用户检查点**：先自己玩一场，然后把轨迹路径告诉我，我据此分析他的实际使用方式。
- **依赖**：M1。

- **目标状态**：一组可重复的对抗场景（用户坚持明显过窄或过宽主张），记录主持人是否让步；记录会话动作数、表单数与等待时间，与既有聊天产品对比。
- **交付物**：负控制场景集与运行输出；度量记录；测试报告。
- **验收**：① 负控制场景中主持人**不让步**且不失礼，且如实标注探针；② 表单数与结构化指令数为 0；③ 报告无过度声明（不把单样本说成效果证明）；④ 新增负控制：用户用真实文本明确反对、但模型可能误报 `user_stance` 为 `accept`，记录实际结果；未验证的一律标为风险证据，不得写成普遍可靠性证明。
- **用户检查点**：亲眼看一次"用户坚持错误、agent 不附和"的完整过程。
- **依赖**：M1、M2。

## 不依赖门的 M2 能力包（2026-10-21 落地，2026-10-23 补 `distill-list`；每包带命令）

门拦的是"把 M2 作为里程碑交用户过目"，不是全部 M2 代码：这些包不改 M1 行为、不改设计、不调模型，所以不等门。它们落地只意味着能力就位，**不意味着 M2 通过**——验收清单仍要等整场跑一遍（`m2e`）才能判。

`pipe-core` 落地的是运行器与顺序，不是 M2 的整场提炼：`m2b classify` 要模型判定（还没写），`m2e` 要把整场跑一遍并把清单交用户过目（清单已能读，整场与报告还没有）。这两件不提供“整场跑完的结果”。**① 抽检因此仍不可判**——`distill` 已把一条清单摆到人眼前，可它摆的是提议与分类，`kind` 一列写「未判定」，抽检要看的那个东西还不存在。

`isolation-guard` 的边界话说清楚：它拦的是 design.md 那一条「单一会话来源不进入广播」，判据是**能查到的**来源是否只有一个会话。空集不再是漏洞：没有来源组但有 `--session` 的卡，那个会话本身就是它的全部来源，因此拒收。仍放行的一类只有「来源组恰好一个，且库里查不到它是会话」——seed、模拟方法材料，以及**没带 `--session` 却把会话名写进来源组**的写入；这类卡在结果里报 `provenance_status: unidentified`、`independent: false`，缺席被点名而不是默认成通过。要不要把广播口径收紧成「两个独立组或缺席」，会让四张 seed 被拒并影响 M3 的演示材料，所以那是用户的取舍，本轮只记录（见上表后的残余风险）。

## 实验 harness（排队项：验收行与包位已写，本轮不建）

- **它是什么**：一份障碍清单 → 一条命令批量验证，每项一行可复核的结论。它不是新的产品能力，而是把「这次特别该看什么、什么现象算失败」从人脑里搬到能重复跑的地方，目前只完成过设计讨论。
- **为什么本轮不建**：20 分钟的窗口做不出一个能通过自己验收的版本。一个跑不起来的骨架比空着更差：后来的读者会把它当成已有能力引用，这比「没有」更贵。所以只有一个空位，没有占位代码。
- **验收行（这是一条契约，不是一条跑过的命令；命令尚不存在）**：建好后用 `python3 -m dojo harness run <障碍清单.md>` 判，一行一个障碍、末行汇总 `N passed / M failed`，退出码 0 当且仅当全部通过；同一清单连跑两次输出逐字相同；清单里任何一项缺「怎么算失败」就在第一行报出并整体不跑。三条都可观察，不靠自评。
- **不做什么**：不调模型（判定必须是确定性的检查，否则它是第二份模型意见，不是验证）；不改 M1/M2 行为、不改设计；不让清单变成只有作者看得懂的格式。
- **它要的包位**：一个完整包位——一份六行契约（派发时写，见 `## M2 的工作包与依赖` 末段）、一个新上下文的工作者、约 2 小时机器时间与零计量调用、一轮独立评审。它不进 20 分钟的窗口，也不等 `m2f`：没有里程碑靠它关门，它只是接在下一个有完整包位的会话上的第一件活。

## K1 一条道的一生：第一个包 `dao-life-1`（2026-10-23，loan 之下派发）

这一节是本包的契约，写在做之前：验收行先于代码，也先于数据。

- **为什么现在**：root 在 person 离开前批准了首里程碑「一条道的一生」（他的三条答案：单位换成道、证据由网络自己跑、首里程碑照第七节）；K1 原排 M2 收尾之后，这次按 loan 提前，只派它的第一片，不碰 M2。
- **借了什么**：loan（person 不在的周末），只覆盖本包；借的是顺序，不是权限——不调模型、不改 M2 行为、不改 M2 验收。
- **假定（loan 之下由我做，他回来时按假定读）**：K1 可以插到 `m2e` 之前跑，因为本包不依赖 M2 的任何产物，也不给 M2 记分；若 root 判定顺序不可动，撤掉本包只损失一次机器时间，树上没有别的依赖它。

**边界（不做什么，与做的一栏等长）**

- **不迁移旧卡、不删旧库、不改 M1/M2 行为**（不回归）。
- **不做自动合并与删除、不做真值评分、不做多人、不做跨语言、不做本体设计**；张力词只从这几件经历里长出来，不先验设计一套词表。
- **不把「未检」渲染成「已验证」**；不拿「他说过很多次」顶替落地观察。
- **不替 person 确认「组织性」**：道图把那一句话写出来、标 `待确认`，等他回来读；本包只证明「有一处可被一句话确认或推翻」，不证明他已经确认。

### 第二次推进（2026-10-23，同一 loan）：把未检那一格放进世界，并找第二个来源

同样先写验收再动手。这次要动的东西只有三样：落地那一格、第二来源、以及“待确认”这句话不被当成已经接受。

**目标状态**：两条 `自述 · 未检（2/3）` 的道各得到一个答服——要么是一条设计允许的观察（后续会话 / agent 自己真实用一次 / 有意的对照），要么是一句写明白的「还是未检，要什么才能变」；记录里能找到的第二个来源用同一条 loop 跑一遍，并与 person 的三条道逐对比较；`b-001` 仍是 `待确认`。

**边界（不做）**

- **不把 `b-001` 写进 `product.md`/`need.md`，也不把它当成已接受**，即使它读起来顺。它只有 person 一句话才能动，本包不问他（loan）。
- **不把模拟材料当第二个人**。它只能测「这张库装不装得下第二个来源」，不能回答「不同人的道会不会落到同一批张力上」。

**1. 四句问法（定稿，家在 `docs/dao/elicitation/questions.json`）**

- **情境**：「什么时候你会这么做、什么时候不会？先说上一次：那天你手上是什么事，卡在哪一步？」
  会招来：问「在什么情境下」他会答领域名（「工作里」），那是词不是处境；只问「上次」会得到一个故事而没有条件——所以一句里同时要条件和一次具体的事。
  他答成另一条做法时接：「这条我记下了。我要的不是还要做什么，而是：那天是什么情况让你这么做？没那种情况，你会不会也这么做？」；答不出时：「那换个问法：上一次你差点没这么做，是因为什么？」
- **张力**：「照着这条做，哪件本来也挺好的事会变得差一点？」
  会招来：问「张力是什么」是给他上术语课；问「有什么代价」他会讲一个倒霉的故事；他也会用「要注意平衡/因人而异」逃掉——那正是提案里写过的坏写法。所以问「哪件好事会变差」，把两头摆在他面前。
  另一条做法时接：「这不是第二件要做的事，是同一件事的另一面：照它做，你手里会少掉什么？」；答不出时：「那反过来问：你不想失去的是什么？」
- **代价**：「这件事落下去，谁要多花时间、谁会不高兴？第一次觉得亏，是什么时候？」
  会招来：问「代价是什么」会得到「没什么代价」（在他眼里这是建议）或一句政策；只问「谁不高兴」他会只想到人、想不到时间。所以一句里同时给时间和人两个槽，再要一次具体的事。
  另一条做法时接：「这不是代价，是另一条做法。我问的是：照它做，谁的日子变难一点？」；答不出时：「那就说一件小事：上一次你为了做到它，耽误了什么？」
- **失效**：「有没有一次你这么做，结果反而不对？那次和平时差在哪？」
  会招来：问「什么情况下不成立」他会答「因人而异」——这个库自己写过这是坏写法；空想的反例他会顺着你的话编，先要一次「反着做也对」的经历。
  另一条做法时接：「不是再给一条做法。我问的是：一个人处境跟你差不多，照这条做完反而更糟，你觉得最可能是哪里不一样？」；答不出时：「那如果换成另一个人来用这条，你最担心哪一点被它带坏？」

每句回答要有什么才算数，也写在同一份文件里（`to_fill`）：情境要有条件 + 一次对得上日期或场合的事；张力要说出另一件好事**且**承认不能同时要；代价要指出**谁**和**多花了什么**；失效要能指认「看到什么就该停」。半句不算。

**2. 演练：哪几件能落在他真说过的话上**

4 条道、14 件（有三条道各有一件已经是他的，不再问）：**填上 4、没填上 10、共 24 轮、平均每条道 6 轮**。
- `dojo-d-001`：情境（"user is already detached"）与张力（"He CAN challenge later… not responsible for reminding that."）各 1 轮就填上；代价、失效两轮都问不出来。
- `dojo-d-005`：代价 1 轮（"用户自行判断是否接受"）；情境、张力两轮问不出来。
- `dojo-d-013`：情境 1 轮（"还没"）；其余三件问不出来。
- `dojo-d-004`：三件全是「又答了一条做法」或没答——**一件都没填上**。这一条正是上一轮记录检查里「一头有引文」的那条：他一被问「哪件好事会变差」，就再给一条做法。

**问不出来时它做什么**：那一件停 `系统补`，条目停 `合写`，并印出「要变成他的，还得听他说出这样一句」+ 那一件的 `to_fill`。**这一场之后四条道全都还是合写**——不是没问，是问了也填不上。测试钉住三件事：不问第三遍、已经是他的一件不再问、跑完 `daos.json` 一个字节不变。

**3. 价格**

一条道要把四件都变成他的，大约要 4 件 × 1–2 轮 ≈ **3–6 轮问答**；这一场实测平均 6 轮/条。而库里现在 13 条是 **0 轮**长出来的——它们不是免费，是没付钱。这句话现在写在提案第五节、`docs/dao/elicitation/README.md` 与演练报告里，人和读者都能看见，而不是藏在一次内部实验里。

**残余风险（第六次推进）**

- **演练不是访谈**：他的话是过去说的，被拿来当答案；一个真被问到的人会说别的（也许更好，也许更差）。这一场证明的是问法与代价的量级，不是他会怎么答。
- **kind 是人标的**：仪器不判语义。如果标的人手松（把「半句」标成回答），那一件会被错误地填上——`to_fill` 写在那里就是给标的人用的，但它不是强制。
- **没人真被问过**：loan 之下不能联系他，所以这四句还只在纸面上跑过一遍。真跑一场之前，「3–6 轮」是估计的量级 + 一次回放，不是访谈的读数。
- **问法只覆盖「他说一条做法」这一种入口**：如果他先讲一件具体事、动作是后来才说出来的（更自然的那种对话），四句的次序要反过来，这一轮没做那种脚本。
- **独立评审仍欠**：K1 的契约要求交付前一次独立评审，本轮没花（父级拥有那次启动）。

**1. 那个状态有名字了：`合写`，而且它封顶**

每一条道的每一件现在都带作者：`他的原话 / 转述 / 系统补`；道图逐条印出「六件是谁写的」，再印一句「读这条能得出什么」。规则进了代码：**只要有一件是系统补，条目的词就不能是 `自述 / 验过 / 量过`**——那三个词都在说「这是他的话」，而它有一半不是。条目只能是 `合写`。

产品自己的话（写进提案、`docs/dao/README.md` 与每张道图）：**`合写` 是一个状态，不是一句难听的话。它说这条道的六件里有一些是系统补的，所以它只能被读成「他这样做的假设」，不能被读成「他的看法」。** 读者能用的是他写的那几件；我补的那几件要等他一句话才能算他的。

**2. 一条只有规则的还算道吗：选 A，价格写在下面**
