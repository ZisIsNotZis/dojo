# 道图：一条道（p-dojo）

这几条道说的是同一件事：你要我把「活」拿走，但要先把「样子」和「价」摆在你面前。
其中有一条边界是我读出来的、你没说过；一句话就能推翻它，见「连接与边界」。

**这张图是一个人的。**记录里只有一位真人的具体经历，所以它证明的是这张库能把一个人的经历收成一张带边界的地图，
不证明它装得下第二个人的道理。目标仍是「人类的道」；要走到那儿，需要一个真实第二人的一场会话（`docs/probe/tension-convergence.md`）。

## 这张图里有什么

1 条道，每条六件套齐全；1 条都有自洽与可反驳两张回执，落地那一格 1 条有观察、0 条是「未跑」。
另有 1 条材料写不成道（按缺的那一件：情境 0、张力 0、动作 1、代价 0、失效 0、归属 0、重复 0），0 条候选，0 对互相打架；它们都在「没进库的东西」一节。
六件按来源合计：情境 系统补 1；张力 系统补 1；动作 系统补 1；代价 系统补 1；失效 系统补 1；归属 他的原话 1。
这一行是这张图最该被读的一句话：他给得出「做什么」和「从哪来」，给不出「什么处境」「哪两个好处在打架」「谁付什么」——那些是我补的，标着「系统补」。

**按作者分：他的 0 条、合写 1 条、系统的 0 条。**

**「合写」是一个状态，不是一句难听的话。**它说这条道的六件里有一些是系统补的：它只能被读成「他这样做的假设」，不能被读成「他的看法」。
规则是硬的：只要有一件是系统补的，这条道的词就不会是「自述」「验过」或「量过」——这三个词都在说「这是他的话」，而它有一半不是。
它的等级被最弱的那一件封顶；要升，只能等他一句新的确认或推翻，走「推断怎么变成他的」那条路。
来源 id 1 个（账本里手写的不同来源 id；曝光账本 0 行）。这不是人数：id 是人手填的，系统没核过它后面是不是不同的人。同一个人的两次自述只留一个 id，所以两个 id 可能是一个人。只有引语、说不出自己在什么处境里怎么做的来源不计入（案例须有已观察到的动作）。曝光未知按「不独立」算：能确定的是这里没有第二个被核过的来源，不是共识。
提炼是这次会话的 manager 从记录里读出来的（凡读法处标「推断」），不是模型判定：这一包 0 次模型调用。

## 一条道长什么样

在 S 里，宁可 A 不 B，代价是 C；当出现 D 时，反过来。S 是适用域，A/B 是张力，C 是价格，D 是失效条件。

## 道一　repeat-d-001　重复看请求，不看结果；重试要有证据，不能靠猜

> 在一个已经抽身、检查交给系统的人那里，重放与「真的又做了一次」必须事后分得清：判重比整份请求，版本只跟库存状态走；断线时没有证据说明第一次没生效就不重发。代价是每个写入点都得把整份请求原样传下来，漏一个可选输入就退回旧错；当这笔操作本来没有可比的状态、或判重的人就是作者本人时，反过来。

| 件 | 内容 |
|---|---|
| 情境 | 谁：一个把判断交给系统的人：他只在自己想推翻时回来，重放与重试由系统自己发起；何时：同一个动作可能因为断线或再点一次而被发送两遍，而账本必须让后来的人分清这是哪一种；约束：人不会替你盯着哪一次是真的、账本要能回答「这行是重放，还是又做了一次」；领域：工具与流程、重试与幂等 |
| 张力 | 分清重放 vs 不让已完成的工作重开——两头是「把每次请求分别记下来，事后能分清」与「重放不改动已完成的状态，别把工作变回待办」。两样都要，而且会一起丢：只留第一样，重放让已完成的工作重新变成待办；只留第二样，两次不同的请求在账本里长得一样。根子是同一个：判据比请求少。（词表键：重复与重试——判重比整份请求，还是比结果；重试靠证据，还是靠猜）|

## 推断怎么变成他的

一条道里的「系统补」不是永久判决，但它只有一个出口：**他后来自己说了一句话，那句话逐字落进事件层，要么确认、要么推翻我补的那一件，并且带回执（谁跑的、对哪个版本、跑出什么）。**
确认的，那一件从「系统补」变成他的话，条目的作者跟着变；推翻的，必须写处理（改适用域或撤回）并把条目升版——反例不是降级，是改适用域。不是他说的不能晋，引文不在事件里的不能晋。

现在晋升 **0 条**：他还没就任何一条取舍说过话。现有记录对 2 件「系统补」的回答是：确认 1、部分 0、收窄 0、推翻 0、未表态 1。

**确认不等于晋升**：确认只说明他写过那两头，不说明他把「两者不能同时拿满」这句话说出来过。取舍要他亲口说，才算他的。
