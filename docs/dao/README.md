# dao/ — 一条道的一生（K1）

这一层把三层分开放，再用一条命令接起来：具体经历（事件层）、从它拔出来的道（提炼层）、网络自己在道上跑出来的回执（检验层）。
它不是新产品能力，也不是模型提炼；它证明的是：一条道能被完整地生出来、被网络自己检一次、把它没跑过的那一格原样印出来；两个来源能被同一条命令跑、并按受控词表逐对比出来。

这里有三个库：`person-dojo/` 是真人（本仓的使用者，`p-dojo`）的记录——13 条道、9 条写不成道的材料、1 条候选、1 对自相矛盾；`demo-strangers/` 是记录里唯一另一批具体材料——模拟语料，**不是人**；`probe-demo/` 是一场按探针格式写的模拟会话，用来证明「一场笔记能直接进这条 loop」。
后两个存在的理由只有一个：测这张库装不装得下第二个来源。它们都不回答「不同人的道会不会收敛」。

## 一条命令

```sh
python3 scripts/dao_life.py docs/dao/person-dojo --compare docs/dao/demo-strangers --at 2026-10-23T14:02:48Z
```

退出码 0 当且仅当每条道的自洽与可反驳都过、每条「落地未跑」的道都写明了要什么。它写五份生成物：两个库各一份 `receipts.json` 与 `道图.md`，外加第一库目录下的 `对比.md`。
`--check` 只判不写。不带 `--at` 时回执里的时间写成 null，其余不变（同一 `--at` 重跑，生成物逐字节相同）。不调模型、不联网、不连数据库。
只看一个库就去掉 `--compare`；词表默认取自数据目录上一层的 `vocabulary.json`，可用 `--vocabulary` 指定。

## 一场笔记怎么进同一条 loop

把 `note.md`（`docs/probe/tension-convergence.md` 的四行头、两节、五格格式）和一份 `extraction.json` 放进同一个目录，然后 `python3 scripts/dao_life.py <目录>`。
命令发现目录里没有 `episodes.json`，就把笔记推成整层，再跑同一条 loop（自洽、可反驳、落地、道图）；它不生成第二份拷贝，笔记始终是唯一的事实出处。

- **笔记能供的**：`情境`、`张力`（A ↔ B）、`方向`、`原话`、`锚`，加上头部的人与日期 → 事件层与归属。
- **笔记不能供的**：动作的落点与幅度、代价、失效条件、规则表，以及「这个处境里哪些轴取什么值」→ 写进 `extraction.json`，标「推断」。命令不替你决定这些，缺一项就拒收。
- **拒收**（理由写在第一行，且不写任何文件）：缺头部行、`date`/`minutes`/`sample` 不合格式、锚在「## 逐字」里找不到、张力少一格、原话不带引号、`A ↔ B` 不是一对、`extraction.json` 缺来源类别、笔记里有某条张力而提炼里没有它、提炼缺 `price`/`off`/`rule` 之类。
- **形状**：`probe-demo/` 是一场模拟会话——头部写 `sample: acquaintances`，但 `extraction.json` 的 `attribution` 是 `synthetic`，所以它的状态行是 `模拟 · 未检（2/3）`，不是一个人的道图。

## 一场讨论会话怎么导出笔记

`python3 -m dojo discuss` 的轨迹可以直接变成同一份探针笔记，不靠人抄：

```sh
python3 scripts/dao_session.py --trace <数据库目录>/sessions/<session>.jsonl \
  --out /tmp/lib --person p-demo --sample acquaintances
```

它写两份：`note.md`（探针格式；四行头取轨迹的日期与时长，`## 逐字` 是他的会话输入与四件回答，`## 张力` 是他「张力」那一件里说出的 A ↔ B）和 `session.json`（机器记录：哪几件在会话里被晋升、逐字回答是什么、轨迹与笔记的 sha256）。`--check` 只校验不写盘。

- **作者由会话决定，不由写提炼的人声明**：库目录里有 `session.json` 时，四件的 `part_sources` 只按它晋升过的那几件算；每件回答必须逐件匹配 `note.md` 的 `## 逐字` 中对应的完整行，并按情境→张力→代价→失效的顺序消费，不能只匹配子串或重用前面那件的行。`extraction.json` 把没晋升的一件写成「他的原话」时判「作者冲突」，库不建。声称动作是他的时，动作方向必须逐字出现在会话写下的方向里。
- **摘要不是防篡改**：`session.json` 记了 note 的 sha256，改 note 会被抓住；但把 note 与 `note_sha256` 一起重写照样能过，`trace_sha256` 也无法在库里重算。它防的是不一致的编辑，不是伪造——这个库不是防伪记录。
- **它不写 `extraction.json`**：动作落点、代价单位、规则表仍要人写，所以导出的笔记还要配一份提炼才能进 `dao_life.py`。这一半没有自动化。
- **拒收都比猜好**：一件没答、张力说不出两边、回答里含 `|`／引号／换行（探针格式逐字承载不了）、轨迹没有已写入的结论在前，命令都退非 0、说出是哪一件，盘上不留东西。
- **一场只有一条**：`discuss` 只在第一条写入的结论之后问四件，所以一场会话最多导出一条张力；第二条结论没有四件，也就导不出来。
- **下一步命令会印出来**：导出成功后它会给出带 `--vocabulary docs/dao/vocabulary.json` 的 `dao_life.py` 命令；库目录不在 `docs/dao/` 下时，词表不会自动找到，照印出来的跑就行。

## 文件是哪一种

| 文件 | 种类 | 谁写 |
|---|---|---|
| `vocabulary.json` | 落盘数据：受控张力词与动作词（13 个张力词、14 个动作词，2026-10-23 冻结） | 手写；新增一个词要写理由与它从哪条经历来 |
| `comparison.json` | 落盘数据：一次对比的读法与限制 | 手写；没有它，`--compare` 不跑 |
| `<库>/note.md` + `<库>/extraction.json` | 落盘数据（笔记库：事件层来自笔记，提炼层来自 `extraction.json`） | 手写：笔记照探针格式（或用 `dao_session.py` 由会话导出）；提炼写它不能从笔记知道的部分 |
| `<库>/session.json` | 落盘数据（会话作者记录：四件哪几件被晋升、逐字回答） | `scripts/dao_session.py` 生成；库目录里有时，`part_sources` 只按它算 |
| `<库>/episodes.json` | 落盘数据（事件层） | 手写：原话、路径、行号、来源类别 |
| `<库>/daos.json` | 落盘数据（提炼层） | 手写：六件套 + 张力键 + 动作键 + 一张可判的规则表 |
| `<库>/observations.json` | 落盘数据（落地观察 + `needed`） | 手写：观察与「要什么才能有这一格」 |
| `<库>/exposures.json` | 落盘数据（曝光账本） | 展示时追加 |
| `<库>/map.json` | 落盘数据（连接、边界、候选、互相矛盾的一对） | 手写：标 `待确认` |
| `<库>/refusals.json` | 落盘数据（写不成道的材料） | 手写：缺哪件、为什么、材料在哪 |
| `<库>/record_checks.json` | 落盘数据（现有记录对系统补的回答） | 手写：状态 + 引文 + 出处 |
| `<库>/promotions.json` | 落盘数据（推断怎么变成他的） | 手写：晋升要一句真实的话 + 回执 |
| `<库>/receipts.json`、`<库>/道图.md` | 生成物 | 命令生成，不要手改 |
| `person-dojo/对比.md` | 生成物 | 同上 |

## 六件里的哪一件是他写的（作者，不是证据）

每条道带 `part_sources`：情境、张力、动作、代价、失效、归属，各自标 `他的原话`、`转述`、`系统补`。不写就判不过——系统补的不能冒充他的。
**等级被最弱的那一件封顶**：只要有一件是 `系统补`，这条道的词就是 `合写`，永远不是 `自述 / 验过 / 量过`（那三个词都在说「这是他的话」）。`合写` 是产品里的一个状态，不是一句难听的话：它说这条道只能读成「他这样做的假设」。
现在：13 条全是 `合写`；情境、张力、代价 13/13 是系统补；动作 11 条是他的原话。**

`record_checks.json` 记现有记录对每一件 `系统补` 的回答（确认 / 部分 / 收窄 / 推翻 / 未表态，带引文）；`promotions.json` 记他后来哪句话把哪一件变成了他的。现在 26 条检查（确认 9、部分 9、收窄 2、推翻 0、未表态 6）、晋升 0 条。`map.json` 的 `red_flags` 记记录不同意我的地方。
一条道允许把某件读出来，条件是记录里点了它换掉的那一头，或点了一个可观察的翻转条件；两条都没有，就该进 `refusals.json`，不该硬填。
现在的合计（13 条）：**情境 13 条全是推断、张力 13 条全是推断、代价 13 条全是推断**；动作 11 记录 / 1 推断 / 1 转述；失效 2 记录 / 11 推断；归属 11 记录 / 2 转述。

## 写不成道的材料

`refusals.json` 一行一条：材料在哪（路径+行号）、缺六件里的哪一件（或「重复」）、为什么从这份材料里写不出来。
它和 `map.json` 的 `candidates` 不是一回事：候选是六件写得全、但案例撑不住；拒收是六件里有一件根本写不出来。
道图按件印出计数；缺 `missing` 或没写理由的拒收会判不过。现在 9 条：情境 3、张力 4、动作 2、代价 2、失效 1、归属 1、重复 1。

## 库里的两条关系

`map.json` 的 `contradictions` 记同一份记录里方向相反的一对：两条都留在库里，写清现在按来源顺序怎么读、以及要那个人一句话才能定。
同张力同方向的一对则由命令直接判不过（按替换试验它们是一条，留一条、另一条退回拒收）。现在：0 对同一条、1 对相反（`con-001`）。

## 来源分四类，状态词跟着来源走

`person`（他本人的原话）→ `自述`；`relayed`（root 转达）→ `自述（转述）`；`synthetic`（模拟语料）→ `模拟`；`unverified`（署名未核）→ `传闻`，只能当旁证。
一条道的出处里至少要有一条不是 `unverified`。模拟材料可以支撑一个库，但它的状态词永远是 `模拟`，不进独立性，也不进 person 的道图。

## 落地那一格什么时候算数

只认三种来源：他人的后续会话里自然出现的结果、agent 在自己的真实任务里应用并记下结果（自验，弱一档）、有意的对照（量过）。
另外两条是硬的：观察必须晚于案例（案例多为日粒度，所以同一天的观察要写到分）；自验必须写清 `applied_in`（在哪件真实活里用过）、`result`（结果）、`could_have_gone_otherwise`（本来可能怎样），缺一项就不计入，被拒的理由印在道图上。
没有观察的格子写 `未跑`，并且 `observations.json` 的 `needed` 必须写明要什么、为什么现在拿不到、谁能补——不写，命令判不过。

## 对比什么时候可以存在

一次对比必须带 `comparison.json`：命令只算逐对关系（同一张力同向＝变体，同一张力反向＝相反，不同张力＝无关）与词表覆盖；
「读法」和「限制」由人写，两边分开标。对比只读，不改任何一条道——这也是「第二个来源没有改动任何道」这句话能被检查的原因。

## 现在哪里还弱（别把它读成已完成）

- `dojo-d-001` 的落地是自验：写这条道的人自己判它在这件活上被用到了。它比「未跑」强，比一次对照弱。
- `dojo-d-002` 的落地是他人后续（弱）；`dojo-d-003` 仍是 `未跑`，`needed` 里写着要一次他付钱、价能算出来的决定。
- 第二个来源是模拟材料，作者与我们是同一只手：它重合或不重合都不说明人的事。记录里没有第二个真人。
- 词表只有 13 个张力词，任何「收敛」的说法在这个尺度上都不可测（提案第六节的命名漂移风险，小规模版本）。
- 十三条里只有三条有落地观察，且全是弱观察（一条自验、两条后续）；三个 `3/3` 读起来是「三条弱观察」，不是「三条已验证」；另外十条是「未跑」，每条都写了 `needed`。
- 13/13 可反驳「过」门槛不高：越界处境是从条目自己的失效条件造出来的，它证的是边界不是装饰，不是两个处境在世界上真的不同。
- 六件里的四件（情境、张力、代价、多数失效）是我读出来的：这个形状能把它们填得看起来很完整，填错也一样整齐。
- `b-001` 仍标 `待确认`，没有写进 `product.md` 与 `need.md`；一个测试钉住这一点。
- 有一条道是三条道指出来、但那六件经历还撑不住的（`cand-001`，关于「还没」是一扇开着的门）：它在 `map.json` 里是候选，不进库、不计进数目；候选长期不清理会变成第二个无人读的清单。
