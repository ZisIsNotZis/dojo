# 一场跑在真讨论循环里的会话（脚本化被访者，零模型调用）

这一场不是在讲一个新故事，是看四句问法接进 `python3 -m dojo discuss` 之后会发生什么：
结论在同意那一轮写进库（和以前一样），之后主持人接着问四件；问不出来的那几件停在系统补。

## 会话

```

你> 对，就这条。
你> user is already detached

```

前两句讨论（「把检查交给系统…」「对，就这条。」）是这场会话里的他，由 harness 写成、标明模拟；四句回答里能引到记录的都带行号，不能引的是「没答」。

## 结果

- 结束原因：`eof`；模型请求：2 次（全部来自脚本化的主持人，未联网）。
- 四件的问答：6 轮；变成他的话的：情境、张力；停在系统补的：代价、失效。
- 这场会话产出的条目（投影）：「把持续检查交给系统，人这一侧只保留「随时可以推翻」的位置。」——**合写（他写了 情境、张力、动作、归属；系统补了 代价、失效）**。

## 这一场说明什么

- **写作规则没变**：结论在他说「对」的那一轮就写进去了；四句问法是那之后的事（测试钉住：问第一件时库里的结论已经在了）。
- **问不出来就不填**：代价与失效没有回答，条目的这两件仍是系统补，所以它是**合写**，不是「他的」。
- **代价**：这一场 6 轮问答换来两件变成他的；另外两件问了两轮也没有，条目停在合写。
