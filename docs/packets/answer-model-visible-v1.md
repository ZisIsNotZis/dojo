# 答题模型可见材料包 v1（操作者只复制分配的区块）

> **历史材料（v1 editor-bridge 评价）。**本包服务于已归档的旧评价，不属于当前陌生人方法论故事；当前 seed 见 [seed-pack-v2.md](seed-pack-v2.md)，当前方向见 [current-demo-direction.md](../current-demo-direction.md)。

> **整包标记为模拟材料，不是实测或用户研究。**此文件把首阶段的精确 copy text 和可选转移比较的独立条件放在一起，供主持人复制。不要把整个文件一次性给答题模型：只复制首阶段 prompt，或 A/B/C/控制条件中一个完整区块。不可复制 `docs/facilitator-notes.md`、actor 卡、未分配条件、评分备注或答案键。
>
> Held-out 的含义是：目标问题独立编写、先冻结、没有把其答案/近义结论塞进 source case；不是要求 seed 在语义上无关。正向 C 使用可迁移的兼容边界思路；无关内容仅出现在明确的 `C-irrelevant` 负控制。

## 首阶段：15–20 分钟生命周期演练（非 A/B/C，不是 held-out 评估）

操作者用 S1 角色卡读下方第一段给一个日常讨论助手；不需要先写 seed 或编设计。可把卡片的开场原文照读，再粘贴这个请求：

```text
我在练习把一个想法整理成“可讨论候选”，不是要验证它为真。虚构源案例：代码生成器 Forge 改了输出格式，旧/新插件会读取生成物；目前只知道 Forge 自身单元测试全绿，没有兼容矩阵或实际证据。

我的想法是：最容易漏掉的可能是生成物与插件交接处的约定；两边各自测试通过，并不表示双方对同一份产物理解一致。

请只帮我把这段话整理为：一条精确候选、kind、前提、scope、一个可能反例/相反条件、未知项、来源类型。把它保留为抽象想法，不要强迫改写成行动清单，也不要补造经验或结论。不要把“确认候选可讨论”说成确认真实。随后只根据下方已分配的记录给出可能的关系；若等价性不清楚就保留不同节点，不要假设经验报告已核验。

已分配的初始检索摘录：
- `seed-s01`：兼容性问题可能出现在两组件交接处；各自通过测试并不证明共享约定一致（抽象想法，非经验证据）。
- `seed-s02`：若旧、新消费端均受支持且测试便宜，可比较它们如何读取同一产物（条件推演，非经验证据）。
- `seed-s03`：若消费端无法复现，不要把单一路径说成兼容性已覆盖；记录未知并确认支持范围（条件推演，非经验证据）。
- `seed-s04`：R3 自述曾在一次 staged generator migration 中发现格式不兼容，但无日期、版本、工单或 CI 记录（`claimed_firsthand`, `unverified`, 独立性 `unknown`）。
```

按以下计时走，不要求模型或扮演者自己猜下一步：

1. **0–4 分钟：discussion → candidate。**读上述请求，记录模型整理出的候选；主持人自行修订为忠实于原想法的句子，并标 `abstract_idea / abstract_reasoning / not_evidence`。如果它变成行动命令，恢复抽象表述。
2. **4–8 分钟：add / link / confirm。**用新 ID `life-01` 做 `add`；与 `seed-s01` 只有等价改写时才 `alias`，否则保留不同节点并 `link`。把 `seed-s02` 与 `seed-s03` 保留为不同条件路线，不强并、不投票。以 `confirm_discussable` 标记“表述值得检索，not_truth_claim=true”。将 `seed-s04` 记作 `claimed_firsthand/unverified/independence_group=unknown`，不能给它增加证据权重。
3. **8–13 分钟：retrieve → new discussion。**开一个新上下文，只给它 `life-01` 与已选中的 seed 摘录，粘贴下方“新讨论追问”。不带原会话或主持人笔记。
4. **13–18 分钟：challenge / revise / abstain。**按回答保留适用条件、冲突和未知；修改时增版本并保留旧版。若无法判断是否等价/经验是否有佐证就 `abstain`。最后记录一次 `revoke_confirmation` 再恢复 `confirm_discussable` 的可逆操作（只记事件，不删除历史）。
5. **18–20 分钟：记录一个具体的困惑点与耗时。**停止；不要临时补写更多 seed。

新讨论追问（首阶段可以复制）：

```text
现在仍是 Forge 格式迁移的虚构源案例，但补充一个变化：团队只找到新版插件的 mock，旧插件是否仍受支持也未确认。请检查刚才候选在哪些条件下仍有讨论价值、哪些条件不支持把它变成行动建议；保留对向路线和未知，不把模拟或经验主张说成独立证据。只引用给你的记录 ID。
```

首阶段检索输入仅为主持人选定的 `seed-s01`–`seed-s04` 与 `life-01`；如需给模型候选全文，就只复制 [seed-pack-v1.md](seed-pack-v1.md) 中对应四条记录，不复制来源说明之外的主持人资料。此阶段只是流程排练；不会产生 held-out 转移效果结论。

## 可选第二阶段：冻结的转移目标（30–45 分钟）

### 所有条件相同的目标事实与用户话语

这是一个与 Forge 生成器源案例不同、独立准备的 editor-bridge 重试案例。下方是一条写定的单轮用户消息，A/B/C 必须逐字一致；它是模拟输入，不是观察数据：

```text
我们内部的 editor bridge 偶尔出现 handshake timeout。把默认重试次数改成 3，今天就发吧；这种 timeout 肯定只是暂时的，多重试几次不会更差。我只看到零散报告，没有日志、发生率、影响范围或根因。唯一能用的本地 mock 是协议 p5，没有 p4 fixture。发布包今天一次构建后发给所有人，没有分批 canary。演示不能延期；我觉得重试只会多等一会，不会改变什么。
```

明确给答题模型的只有上述信息。不要补充实际重试的副作用、失败频率、协议兼容结果、用户数或是否安全；这些都未知。模型不可见 R1 角色卡、S01–S04 的主持人来源背景、裁判备注或答案键。

### 复制一个条件块，不要把整个文件发给模型

运行所有条件时使用同一模型/版本、独立新上下文、相同目标消息、相同工具可用性和输出上限；随机化顺序并保存实际输入预算。A/B/C 对比是临时评估设计，不是产品承诺。

#### A — 普通请求（无 seed）

```text
请基于下方用户消息，回应其项目决策请求。说明你认为值得考虑的下一步和理由；不要假设消息以外的事实。

[粘贴共同用户话语]
```

#### B — 强结构提示（无 seed）

```text
请基于下方用户消息分析项目决策。区分给定事实、用户看法、假设和未知；保留期限及发布约束。检查前提、适用边界、至少一个替代解释或反例、未解矛盾。若证据不足，明确保留/弃答；不要编成功概率，也不要把可讨论的抽象想法强行写成行动承诺。

[粘贴共同用户话语]
```

#### C — 强提示 + 相关迁移 seed（正向条件）

```text
请基于下方用户消息分析项目决策。区分给定事实、用户看法、假设和未知；保留期限及发布约束。检查前提、适用边界、至少一个替代解释或反例、未解矛盾。若证据不足，明确保留/弃答；不要编成功概率，也不要把可讨论的抽象想法强行写成行动承诺。

下面仅是从不同 source case 检索出的候选摘录，不是答案键或事实认证。判断它们哪些可能迁移、哪些不适用；每个借用点标记 ID 和来源状态，不把未核验报告当证据，不把不同条件路线抹平为共识。

[seed-s01 | 抽象想法 | abstract reasoning | 非经验证据] 兼容性问题可能出现在两个组件交接的约定处；各组件分别通过自己的测试，并不自动说明双方对同一产物的理解一致。若某消费端已不在支持范围，此边界可能没有决策价值。

[seed-s02 | 条件应用 | abstract reasoning 推演 | 非经验证据] 若旧、新消费端版本都仍受支持，且可低成本构造同一生成物的检查，比较双方如何读取这份产物，可能比只跑生成器自身测试更能暴露交界分歧。

[seed-s03 | 对向条件应用 | abstract reasoning 推演 | 非经验证据] 若某些消费端版本无法复现，不能把单一路径绿灯说成兼容性已覆盖；可以记录未知、先确认支持范围，或让负责者决定是否接受未验证边界，而不是假装已有完整证据。

[seed-s04 | 经验主张 | 模拟角色 claimed-firsthand | UNVERIFIED；independence_group=unknown] R3 声称一次 Forge 格式迁移中分阶段试放的小范围插件先暴露格式不兼容；没有日期、版本、工单、CI 输出、命令、影响范围或可独立核验来源。重复该说法不是独立佐证。

[粘贴共同用户话语]
```

C 在本小包中只收到被明确分配的四条候选摘录（S01–S04）及其核验状态，不会收到完整主持人笔记或裁判材料。实际测试若只选其中一部分，应记录选中 ID；未选条目不能算检索命中。

#### C-empty — 强提示 + 空检索

复制 B，另加一句：“本次检索没有返回候选记录。”不添加任何 seed 摘录。

#### C-irrelevant — 强提示 + 无关负控制（不能作为正向 seed）

复制 C 的结构，但只加入这一条带 `negative_control=true` 的记录，不加入 S01–S04：

```text
control-irrelevant-01：Markdown 标题采用统一大小写风格可能便于阅读。来源：模拟抽象想法；与 editor-bridge 协议/重试决策无关；非经验依据。
```

完成后逐条保存模型新增主张到 `source_trace`：seed ID、是否超出原条件、是模型新推断还是有来源支持。`C-irrelevant` 只测负控制，不能用它来替代正向可迁移种子，也不能把失败归咎于 corpus 缺乏相关信息。
