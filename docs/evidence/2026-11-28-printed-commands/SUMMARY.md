# 屏幕上的命令，复制出来就是那条命令

2026-11-28，任务 #3419 第一段。监督者一共报了四次，后三次都发生在我已经改过之后：

1. 用 `--db` 指定不同的库开场时，照抄退出或回看里的草稿命令，仍跑去默认库并找不到。
2. `DOJO_DB=chosen.sqlite3`（相对）在 A 目录开场，换到 B 目录粘贴，退出 2 并在 B 新建空库。
3. 一次性的绝对 `DOJO_DB`，复制提示到同一 HOME 的普通终端，提示仍省略库，打开默认空库。
4. 从默认库谈完，粘到平常用另一个库的终端：`show` 指错库；`--resume` 以 0 退出，**并把这一场
   的后半段写进了那个库**。

四次都在真实 CLI 上先复现再改（`.scratch/3419/probe_*.py`）。前三次我都只把刚报的那个例子改对，
所以第四次还有洞。监督者那句判断是对的：

> 请一次收齐显式、自选环境库和默认库的差别，避免继续逐例打补丁。

## 一条规则，没有例外

**每一张卡片命令、每一条回看/续谈命令，都写绝对路径；不看环境变量。**

以前的规则是「一条不带 `--db` 的命令会不会读到同一个文件就不写」，这个问题的答案取决于提问时
的环境：目录（相对 `$DOJO_DB`）、终端（一次性 `$DOJO_DB`）、还有「默认库」这件事本身
（一个终端可以用 `$DOJO_DB` 把默认库换掉）。印出去的一行字不可能带着这些条件。

| 库是怎么来的 | 屏幕印什么 |
|---|---|
| 没指定，用默认位置 | `python3 -m dojo --db <那个位置的绝对路径> show <id>` |
| `--db <路径>`，相对或绝对 | `python3 -m dojo --db <绝对路径> show <id>` |
| `DOJO_DB=<路径>`，相对或绝对 | `python3 -m dojo --db <绝对路径> show <id>` |

**为什么连默认库的短形式也不要。** 短形式的含义是「默认库」，而「默认库」恰恰是各个终端
不同意的那件事。我曾以为给最常见的情形留个短形式是好事——那是我的偏好，读者没要过；而它
换掉的是唯一重要的性质：粘贴回来的续谈会不会写进另一场没碰过的库。

同一类还有第二面：`$DOJO_SESSIONS` 也可能是相对的，所以印出来的轨迹路径一律绝对。

## 库路径仍然不进轨迹

我第一版把库路径写进 `session_end` 行，回看就能自己知道库在哪。监督者否掉了，理由成立：

> 路径属于本地命令上下文，避免把本机库位置变成原话文件或公开样例的一部分。

所以分工是：轨迹记「他说了什么」，库路径只活在这条命令行上。退出屏幕印它 → 用户复制时它
跟着走 → `transcript --db` 接住并往它印的命令里传一层。A10 量的就是这个。

## 改了什么

| 位置 | 之前 | 现在 |
|---|---|---|
| 退出屏幕的草稿命令 | `python3 -m dojo show <id>` | `python3 -m dojo --db <绝对路径> show <id>` |
| 四件问完的回执 | 回看命令不带库 | 带上 |
| `transcript` 里的 `show` / `--resume` | 不带库 | 用 `--db` 传进来的库（新选项，只影响它印出来的命令） |
| `freeze-materials` / `seed` 提示 / demo | 各自拼字符串 | 同一处渲染 |

新文件 `dojo/commands.py`：

- `quote()` 选引号规则：安全字节不加引号；只有空格和单引号加双引号（最常见、最好读）；
  其余单引号加 `'\''`。`!` 也算不安全，因为交互式 bash 会做历史展开。
- `absolute()` 把相对路径补成绝对路径。
- `dojo(...)` 生成 `python3 -m dojo [--db LIB] <args>`；flag 不加引号。
- `library_argument()`：**总是**返回同一个文件的绝对路径（或 `None`，当调用者没有库可写）。

之前有四处各自拼命令（`discuss` 用 `shlex.quote`、`storage` 自己写「有空格就加双引号」、
`transcript` 又是 `shlex.quote`、`demo` 直接 f-string）。四种拼法，两种是错的。顺带删掉了
`transcript.command()` —— 改完之后已经没人调用，留着就是第二处会再次走偏的渲染。

## 修的时候自己踩的坑

1. **探针假通过。** 第一版探针自己去粘贴 `python3 -m dojo transcript …`，而不是粘贴屏幕上
   印的那一行 —— 屏幕那行当时还没带 `--db`，正是缺陷所在。改成「粘贴屏幕印的」才红。
2. **两结果都算过。** 一度写过 `exit in (0, 2)`，等于没测；另有一处拿原始路径去 `in` 一条
   加了引号的行，永远不成立。都改成问 `commands` 自己、用真 shell 分词。
3. **README 示例被真跑。** `test_readme_views` 会执行每一块 ```` ```sh ````；我那段指着
   `/home/me/...` 的例子因此红了。改成 `mktemp -d` 的真块，录下来的屏幕放进 ```` ```text ````。
4. **两条红臂其实是绿的。** 它们让我发现两件真事：`transcript.command()` 已经没人调用
   （删了）；「四件问完」那行回执从来没被量过，因为 A 段总是早退。补了 A0 组。
5. **一条臂只靠抛异常变红。** 去掉引号后 `shlex.split` 炸掉整个 verify 进程，后面所有检查都
   没跑。一条无法被 shell 分开的命令应该是一条有名字的不成立，不是 traceback。
6. **同样的错又犯一次。** 写「看环境变量」那条臂时只换了判断语句，忘了那个文件已不再
   `import os`，臂靠 `NameError` 变红。崩溃不是证据。补上之后它红了 8 项有名字的检查。
7. **重名的检查。** 一次运行里两条都叫 `B3b`，让「哪条红了」说不清；已拆开。
8. **我在靠例打补丁。** 前三次报告我都只把刚报的那个例子改对，所以第四次还有洞，而且第四次
   比前三次严重（`--resume` 以 0 退出、写进另一个库）。真正的修法是把问题换成不依赖环境的
   问法，并且把「默认库短形式」这个自己的偏好也去掉。
