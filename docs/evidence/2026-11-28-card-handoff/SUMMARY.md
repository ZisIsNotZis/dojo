# 一条经验改过之后，真的改变了后来的一场会话

日期：2026-11-28。基线 `a4b16b7`（上一片，`candidate/lesson-loop`）。离线；0 次模型调用。

## 这一片回答的问题

监督者：「一条经验经过讨论、质疑和再使用后，真的改变了后来做的一件事。找具体场景走完
整个过程，保留当初的证据和后来为什么改主意。」

上一片（`2026-11-27-lesson-loop`）已经把「为什么改主意」送到了**只读出口**：`search`、
`broadcast`、`show`、`export` 都会带上 `revision_basis`。那一步之后，后来的人**能读到**
理由。但「改变了后来做的一件事」还差一步：**后来那场会话本身没有被那张卡改变**。

## 改之前实测（`probe_card_gap.py`，在 `a4b16b7` 上）

一场会话定下一句 → 一个反例质疑它 → 他改窄并说了为什么 → 新一场开始，说「我想接着上次
那条继续想」。那一场模型收到的完整上下文是：

```
用户人物档案（…）：
# 人物档案
…

用户本轮自然语言输入：
我想接着上次那条继续想

请按系统约定返回 json。
```

- 上下文里有那句被改窄的话：**False**
- 上下文里有他改主意的理由：**False**
- 上下文里有被改掉的那句：**False**
- 屏幕上提到这张卡：**False**

屏幕印的是 `NEW_SESSION_LIMIT_NOTE`：「新开一场不会自动带上以前讨论过的结论；上一场
定下的那条要在这里说出来，这一场才接得上。」

**这句话本身是真的**，但它把「再使用」的全部工作交给了人：他得记得上一场说了什么、记得
自己后来改过、还得把改动和理由一起再说一遍。这就是「经过质疑和再使用」这件事在产品里
不存在的原因——不是信息丢了，是**新会话没有任何入口能拿到它**。

## 改了什么

`python3 -m dojo discuss --card ID`：把库里已有的一张卡交给这一场。四条一起成立才算数：

1. **屏幕点名这一版。** `handoff_block()` 印出是哪张卡、现在这句、**被改掉的那句**、
   以及他当时**为什么改**。没改过的卡不印「原来是」；没有 `revise` 行就是没有，不编。
2. **请求里真有它。** `handoff_for_model()` 把同样的三件事放进模型上下文，并写明它是
   「资料，不是用户本轮说的话」。屏幕说带了、payload 里没有，就是这一系列一直在修的
   那种缺陷，所以这一条在 `verify.py` 里是单独的检查项。
3. **只发一次。** 交付只随第一个**真的拿到回答**的请求发出（`handed_sent` 在拿到答案后
   才置位）。每轮都重复，会诱导模型把一张卡当成他最新说的话；而第一轮失败就把卡丢了，
   这一场又会变成「自称带着卡、其实没有」。
4. **重复不算新到达。** 交付的那一刻写 `record_read(..., surface="discuss")`——这正是
   回声门 `_session_already_saw` 唯一读的东西。所以「本场只是重新说了一遍」这句话是
   由记录支撑的，不是礼貌用语。

另外两件顺带修掉的：

- **本地错误先说本地的话。** 在**真实 CLI** 上走出来的：`--card c9` 打错 id 时，先报的
  是「未配置 DOJO_LLM_BASE_URL」，把人送去查端点设置。现在 `cli.py` 与 `run_discuss`
  都先解析卡；读不出来就退 2、不发请求、不提端点。
- **合并过的卡不会被误报成「没合并」，也不会把没合并的报成「已合并」。**
  `redirect_chain` 永远以被请求的 id 开头，用真值判断会把普通卡也印成「已被合并到…」。
  现在只有长度大于 1 才算合并。

### 12 句收场话：按「说的是这一题」还是「说的是这场谈话」分开

它们在 `dojo/elicit.py` 里，`SKIP_PATTERNS` 与 `STOP_PATTERNS` 各认领一部分，**分界线是
主语**，不是语气强弱：

| 句子 | 读数 | 理由 |
|---|---|---|
| `这题就到这儿吧` / `这一题我没什么要补充的` / `这道题算了` / `这个问题先不聊了` / `我不说了` | `skip` | 说的是**这一题**。读成 `stop` 会声称他结束了整场，他没这么说 |
| `算了吧` / `算了算了` / `我该走了` / `我说完了` / `今天先到这儿` / `先聊到这儿吧` / `别说了` | `stop` | 说的是**这场谈话** |

两个真踩过的坑：

- **正则里的选择顺序是有意义的。** `(?:问题|题|件|个|问)` 让 `这个` 先命中 `个`，剩下
  `问题先不聊了`，没有任何模式接受。把 `个` 当作 `这` 后面的量词才行。
- **红臂改错文件也会是绿的。** 我的臂 E 第一次改的是 `SKIP_PATTERNS`（那些模式确实
  在那里），所以它没往 `STOP_PATTERNS` 里加任何东西，绿得毫无信息。复核自己的教训
  在我这里又发生了一次：**一条没落地的红臂不是证据。**

验证：`probe_winddown_corpus.py` 的 10 句材料仍然全是 `answer`，7 种既有跳过仍然全是
`skip`；新增的 `test_the_wind_down_forms_the_review_found_never_become_material` 逐句
断言读数，并且同时断言 `is_stop_statement` **不**认领那五句（只断言顺序会漏掉复合臂）；
六条红臂 `.scratch/3363/redarm_review.py` 全部真红。

## 这一片没有做的事（别当成已解决）

1. **一次只能交一张卡，得知道 id。** 没有「按那句话检索」。`--card` 读的是已有 id，
   不是自然语言。要用检索，得先决定「检索到什么程度算同一件事」，那是产品决定。
2. **只影响这一场，不改卡。** 新一场里他推翻或改窄，走的是原来就有的 `revise` 路径；
   `--card` 自己一个字节都不写卡，只写读记录与轨迹。
3. **`load_resume_trace` 现在认识 `handout` 行**，但旧轨迹里没有它，续跑旧轨迹读不到
   「这一场当初被交给了哪一版」——只能从读记录倒推，而读记录只记 id 与时刻。
4. **交付给模型的只有七个内容字段加理由**，不含 `time_basis` / `source_basis`。
   一张卡是谁、什么时候、以什么来源立起来的，模型这轮仍然看不见。
5. `--card` 与 `--no-trace` 可以一起用：卡会交给这一场并写读记录，但轨迹里没有
   `handout` 行。这是有意的（`--no-trace` 就是不存原文轨迹），但**读记录的 `reader_session`
   仍然指向一个没有轨迹的会话 id**，读的人要能接受这一点。
