# 打字说的「先到这吧」被记成了回答

上一片（`2026-11-27-closing-line`、`2026-11-27-receipt-truth`）修的是**按 Ctrl-D 结束输入**
那条路：回执说他「没答出来」，其实他只是不想继续。那一片之后，同一个毛病还在**打字**这条路上，
而且更糟——他没有结束输入，所以会话继续问了下去。

## 改前实测（`probe_stop_words.py`、`probe_last_part.py`，在 `666263b` 上）

第二题（张力）时输入这些话：

| 他打的字 | 轨迹里的 reading | 进了 collected | 屏幕说 |
|---|---|---|---|
| `算了，先不说了` | `answer` | 是 | 你答了 情境；**你提到跳过的那句我按原话收在 张力 里** |
| `先到这吧` | `answer` | 是 | 你答了 情境、张力 |
| `不想聊了` | `answer` | 是 | 你答了 情境；**你提到跳过的那句我按原话收在 张力 里** |
| `就说这么多吧` | `answer` | 是 | 你答了 情境、张力 |
| `我没什么要补充的` | `answer` | 是 | 你答了 情境、张力 |
| `这几题我不想答了` | `skip_rest` | 否 | （正确） |

两个独立的问题：

1. **他明明在说「别问了」，系统把这句当成了那一题的材料**，然后接着问代价、失效。
   其中四句还会触发「按原话收在…里」，因为他打的字里有「不说了」「不聊了」这类词，
   被 `reads_like_a_skip_request` 当成「他提到了跳过」——**而他没有提过跳过**。
   这正是这两片一直在修的同一件事：回执描述了一件没发生的事。
2. 另一条同源缺陷：`declined_count` **记的是他说的数，不是实际搁下的数**。
   「接下来五题都先不答」而只剩两件时，`declined=["代价","失效"]` 却 `declined_count=5`。
   字段名说「count」，内容是「他说的数」。

## 改法

### 1. 收场话有自己的读数（`dojo/elicit.py`）

`classify_answer` 多一种结局 `"stop"`，由新函数 `is_stop_statement()` 判定，词表在
`STOP_PATTERNS`（八组整句模式，覆盖「算了」「到这儿为止」「就说这么多」「先这样」
「没什么要补充的」「先撤了」「不想聊了」这些说法）。

两条边界，都是用真实句子量出来的：

- **只认整句，且不超过 12 字。** 收场词在真材料里到处都是：「说到这儿我想起来，那次是周三」
  「就这样吧，我们当时是这么定的」「我算了吧，这事我后来没再提」。这些必须还是材料。
  这一点有红臂守着——把整句匹配换成前缀匹配，测试立刻红（见下）。
- **`skip` 与 `stop` 的分界是「说的是问题，还是说的是谈话」。**「不想说」「不说了」
  是这一题不答（原样保留为 `skip`，一个字没动）；「不想聊了」「先到这吧」是这场不聊了。

### 2. 收场就真的结束（`dojo/discuss.py`）

主循环在 `skip` 分支**之前**拦 `stop`：印「好，就到这儿。」，打回执，结束会话。
轨迹里那一行是 `reading="stop"`，**不会进 `collected`**，也不会变成 `supplied`
（「没答出来」是另一个错词）。

轨迹的 `session_end.reason` 仍然是 `eof`：对他来说这是同一件事——会话在桌上留着一张草稿结束。
差别只在他看到的回执上，所以内部不必多一套词汇。

### 3. 回执说「你说到这儿为止」

`closing_text` 新增 `spoken_stop`。同一格有两种事实，不能合用一句话：

- 输入在他面前断掉 → 「问到 张力 时你**结束了输入**」
- 他说了「先到这吧」→ 「问到 张力 时你**说到这儿为止**」

对打了「先到这吧」的人说「你结束了输入」，描述的就是一件没发生的事。

### 4. 两个数分开存

`elicitation_state` 的 `declined_count` 现在是 `len(declined)`——**实际搁下了几件**。
他说的数单独放在 `declined_stated`，一路接到 `--resume`（`elicitation_declined_stated`）
和 `session_end` 的摘要里。

回执因此能说出两个事实：

> 你说接下来 5 题先不答，剩下只有 代价、失效，就没再问。

旧版在数对不上时会退回「你说剩下的先不答 代价、失效」——不撒谎，但把他提过的数丢了。

### 红臂（`redarm.py`，就在这个目录里）

```
python3 docs/evidence/2026-11-27-typed-stop/redarm.py .
```

把修好的东西一点点改回去，看测试会不会红。每一条都 `cp -a` 一份树再改，不动工作区。
六条全部真红：

| 改回去什么 | 结果 |
|---|---|
| A 删掉循环里的 `stop` 分支 | 红 3 项（张力又回到 `collected`） |
| B `is_stop_statement` 永远假 | 红 3 项（同上） |
| C 回执对收场话仍说「你结束了输入」 | 红 2 项 |
| D `declined_count` 改回他说的数 | 红 1 项（`2 != 5`） |
| E 整句匹配换成前缀匹配 | 红 1 项（`算了，没谈拢` 被吞） |
| F 收场话退回旧的 `answer` 读数 | 红 3 项 |

**E 这一条值得记下来**：它第一次跑是绿的。原因是我的边界测试只用了长句，
而 `is_stop_statement` 还有个 ≤12 字的长度闸，长句根本走不到模式匹配那一步——
测试证明的是那个闸，不是整句匹配。补了七个短的（`算了，没谈拢`「到这儿为止都顺利」…）
之后才真红。**一条绿的红臂不是在说「这里没问题」，而是在说「这条测试没咬住它」。**

## 没解决的问题（别当成已解决）

1. **收场词表是穷举的。** 没说到的说法（「我该走了」「先忙别的」）仍然会被当成回答
   存进材料。「我得走了」在表里，「我该走了」不在。没有模型参与，这就是它的边界；
   要更宽就得先决定「多不确定才算收场」，那是产品决定。
2. **`session_end.reason` 仍是 `eof`。** 读轨迹的人分不出「他按了 Ctrl-D」和「他说了先到这吧」。
   这是有意的（对他是同一件事），但如果以后要做「他主动收场 vs 掉线」的统计，得加一个字段。
3. **`declined_stated` 是新增字段，旧轨迹里没有。** 旧轨迹读出来是 `None`，回执会走
   「剩下的先不答」那条分支——对旧数据不算错，但别指望它能倒推他说过的数。
4. **上一片留下的既有偶发失败仍在**（`test_storage` 里微秒时钟对秒级时钟），与本片无关，
   已在那一片的证据里写清复现方式。
