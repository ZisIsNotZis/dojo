# 他说过的四件，终于到了那张卡上

> 当前复跑用 `/认可` 认可屏上核对过的版本，再走四问。下文原始读数和屏幕保留作历史记录；现版读数以 `verify.py` 为准。

2026-11-28。基线 `d77d2c2`。离线：模型是本地回环桩，回答是文件里写死的常量——
**这不是真人会话，也不是模型的判断**。全程只走标准 CLI。

## 这一片回答的问题

产品对它的用途只说过一句话：一条道里的情境、张力、代价、失效必须**从他嘴里出来**，
否则那条道就是 `合写`，它的 `part_sources` 写着 `系统补`。`discuss` 也确实问了这四件，
把他的话留在轨迹里——然后就没有下文了。实测（`.scratch/3474/probe_promote.py`，
标准 CLI、四句具体的回答）：

```
四件问答：reading=answer, collected=true  ×4
session_end.elicitation: promoted=[]  part_sources=系统补 ×6
回执：这些原话留在本场记录里，没有写进卡片。
```

他答了四件具体的事，卡上还是模型写的那一版+模型补的条件。过几天他回来找，或者把这
张卡带进下一场讨论，**看不到自己说过的任何一句**。这就是「他的道」和「模型的推断」
在这个产品里一直分不开的地方——不是信息丢了，是**从来没有一个写入口**。

## 两个词，两件事，以前是这样读的

| | 什么意思 | 改之前 | 现在 |
|---|---|---|---|
| 收下 | 磁盘上留了他的字 | 真的（在轨迹里），回执也说 | 照旧 |
| 这一件有材料了 | 卡片上带着他的字了 | **从来没有发生过** | 一次写入，四个回答逐字进卡 |

## 改了什么

**`promote_answers`（`dojo/storage.py`）——一条卡片的回答，写进自己的表。**

- **不是写卡片的状态。** 状态一写就会 `version+1`，而 `pipeline_marks` 拿版本号判断
  「这件已经处理过」：只是留一句他说的话，会把做完的工作重新变成待办。这一点是旧测试
  `test_material_change_revises…` 当场抓住的，第一次实现就是写状态。它也会改
  `wording_digest`，让他之前那次「认可这套说法」失效。两件都不能接受，所以另建 `answers`
  表：`(candidate_id, field)` 为主键，存原话、会话、时刻、当时间的问句。
- **不碰句子、不碰条件、不碰状态、不添来源。** 他的话是这张卡的**材料**，不是它的措辞，
  也不是第二次到达：`independence()`、`broadcast`、认可摘要、检索门都读不到它。
- **写不进去就不说写进去了。** 第一次实现把「打算写的那几件」当成了「卡上有的那几件」，
  库里每一条都写失败，回执却照旧说四件都附上了。现在写完要**从表里读回来**，回执说的是
  读到的结果；读不到就印 `这些原话没能附到卡片上（原因）`。
- **可以撤。** `unpromote_answer` 把一件拿下来，原来那句留在账本的 `from` 里。

**回执和开场白都跟着改。** 回执现在说「你在这几件上的原话现在也附在卡片 X 上了」，并
逐个点名**没附上去的那几件**（跳过、没遇到过、没答出内容）；开场白原来保证「卡片上的字
这一版仍全算我写的」，在这之后那半句仍然真、但读起来像「什么都不会发生」，所以改成说清
楚哪一部分会去哪。

**`part_sources` 仍然是 `系统补`，这是刻意的。** 它回答的是「这一栏的字是谁写的」；他
的话是**另存在旁边**的，没有变成 `scope` 或 `contradictions`，这场会话也不判它有没有答
到点上（那是 `to_fill`，得由读者判——上一片的结论，这一片照旧）。所以轨迹里另加一个
`answers_attached`，说的是另一件事：卡片上有没有他的话。

**三个读出口都能读到他的话。**

- `search`：他的失效例子（`没发出来 路上 才发现`，卡片正文里一个都没有）现在能找回这张
  卡，并且明说「你记得的字不在卡片写的那句里，而在附在这张卡上的你的原话里」，下面逐条
  印原话。命中只有在他自己的屏幕上才算——`retrieve` 不加 `for_reading` 时搜索范围一字
  未变，所以模型能拿到的东西没有变宽。
- `discuss --card`：开场屏和发给模型的请求都带上他的话，并标明**这是他的原话、不是这张卡
  的措辞、也不是对它的赞同**。
- `show`：`answers` 与 `candidate` 并列，`candidate` 仍是逐字节的存储状态。

## 复核在发布前拦住的那一处：`--no-trace` 是个假开关

主管的读法（干净导出、标准 CLI）：明确用 `--no-trace` 开一场，屏幕说「这些原话只在这次
对话里用过」，确实没有轨迹文件，**而 `show` 读到了四条逐字原话**。我自己另写了一个探针
重走三场（`.scratch/3480/probe_notrace.py`）确认：

| 场景 | 回执 | 轨迹文件 | `show` 里的 `answers` |
|---|---|---|---|
| 正常讨论 | 附在卡片 … 上了 | 有 | 四条 |
| `--no-trace`（修前） | 这场不留原文 | **没有** | **四条** |
| `--no-trace`（修后） | 没有附到卡片上 | 没有 | 空 |
| 事后手工 `promote` | —— | 没有 | 只有那一条，且能搜到 |

根因是我这一片自己造成的：`promote_answers` 把回答写进库，而**卡片也是同一个盘上的文件**；
`--no-trace` 原来只关会话记录。开场白早就写了「不会附到卡片上」，所以错的是代码，不是屏幕。
修法：`trace is None` 时**不写**，回执改说「这一场你选了不留记录，所以你的原话没有附到
卡片上」，并指出想留就自己跑 `promote`。`promote` 仍然写——那是他本人事后敲的命令，不是
一场声明过不留记录的会话替他决定。

两个新读数（E 段）+ 两条新红臂：`no-trace-keeps-his-words-on-the-card-anyway`、
`the-quiet-session-says-nothing-about-the-card`。README（中英两版）里那段自相矛盾的话改成
按开关分两种情形讲，`--no-trace` 的帮助文字也改成覆盖卡片。

## 复核又拦住一处：那条原话回不到它那场

`show` 里每条原话带一个 `trace` 字段，但它是 `datetime.now().isoformat()`——**晋升的时刻，
不是地方**。读者拿到一个打不开的字段，用自选会话目录（`DOJO_SESSIONS`）时更晕。

现在 `trace` 是那一场记录文件的**绝对路径**，屏幕把它印成能直接粘的命令：

```
什么时候会这么做（情境）：「上周二夜里冷库温度报警…」（来自会话 discuss-2f67…，记于 2026-11-28）
  回看说这句的那一场：python3 -m dojo --db /abs/lib.sqlite3 transcript "/abs/my records/discuss-2f67….jsonl"
```

实测（`.scratch/3480/probe_traceback.py`，会话目录叫 `my records`，带空格）：四条 `trace`
都是存在的文件；照抄那行、在**另一个目录**里粘贴，rc=0 并把他两句原话都印出来。

两种真实状态分得开，也不互相冒充：

| 这条原话怎么来的 | 屏幕 |
|---|---|
| 讨论里说的 | 「来自会话 … 」+ 一条 `transcript` 命令 |
| 手工 `promote` 的 | 「（手工附上的）」，**不**印命令、不造会话号和时刻 |
| 那场没留记录（`--no-trace`） | 「这一场没有留下记录文件（--no-trace），回到那场只能靠会话号」 |

新读数 5 项（A 段 `trace` 是真文件 + 屏幕命令可粘可跑；E 段手工附上的行不带会话/时刻/文件且屏幕说手工），
新红臂 2 条（`the-record-of-a-session-is-a-timestamp-not-a-place`、
`a-hand-kept-answer-claims-a-conversation`）。

## 复核又拦住两处：手工附上会冒充讨论，记录写到一半

**一、手工 `promote` 填了一个来源编号。** 屏幕上于是说「来自会话 s-hand，这一场没有留下记录
文件（--no-trace）」——把一个从没发生过的讨论说成了事实。根因是屏幕在**猜**：它只看有没有
`session`。现在 `answers` 表多存一列 `provenance`（`discussion` / `manual`），`discuss` 写
第一种，CLI 写第二种，屏幕不再推断；旧库的行没有这列，就说「来源未记录」，不二选一。

**二、记录写到一半就死了。** 第二条回答没落盘，后三条却照样显示「回看说这句的那一场」，
打开却只找得到第一条。根因是「记录开着」被当成了「这句在文件里」。现在写入卡片前会**真的
读那个文件、逐字找这句**，结果存成 `recorded`（1/0），屏幕只对 `=1` 的给命令，`=0` 的说
「这句没有写进那一场的记录文件（后半段写入失败）」并给出会话号。

**三、旧库第一次升级，两个写入撞在一起。** 复核用两个独立写入同时升级同一个旧库：一条成功，
另一条报 `duplicate column name`，那句回答就丢了。根因是补列前的 `PRAGMA table_info` 在写锁
外面。现在决定与 `ALTER` 在同一个 `BEGIN IMMEDIATE` 里，并且兼容式地容忍 `duplicate
column`（另一个写者已经补上就是我想要的状态）。只读回看旧库仍然一个字节不改。

这一条的红臂值得记下来：**头两版臂都是绿的**。第一版只把锁移出去，却留着 `duplicate
column`
容忍——两者互相遮蔽，测试量不到；第二版加了宽窗口但仍然容忍。只有同时退回“无锁 + 不容忍”
才红。窗口本身只有微秒宽，所以在 `_widen_answers_table` 里留了一个只给测试用的 `_widen_pause`
缝隙：它不制造竞态，只让竞态可观察。

## 复核走到的两条日常路径

**一、库和 `sessions/` 整个搬走。** 用他的话搜得到卡、原话也在，但新印的回看命令仍指向旧址，
照抄退出 2。修法是**按文件名找同一份记录**：文件没在存的那个位置，就在 `DOJO_SESSIONS`、
再在库旁边的 `sessions/` 找它的文件名（`discuss-<32 位>.jsonl` 是唯一的），找到了就把命令印成
新位置，并加一句「记录已不在原处；这是按文件名找到的同一份记录」；找不到就说记录不在了、给出
会话号，不再印一条打不开的命令。屏幕和 `transcript` 用的是**同一个** `commands.locate_record`，
所以印出来的和读进去的不会各说各话。

**二、`--no-trace` 的承诺比代码宽。** 四个回答确实不附上，但开场原封不动说的那句话，在卡片
被认可后仍会作为正文落库——这本来就是产品的主路径，不该禁。所以改的是说法，不是行为：开场块
现在分两句说清「会话原文不保存、四件回答不附上」与「你认可的卡仍会留在库里（那句可能就是你说
过的话，由主持人整理）」，回执也这么说，并指出不要就用 `withdraw`。中英 README 同步。

**三、相对路径。** `DOJO_SESSIONS=meeting notes` 是正常写法，但屏幕就印出了同样相对的路径，
粘到另一个目录的终端就退出 2。现在 `locate_record` 返回的**总是绝对路径**（#3419 的规则，
用在记录上）。复核自己那份复现脚本（`/var/tmp/dojo-move-update.Rvh0uU/`）在这棵树上五条断言全过。

**一条自己踩到的**：D1b 的第一版是**复制**而不是**搬走**记录目录，旧路径仍然有效，读数于是绿得
毫无意义，红臂也拆不穿。第二版把原目录真的暂时移开、读完再放回，红臂才红。

**还有一条是旧账**：`2026-11-28-transcript-view/verify.py` 从 `0213d31` 起就红了，因为它在输出里
找字面的 `python3 -m dojo transcript`，而打印出的命令中间带着 `--db`。这个错误不是本片造成的，
但它会让人不信任其他绿读数，所以一并改成接受带参数的形式（`transcript`、`show` 各一处），
现在那份也全绿。改的是校验，不是产品。

## 自己走一遍时抓到的两处（都出了屏，都看着像对的）

1. **匹配器去卡片的 state 里找回答**——回答在表里，不在 state 里。于是他那句失效例子只
   靠正文里的「系统」勉强对上 1 个词，屏幕上「对上 1 个词」紧跟着一句毫不相干的话。读数
   写成「卡片在结果里」时是绿的，写成「对上 ≥3 个词」才红。
2. **交接卡片时忘了带上回答**——`show` 把回答放在 `candidate` 旁边，交接的渲染函数只拿
   `candidate`。后来那一场屏幕和请求里都没有他的话，而库里四条都在。

两条都留成了红臂（`the-matcher-looks-for-answers-in-the-card-state`、
`a-handed-over-card-loses-his-answers`）。第一处还暴露了我自己读数写得太宽：`card in
stderr` 在没有命中时也成立，因为屏幕会列出「最近写下的卡」。

## 撤回的旧断言（都写明了理由）

- 「这些原话没有写进卡片」（`2026-11-28-offtarget-receipt` C6、`tests/test_offtarget_receipt.py`、
  `tests/test_elicitation_closing.py`、那份 WALK）：那个版本上是真的，现在是假的。它真正
  保护的东西——回答不会变成卡片的措辞或字段——保留成更窄的断言，并新增「原样在他自己那一栏」。
- 「卡片在问答过程中没被改写」：比对的是整库的原始行，现在 `answers` 表本来就会变。改成
  比对卡片自己的表（`candidates`/`snapshots`），再加一条「卡上真有他的回答」。
- 开场白「仍全算我写的」：见上，措辞改成说清楚哪一部分会去哪。

## 仍然开着的

- **他后来改口，卡上的旧回答不会自动跟着变。** 现在只有 `unpromote_answer` 和新一次
  `promote_answers`；两场说的话冲突时，屏幕会把两版都印出来，不会挑一条。
- **`part_sources` 与 `answers_attached` 是两个键。** 谁想读「这条道多少是他的」，现在要
  读第二个；把它接进 `scripts/dao_life.py` 的 `authorship` 是下一片的事，这一片没动那个
  出口。
- **真主持人仍未验。** 这个环境没有 `~/.agents/auth.json`，也没有 `DOJO_*`；所有「主持人」
  都是回环桩的常量。
- **「收下」的语义**在这一片里定了一次：**收下 = 磁盘上有他的字；有材料了 = 账本里有一场
  对这一件的写入**。两件事现在各有各的记录，屏幕上也分开说。
