# 他说过的四件，终于到了那张卡上

2026-11-28。基线 `d77d2c2`。离线：模型是本地回环桩，回答是文件里写死的常量——
**这不是真人会话，也不是模型的判断**。全程只走标准 CLI。

## 这一片回答的问题

产品对它的用途只说过一句话：一条道里的情境、张力、代价、失效必须**从他嘴里出来**，
否则那条道就是 `合写`，它的 `part_sources` 写着 `系统补`。`discuss` 也确实问了这四件，
把他的话留在轨迹里——然后就没有下文了。实测（`.scratch/3474/probe_promote.py`，
标准 CLI、四句具体的回答）：

```
四件问答：reading=answer, collected=true  ×4
session_end.elicitation: promoted=[]  part_sources=系统补 ×6
回执：这些原话留在本场记录里，没有写进卡片。
```

他答了四件具体的事，卡上还是模型写的那一版+模型补的条件。过几天他回来找，或者把这
张卡带进下一场讨论，**看不到自己说过的任何一句**。这就是「他的道」和「模型的推断」
在这个产品里一直分不开的地方——不是信息丢了，是**从来没有一个写入口**。

## 两个词，两件事，以前是这样读的

| | 什么意思 | 改之前 | 现在 |
|---|---|---|---|
| 收下 | 磁盘上留了他的字 | 真的（在轨迹里），回执也说 | 照旧 |
| 这一件有材料了 | 卡片上带着他的字了 | **从来没有发生过** | 一次写入，四个回答逐字进卡 |

## 改了什么

**`promote_answers`（`dojo/storage.py`）——一条卡片的回答，写进自己的表。**

- **不是写卡片的状态。** 状态一写就会 `version+1`，而 `pipeline_marks` 拿版本号判断
  「这件已经处理过」：只是留一句他说的话，会把做完的工作重新变成待办。这一点是旧测试
  `test_material_change_revises…` 当场抓住的，第一次实现就是写状态。它也会改
  `wording_digest`，让他之前那次「认可这套说法」失效。两件都不能接受，所以另建 `answers`
  表：`(candidate_id, field)` 为主键，存原话、会话、时刻、当时间的问句。
- **不碰句子、不碰条件、不碰状态、不添来源。** 他的话是这张卡的**材料**，不是它的措辞，
  也不是第二次到达：`independence()`、`broadcast`、认可摘要、检索门都读不到它。
- **写不进去就不说写进去了。** 第一次实现把「打算写的那几件」当成了「卡上有的那几件」，
  库里每一条都写失败，回执却照旧说四件都附上了。现在写完要**从表里读回来**，回执说的是
  读到的结果；读不到就印 `这些原话没能附到卡片上（原因）`。
- **可以撤。** `unpromote_answer` 把一件拿下来，原来那句留在账本的 `from` 里。

**回执和开场白都跟着改。** 回执现在说「你在这几件上的原话现在也附在卡片 X 上了」，并
逐个点名**没附上去的那几件**（跳过、没遇到过、没答出内容）；开场白原来保证「卡片上的字
这一版仍全算我写的」，在这之后那半句仍然真、但读起来像「什么都不会发生」，所以改成说清
楚哪一部分会去哪。

**`part_sources` 仍然是 `系统补`，这是刻意的。** 它回答的是「这一栏的字是谁写的」；他
的话是**另存在旁边**的，没有变成 `scope` 或 `contradictions`，这场会话也不判它有没有答
到点上（那是 `to_fill`，得由读者判——上一片的结论，这一片照旧）。所以轨迹里另加一个
`answers_attached`，说的是另一件事：卡片上有没有他的话。

**三个读出口都能读到他的话。**

- `search`：他的失效例子（`没发出来 路上 才发现`，卡片正文里一个都没有）现在能找回这张
  卡，并且明说「你记得的字不在卡片写的那句里，而在附在这张卡上的你的原话里」，下面逐条
  印原话。命中只有在他自己的屏幕上才算——`retrieve` 不加 `for_reading` 时搜索范围一字
  未变，所以模型能拿到的东西没有变宽。
- `discuss --card`：开场屏和发给模型的请求都带上他的话，并标明**这是他的原话、不是这张卡
  的措辞、也不是对它的赞同**。
- `show`：`answers` 与 `candidate` 并列，`candidate` 仍是逐字节的存储状态。

## 自己走一遍时抓到的两处（都出了屏，都看着像对的）

1. **匹配器去卡片的 state 里找回答**——回答在表里，不在 state 里。于是他那句失效例子只
   靠正文里的「系统」勉强对上 1 个词，屏幕上「对上 1 个词」紧跟着一句毫不相干的话。读数
   写成「卡片在结果里」时是绿的，写成「对上 ≥3 个词」才红。
2. **交接卡片时忘了带上回答**——`show` 把回答放在 `candidate` 旁边，交接的渲染函数只拿
   `candidate`。后来那一场屏幕和请求里都没有他的话，而库里四条都在。

两条都留成了红臂（`the-matcher-looks-for-answers-in-the-card-state`、
`a-handed-over-card-loses-his-answers`）。第一处还暴露了我自己读数写得太宽：`card in
stderr` 在没有命中时也成立，因为屏幕会列出「最近写下的卡」。

## 撤回的旧断言（都写明了理由）

- 「这些原话没有写进卡片」（`2026-11-28-offtarget-receipt` C6、`tests/test_offtarget_receipt.py`、
  `tests/test_elicitation_closing.py`、那份 WALK）：那个版本上是真的，现在是假的。它真正
  保护的东西——回答不会变成卡片的措辞或字段——保留成更窄的断言，并新增「原样在他自己那一栏」。
- 「卡片在问答过程中没被改写」：比对的是整库的原始行，现在 `answers` 表本来就会变。改成
  比对卡片自己的表（`candidates`/`snapshots`），再加一条「卡上真有他的回答」。
- 开场白「仍全算我写的」：见上，措辞改成说清楚哪一部分会去哪。

## 读数与红臂

```bash
python3 docs/evidence/2026-11-28-answers-on-card/verify.py   # 25 项读数
python3 docs/evidence/2026-11-28-answers-on-card/redarm.py   # 9 条臂
python3 -B -m unittest tests.test_answers                     # 20 项
python3 -B -m unittest discover -s tests -q                   # 全量
```

`verify.py` 的五段：A 一场四件都答了的会话；B 过几天用他自己的话去找；C 后来的一场
`--card` 带上这张卡（屏幕与发给模型的请求各查一次）；D 不该动的东西没动。

## 仍然开着的

- **他后来改口，卡上的旧回答不会自动跟着变。** 现在只有 `unpromote_answer` 和新一次
  `promote_answers`；两场说的话冲突时，屏幕会把两版都印出来，不会挑一条。
- **`part_sources` 与 `answers_attached` 是两个键。** 谁想读「这条道多少是他的」，现在要
  读第二个；把它接进 `scripts/dao_life.py` 的 `authorship` 是下一片的事，这一片没动那个
  出口。
- **真主持人仍未验。** 这个环境没有 `~/.agents/auth.json`，也没有 `DOJO_*`；所有「主持人」
  都是回环桩的常量。
- **「收下」的语义**在这一片里定了一次：**收下 = 磁盘上有他的字；有材料了 = 账本里有一场
  对这一件的写入**。两件事现在各有各的记录，屏幕上也分开说。
