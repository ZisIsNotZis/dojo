# 走一遍：他说的四件，怎么到了卡上

2026-11-28，干净检出即可重跑。这一段只加了一张表和三个读出口，不改卡片状态、不改库结构
的既有列、不发外部请求。没有真人参与：下面「他」说的话都是写在脚本里的常量。

## 0. 整段入口（不需要端点）

```bash
python3 docs/evidence/2026-11-28-answers-on-card/verify.py
python3 docs/evidence/2026-11-28-answers-on-card/redarm.py
```

`verify.py` 在临时目录里自己建库、自己走路：一场讨论答完四件 → 过几天用他自己的话找 →
后来的一场把这张卡带进讨论 → 查不该动的东西。它打印真实屏幕和每条读数，全部通过时退出码 0。
`redarm.py` 把每一处修复依次退回旧行为，证明每条读数真的会红。

## 1. 一场讨论，四件都答了

```bash
DB=$(mktemp -d)/walk.sqlite3
export DOJO_LLM_BASE_URL=http://127.0.0.1:4000/v1   # 任意 OpenAI 兼容端点
export DOJO_LLM_MODEL=<端点注册的 id>
export DOJO_LLM_API_KEY=<你自己的 key，不要写进文件>
python3 -m dojo --db "$DB" discuss
```

四件他都答了具体的句子时，回执结尾是：

```
四件问完了：四件你都说了原话。这些原话留在本场记录里。你在这几件上的原话现在也附在卡片
d-… 上了（情境、张力、代价、失效），照你说的字存，没有改写成卡片的措辞。答没答到点上，
这句不判——判断留给你。卡片上那句子还是提问前写下的那一句，这场问答没有改过它，字仍算
我写的；你的话是另存在它旁边的，没有变成它的措辞或条件。
```

三件事要能一眼分开：**他的话在不在卡上**（`answers_attached`）／**那一栏是谁写的**
（`part_sources`，仍然是 `系统补`）／**卡片那句改没改**（没改，版本也没动）。

答过的件和没答过的件要分开点名。跳过一件、或两轮都没答出内容，回执会说：

```
…另外 代价 没有附上去：这一件的回答不算材料（跳过、没遇到过，或没答出内容）。
```

写不进去的时候（磁盘满、库只读），回执说的是读回来的结果：

```
这些原话没能附到卡片上（…原因…）；它们仍在本场记录里，卡片也没有因为这次失败被改。
```

## 2. 过几天，用他自己用过的话去找

```bash
python3 -m dojo --db "$DB" search '没发出来 路上 才发现'
```

这三个词**一个都不在卡片正文里**，只在他说过的失效例子里。屏幕（stderr）：

```
在这个库里找：「没发出来 路上 才发现」
  1 张卡的字和这些词重叠：这只是字词的重叠，不是按意思或可信程度找的。
1. d-…  草稿  对上 6 个词：出来、发出、发现、才发、没发、路上
  「把持续检查交给系统跑，人只在结果会打断他时才被叫醒。」
  检索会把这一版交出去（可以带进新讨论）；下面是它自己的条件。
  你记得的字不在卡片写的那句里，而在附在这张卡上的你的原话里（原样印在下面的「他的话」）；
  卡片本身那句和这些词没有重叠。
  什么时候成立：「他已经抽身、这条提醒的失败不会当场伤人时」
  …
  他的话（库里存的原话，附在这张卡上；不是这张卡措辞的一部分）：
    什么时候会这么做（情境）：「上周二夜里冷库温度报警，我已经回家了，手机响了我才回去」
    哪件好事会跟着变差（张力）：「盯现场的踏实感就只能选一个」
    谁要多花什么（代价）：「负责夜班的两个同事要多花时间跑一趟」
    什么时候反而不对（失效）：「有一次系统没发出来，我在路上才发现，那次就不该靠它」
  带进一场新讨论：python3 -m dojo --db /abs/…/walk.sqlite3 discuss --card d-…
```

每条后面还带着它是哪个会话说的、哪一天记的，可以回到那一场去看原句。

## 3. 把这张卡带进后来的一场

```bash
python3 -m dojo --db "$DB" discuss --card d-…
```

开场屏在条件、反例、未知、前提之后多一段：

```
  他的话（库里存的原话，附在这张卡上；不是这张卡措辞的一部分）：
    什么时候会这么做（情境）：「上周二夜里冷库温度报警，我已经回家了，手机响了我才回去」
    …
```

发给模型的第一个请求里也有同样四条，标着：

```
这张卡上还附着他本人对这几件的原话（是材料，不是这张卡的措辞，也不是对它的赞同；引用时
要说成「他说过」，不能说成卡片这么写，也不能当成第二个独立来源）：
```

`verify.py` 里这两条分别查：屏幕上有没有、请求里有没有。

## 4. 不该动的东西

| 什么 | 为什么不能动 | 怎么查 |
|---|---|---|
| 卡片的 `version` | `pipeline_marks` 拿版本判断「处理过」，一动就把做完的活变回待办 | `verify.py` D 段 |
| `wording_digest` | 他之前「认可这套说法」绑在它上面，一动那条认可就失效 | `tests/test_answers.py` |
| 句子和四个边界字段 | 把他的话搬进 `scope`，等于把模型的措辞说成他的 | 同上，逐字段比 |
| 来源与 `independence` | 他的话不是第二次到达，广播会因此把他自己算成两个人 | 同上 |
| 模型能检索到的范围 | 他自己的屏幕能按他的话找，模型不该因此拿到更多 | `verify.py` B 段 |

## 5. 不用讨论，直接补一件 / 撤回一件

一场讨论之外（比如他在别处说过一句），可以把他自己的话直接附到卡上：

```bash
python3 -m dojo --db "$DB" promote d-… --answer 情境=上周二夜里报警 --answer 失效=系统没发出来 --session s1
```

`--answer` 每件一次，写法是「件=原话」；件名可以是 `情境/张力/代价/失效`，也可以是字段名。
输出是写完之后**从表里读回来**的那几件，不是「打算写的那几件」。

## 6. 撤回一件

```bash
python3 -m dojo --db "$DB" unpromote d-… 情境 --reason '那次说的不是这条'
```

（CLI 入口见 `dojo/cli.py` 的 `promote` / `unpromote`。）原来那句留在账本的
`unpromote_answer` 事件里，卡片版本不动。
