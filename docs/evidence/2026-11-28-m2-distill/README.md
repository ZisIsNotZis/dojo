# M2：普通收场、事后回看与显式模型判类

**当前判断（2026-11-28）：普通收场到事后回看已通过本地合成验收；M2 尚未通过。** 这次没有获准模型线路，未验证真实模型判类质量；用户也还没有独立看过清单并决定它是否值得入库。这里是 M2 当前证据和边界的总入口；[计划](../../plan.md#m2-无声入库与会话末提炼)中的早期拆包表仅作历史记录。

既有收场与分类证据来自公开基线 `2b16ab8` 之后的工作。本次“所选版本 → 原话 → 取舍”小候选单独以 GitHub 公开提交 `83dffa398e6e304adb4c5c14fe76cbfa05fbfa57` 为基线；两场对照用相同脚本在该基线与候选上跑，不带入其他本地底稿。

## 正常使用

1. 在 `discuss` 中核对拟稿，只对想保留的版本输入 `/认可`，然后正常结束输入。认可的是当时的表述，不是独立验证。
2. 收尾会报「3 个已认可版本，1 份未认可草稿」（数量按本场而定），并打印「稍后看本场留下的版本和草稿」。复制那条 `distill` 命令即可，不必先跑管线。只有本场原轨迹时，也可以在原库的 `transcript` 回看屏找到同一条命令。`show` 读的是当前库记录，不是本场认可历史。
3. 清单逐版显示原来认可的边界：试法不是实际用过，观察只有两次且没有归因，开放问题没有答案，分色草稿未认可且注明光照限制和「尚未试过」。没有后续分类提议时，类型标为「讨论时拟写」；不会为了填这一列请求模型。

清单与原话回看互补：前者找版本、条件和未知，后者看对话原句。复制所选版本下面的「回看本场原话」；有准确的旧版出处时，另给旧档定位。定位只列指定轮的用户原话，不判断哪句话能支持结论。无轨迹或版本对不上，仍可读账本快照，不借其他版本的原话。清单需要原库，不是只有 JSONL 就能重建库。

## 两场后来读者对照

公开基线已能从 EOF 回执或原轨迹打开同一清单，但从选中条目找拟稿原话要返回整场查轮次；对照旧卡还要查历史并手拼轨迹路径。新候选让读者从版本行直接回看，再作取舍：

| 选了什么 | 核对后怎样取舍 |
|---|---|
| A · 修伞站 v1，临时用一张纸签 | 只留为当晚登记册借不到、值班员在场时的试法；没试过，也不替代常规登记。不关联旧卡。v2 是未答问题，群照草稿未认可且未问同意，暂不采用。 |
| B · 图书交换架 v1，留指引卡 | 本场只限单口开放且前一班在场当面确认；旧卡 v1 包括双口，但旧档原话承认未试过。不采纳双口外推，也不判断它已失败。可记录 `narrows`，不是合并或新增佐证。 |

两场回看零模型请求，原库与三份轨迹的路径和字节不变；单会话卡仍不广播。B 的关联只在库副本显式执行，新卡获 v2 关系记录，旧卡与本场认可 v1 均不变。不据此扩大 M2 验收。独立读者使用的是合成材料，真实用户是否愿意采用仍待验证。

## 已验证与未验证

| M2 验收 | 已经证明 | 还没证明 |
|---|---|---|
| ① 提炼与对话一致 | 普通 EOF 首屏和事后两条回看路径都读到同场 v1/v2/v3、独立的未认可草稿，以及它们的边界；后续 v4 不替换三份历史快照。错误场次零请求；伪造引语不写分类；同秒 A→B→A 绑定最后一次认可。 | 合成响应不代表真实分类质量。即使逐字摘录成立，仍可能漏掉「想试」而抬高语气；冲突回显让人能核对，不是自动判真。还缺用户过目、判断清单价值。 |
| ② 单会话隔离 | 查询实际命中该场卡，`broadcast` 仍以 `single-session` 拒收。 | 不证明跨场广播改善讨论（M3），也不验证不同来源本身独立。 |
| ③ 重复不写新版本 | 既有存储回归覆盖重复内容写入被拒；同场清单反复打开不写库。样例仅把同句但范围不同的印刷角卡当作近邻提议。 | `[新]` / `[变体]` / `[重复]` 是本地比较建议，不是语义等价或合并的证明；已独立核对 B 的两场合成原话，不证明一般近邻语义等价。 |
| ④ 重跑幂等 | 已成功的显式合成判类重跑零请求、零新事件；正常收尾没有额外分类请求；从结束屏或 `transcript` 打开清单两次，内容相同，库和原轨迹哈希不变。 | 长会话可能需再次显式提交下一批（`deferred`）；没有把管线自动挂到收尾。 |
| ⑤ 挑战与历史 | 既有存储回归覆盖显式 `Store.challenge` 设置 `challenged` 并保存历史。清单和 pass 只显示挑战提议，不执行、删除或合并。 | 本轮不把提议视为成立的挑战，也未验收真实讨论中的挑战质量。 |

场次、卡片 ID、版本、认可时间与快照字段均须对上才产生定位。命令携带被核对的轨迹 SHA-256，复制后若文件被替换或改写，就不显示替换后的话；这不是签名，不证明内容为真，也不检测生成命令之前的蓄意伪造。缺少本版拟稿轮时只定位认可轮，不借同句旧版的拟稿。

## 复跑

在候选检出根目录执行。只用临时库、隔离的 HOME 和 `127.0.0.1` 合成桩，不读取个人模型配置。`$OUT` 必须在检出目录外。

```sh
umask 077
OUT="$(mktemp -d)/m2"
python3 -B docs/evidence/2026-11-28-m2-distill/verify_distill_cli.py . "$OUT"
python3 -B docs/evidence/2026-11-28-m2-distill/verify_distill_reapproval.py . "$OUT/reapproval"
python3 -B docs/evidence/2026-11-28-m2-reader/replay.py . "$OUT/conflict"
```

第一条先打印 `PASS ordinary EOF`：结束讨论进程后，从另一个工作目录、一个不同的默认库配置，复制屏上命令直达清单；从 `transcript` 复制命令得到逐字相同的输出。只需读 `$OUT/discuss.stdout.txt` 的末尾、`$OUT/close-reader.txt` 和 `$OUT/close-transcript.txt`，不必先读 JSON。然后才显式跑合成分类，打印 `PASS real CLI`；`distill-reader.txt` 是**分类后**的读数。第二条复核同一秒 A→B→A，第三条模拟把「想试」误判成经验的回包，检查清单显示「判类待核」和原话上下文，而不是把加重后的标签当认可。独立读者也复跑了普通 EOF，另测只有草稿时准确显示 0 个认可、1 份草稿，两条回看路径一致。

确定性回归见 `tests/test_m2_distillation.py`、`tests/test_pipeline.py` 和 `tests/test_storage.py`（`broadcast`、`duplicate`、`test_challenge_revision_and_alias_link_versions_preserve_sources`）。

### 重跑同样两场

令 `$BASE` 指向上述确切公开提交的干净检出或官方归档解包目录。在候选根目录运行：

```sh
umask 077
OUT="$(mktemp -d)"
SCRIPT=docs/evidence/2026-11-28-m2-distill/verify_reader_choices.py
python3 -B "$SCRIPT" "$BASE" "$OUT/base"
python3 -B "$SCRIPT" --require-reader-paths . "$OUT/candidate"
```

先并排读两边的 `A.distill.txt` 和 `B.distill.txt`。候选额外留下 `*.chosen-v1-original.txt`、`B.old-v1-original.txt` 和 `commands.json`；`version-binding.json` 记录错场、错卡、错版、重复轮次以及复制命令后文件被替换的反例；`B.link-copy.json` 是独立副本上的显式写入。`tests/test_m2_distillation.py` 另钉住同秒同内容且缺失拟稿轮的回退行为。

## 什么时候会发送原话

只有另行选择**已获准**的模型线路，并显式运行下列命令，才会提交本场待处理的认可快照和相应用户原话片段；不提交未认可草稿、主持人回复或整份轨迹。后续打开清单只读本地已存提议，不再请求模型。已判版本不重发。

```sh
python3 -m dojo --db "$DB" pipeline --session "$SESSION" --classify --trace "$TRACE"
```

不想发送原话，就直接复制讨论或 `transcript` 印出的清单命令。讨论轮本身的模型调用不是这条判类命令；收尾与回看不增加调用。
