一句话：**四句问法前面原来没有「形状」，现在有；而形状里写着「什么时候停」。**

## 用的是哪条经验，为什么是它

`dojo-d-002`「先给完整形状，再谈细节；追问一次一个」。

| 件 | 内容 | 谁写的 |
|---|---|---|
| 动作 | 先给完整形状，再谈细节 | **他的原话** |
| 失效 | 形状在不知细节时给不出；他开始反过来追问细节 | 系统补 |
| 情境 | 手上几件事、时间比细节贵、这件事还没开始 | 系统补 |

它的 magnitude 那一栏写的是：「一轮最多一个问句，且只问会改结论的；**形状里必须带「什么时候停」**」。

选它有两个理由。一是它的动作和出处来自他的原话，不是我从他的行为里推的。
二是它落在一件**与出处核对无关**的工作上：出处核对那条经验已经用掉了，这次换成
「一个人第一次跟产品说话时，先看到什么」。

## 改前 / 改后：同一个入口，同一条尺子

测的是一个人真正遇到的入口：`run_discuss` 走进四句问法之前，屏幕上那一段。
注入客户端、离线跑，不需要模型。

| | 改前（`f8022a6`） | 改后 |
|---|---|---|
| 第一个问题之前那一段的字数 | **11** | **138** |
| 说清楚有几件 | 没有 | 「四件事——情境、张力、代价、失效」 |
| 说清楚什么时候停 | 没有 | 「每件最多两轮」 |
| 说清楚答不上来会怎样 | 没有 | 「答不上来就跳过，这场照样往下走」 |
| 说清楚想走怎么走 | 没有 | 「想停随时结束输入」 |
| 说清楚卡片算谁的 | 没有 | 「卡片上的字这一版仍全算我写的」 |
| 这一段具体是什么 | 「那我们把它写成这一条。」 | 见下 |

关于原文的那半句随本场的记录设置变（`shape_text(trace_is_open)`）：开记录时说「你答的原话会留在本场记录里」，
关记录（`--no-trace`）时说「这一场不保存原文（上面已说轨迹关闭）」。两句都不会同时出现。

字数尺：`verify.py` 取「第一个问题之前那一段」，去掉尾部换行再数；开记录那一臂是 11 → 138，
读数与脚本输出是同一个数（早先这里记过 154 / 207，那些字已被下面第 4、5 条换掉）。

改后那一段，开记录时（`SHAPE_HEAD + SHAPE_KEPT`）：

> 这条已经写下来了。接下来我问你四件事——情境、张力、代价、失效。问的都是你刚写下的这条，不是一张问卷。
> 一次问一件，每件最多两轮；答不上来就跳过，这场照样往下走，想停随时结束输入。
> 你答的原话会留在本场记录里，但卡片上的字这一版仍全算我写的——所以不必为了把卡片填满而勉强作答。

同一场用 `--no-trace` 时，前两行不变，第三行换成（`SHAPE_UNKEPT`）：

> 这一场不保存原文（上面已说轨迹关闭），你答的话只在这段对话里用，卡片上的字这一版全算我写的
> ——所以不必为了把卡片填满而勉强作答。

改前那 11 个字是主持人的上一句结束语，不是形状：它承接的是「要不要写下来」，
下一个屏幕就是第一个问题。**一个人在那之前得不到「还有几件、什么时候停」这两件事。**

## 这条经验真的改变了谁的行为——诚实的答案：还没有人

这是本片最该被读的一行。**记录里没有任何一个人因此做过不同的事。**

我查了这台机器上所有 `discuss-*.jsonl` 轨迹：到四句问法那一步的只有我自己的探针，
没有任何一场真人的会话走到这里。所以能说的只有：

- 入口**现在**说了经验要求它说的话（上面那张表，可重跑）；
- 入口**以前**没说（同一把尺子，同一份代码，红臂可复算）；
- **没有人**因为这句话多坐了一会儿、多答了一件、或者留下来。这一格是空的。

为什么不能补上这一格：要一场真人会话，或者一个有额度的模型对照（同一件事，一版给形状、
一版不给，看人坐多久、答到哪一层）。本包没有模型额度，也没有人时。

所以这条经验在这里证明的是**它可落地、且落地前后入口不同**，
不是**它有用**。这两件事差得很远，写在一起会让下一读者以为后者已经被证过。

## 还证明不了什么

1. **没有对照。** 138 字对 11 字是「说了没说」，不是「说了之后人会怎样」。
2. **判者是我。** 形状里写哪几件事（四件、两轮、不填、照实记）是我按经验挑的，
   没有第二个人判过这样写对不对。
3. **一处没改，且我判定不该在这一片改。** 模块头的规则是「一次只问一件」，
   指的是**一件**（情境/张力/代价/失效），不是「一个问号」。所以「情境」那一问里
   同时要条件和一次具体的事，不算违规——那正是 `failure_mode` 里写明的设计。
   我第一遍把它读成「两个问句算违反」，那是我的读法错，不是产品的错，记在这里免得下一个人重犯。
4. **这一块的第一版向使用者承诺了一件产品做不到的事，是复核回执打回来的。** 第一版写的是
   「问不出来就不填，那一件留作「系统补」，条目记成「合写」」。但 `elicitation_summary()`
   把六件**全部**置成 `系统补`（`dojo/discuss.py:1146`），`authorship()` 因此永远返回「系统的」；
   `tests/test_elicitation_loop.py:109` 在四件全答对之后仍然断言「系统的」。也就是说
   「合写」这个标签在这个入口上**从不出现**。一个入场块向人承诺一个产品不做的事，
   比没有入场块更糟——它把「我答了就有用」卖给人。
   修法是把那句话删掉，换成它实际会发生的事（原文留作材料，卡片仍记系统补），
   并加一项测试 `test_the_shape_promises_exactly_the_authorship_the_entry_records`，
   拿会话结束时的真读数去对入场块里的字，同时禁止块里出现「合写」。
   这不是「措辞不精确」，是这一片自己引入的、向读者说假话的缺陷。
   回执在 `/var/tmp/dojo-entry-b49950c.Q8rXp7/authorship-review.json`（对照 `b49950c` 的干净快照，
   结束会话时唯一一条的归属是「系统的」），已重跑复现。第二版又换成了库里的标签说法
   （「六件都记系统补」），使用者看不懂；最终版改用日常话讲同一件事，并且顺手去掉了
   「问题是从你这条里长出来的」——那四句问法是写死的，不是按他的话生成的，说了也是假的。
   入口检查现在多四项：怎么跳过、怎么结束、「合写」不得出现、卡片归属必须写出来；
   另加三项对着**真读数**比：答完四件后卡片仍记「系统的」、答完四件后 `collected` 是四件、
   全不答也 rc=0。
5. **这半句在 `--no-trace` 下曾经是假话，是第二份复核回执打回来的。** `9aa9fb6` 上，开场已经印
   「会话原文轨迹已关闭（--no-trace）」，紧接着的入场块仍然说「你答的原话会留在本场记录里」，
   而磁盘上确实没有轨迹（回执：`trace_count` 为 0）。这和「合写」是同一类错：向人描述一个
   这个设置下不会发生的事。修法是把那半句做成随 `trace_is_open` 变的两句，并用入口检查的两个臂
   分别验：开记录→必须说「会留在本场记录」且不得说「不保存原文」；关记录→必须说「不保存原文」
   且不得说「会留在本场记录」。对 `9aa9fb6` 跑同一份检查，这两项转红（红臂已跑）。

   顺带记一笔验证方法：
   「答的原话会留在本场记录里」我先用三个一次性探针读轨迹，三个互相不一致。那是我探针的问题，
   不是产品的问题。
   换成仓里已经绿的那个测试驱动一跑就清楚：四件的 `answer` 与输入逐字相等，
   `collected` 是那四件，`supplied` 为空，`line` 仍是「系统的」。
   现在这条也进了测试：`test_the_shape_promises_exactly_the_authorship_the_entry_records`
   同时断言四件原文逐字在内，`test_the_shape_says_what_happens_only_when_the_session_keeps_a_trace`
   守住关记录那一臂。**教训：当三个自制探针互相矛盾时，先找一个已被仓库验证过的驱动。**
6. **形状会不会变成噪音。** 一场会话里它只印一次；但每条道都走这一段时，
   重复第四次读它的人可能不再读。那时候该改的是呈现，不是「要不要说」。
