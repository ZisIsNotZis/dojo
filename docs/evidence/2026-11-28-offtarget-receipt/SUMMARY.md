# 一句答偏的话：原话收下，问题不算答了

日期：2026-11-28。基线 `4cd8905`（上一片，`candidate/reuse-landing`）。离线；0 次模型调用。

## 这一片回答的问题

监督者：「碰到实质性但答偏的回答，回执和后续卡片能否诚实地保留他实际说的材料，又不把它
算成回答了原问题或用户认可的结论。」

这是第 4 片留在记录里、一直没被检验的那个词：**回执是在承诺「收下了」还是「答对了」？**
`--card` 让更多人撞上它，于是这一片先拿一个像真对话的例子去量。

## 改之前实测（真实 CLI，回环端点，`probe_offtarget.py`）

一场 `discuss --card c1`，四件追问里三件答偏、一件答到点上：

| 件 | 问的是什么 | 他说的 |
|---|---|---|
| 情境 | 那天你手上是什么事、卡在哪一步 | 我觉得这里关键是通知得做好，不然谁都不知道系统跑完了没有。 |
| 张力 | 哪件本来也挺好的事会变得差一点 | 照这个做，我那种先自己看一遍的习惯就没机会用了，那是我挺看重的一件好事。 |
| 代价 | 谁要多花时间、谁会不高兴 | 这个方案对工程师是好事，反正工程师本来就该多写点自动化。 |
| 失效 | 有没有一次你这么做、结果反而不对 | 每个团队都不一样，有的团队特别需要这个，有的完全不需要。 |

屏幕印的是：

```
四件问完了：四件你都答了。这些回答留在本场记录里，没有写进卡片。…
```

（这是**改之前**的屏幕原文。改后同一场的回执见下面的「改了什么」。）

轨迹四行全是 `reading=answer collected=True`；`session_end.elicitation.collected`
是 `["情境","张力","代价","失效"]`。

再用 `scripts/dao_session.py` 导出（`probe_export.py`，张力换成合规形状）：

```
session.json：situation promoted=True  answer='我觉得这里关键是通知得做好…'
              tension   promoted=True  answer='自己先看一遍 ↔ 系统自己跑检查'
              price     promoted=True  answer='这个方案对工程师是好事…'
              off       promoted=True  answer='每个团队都不一样…'
note.md：     - [probe-T1] … | 情境: 我觉得这里关键是通知得做好… | …
```

**两个层次的判断要分开，混在一起读就会修错地方：**

- **导出层是对的。** `session.json` 说 `promoted: true`，含义是「这句话是他在会话里说的、
  按原话留在记录里」，`dao_life.py` 由此把来源记成 `他的原话`。这**不是**「他认可了这条
  结论」，也不是「他答对了这个问题」——`note.md` 的「方向」一格仍是那份候选，`情境` 一格
  只是他关于情境说的原话。这一层没有撒谎，不改。
- **回执层是错的。** 它用了一个词 `你答了`，同时暗示两件事：**话我收下了**，以及**问题
  你答上了**。程序只查过前者（非空、不是跳过、不是收场、不是裸的「不知道」）。后者要靠
  `QUESTIONS[...]["to_fill"]` 让读者判，而这场会话不是那个读者。

## 改了什么

`closing_text` 里那个桶的词：`你答了` → `你在 情境、失效 上说了原话`（四件全说时用短句
`四件你都说了原话`）。并在回执里补一句，只要他说过话就印：

```
答没答到点上，这句不判——判断留给你。
```

**2026-11-28，复核后改了这一句。** 第一版的结尾是「原话在上面，你自己看」。这句话在
真终端里对（回显就在提问下方），但在管道里不成立：`printf ... | python3 -m dojo discuss`
的 stdout 只有主持人说的话，他打的四句一次也不回显；`--no-trace` 时更是哪里都没写。
审核者在 `11ba996` 上用真入口量到这一点：回执把他指向一段不存在的话。

改法不是把所有原话重印一遍（那会把回执变成长篇），而是**去掉指向**：判语只说「不判」；
原话在哪，由紧邻的那句 `use` 负责，而它已经跟着轨迹设置分岔——留轨迹时说「留在本场记录
里」（路径在开场和结尾各印了一次），不留时说「这场不留原文」。两句话现在在两份运行里
都逐字成立。`tests/test_offtarget_receipt.py` 与 `verify.py` C5b/C5c 钉住这三件事：
不留轨迹时不指向屏幕、留轨迹时那句原话真在文件里、开头若没回显就不能说「在上面」。

其余四件（跳过 / 结束输入 / 搁下 / 没答出来 / 没问到）的词一个没动。**这是刻意的**：那片
记录里已经写明，每件只有一个结局词，且必须是真发生的那一个。这一片只修第一个词的语义。

## 为什么不是「再聪明一点去判答没答到点上」

那是另一个产品决定，而且这一片没有任何证据支持自动判得准。`to_fill` 里的四条判据写的都是
「一句带『什么时候/什么时候不会』的话，外加一次能对上日期或场合的事」这种需要读懂语义的
判断；一个正则判它，就会回到这一系列一直在修的那类缺陷——屏幕说了一件程序没做的事。

所以这一片的立场是：**能诚实说的是「收下了」，不能诚实说的是「答对了」，那就不说后者，
并且把「不判」这件事本身说出来**——以前它是沉默地越过。

### 顺带核到的两处，本片都改了

1. **旧证据脚本会钉住旧措辞。** `2026-11-27-closing-line/verify.py` 与
   `2026-11-27-receipt-truth/verify.py` 在改词后退出 1。它们记录的是更早那两片的**事实**
   （屏幕与轨迹一致、三种结局分得开），事实没变，只是词变了，所以更新锚点并注明日期与
   原因，而不是让它们烂掉。这两份都在本片之前写、本片之后仍可重跑。
2. **README 两个首页都没写 `--card` / `--resume`。** 监督者这次点名要「第一次看 README
   的人找得到」。两页各加一节，引用的是**实测**输出，不是编的：

   ```
   无法续跑：--card 与 --resume 不能同时使用。
   无法开始讨论：这张卡读不出来（candidate not found: c9）；未发送网络请求。
   ```

   `tests/test_readme_card_entry.py` 四向把关：两页都得有一条能复制的命令带这个开关；
   两页都得说这两个不能合用；**引用的两句拒绝话真跑一遍**（都是本地拒绝，不需要端点）；
   两页都得说清 `--resume` 要的是哪种轨迹（`sessions/discuss-<32 位十六进制>.jsonl`）。

## 这一片没有做的事（别当成已解决）

1. **没有人真的因此改口。** 这台机器上的轨迹仍然只有我的探针。这一格空着，和上一片一样。
2. **「答没答到点上」仍然没有判据。** 这一片只是不再假装程序判过。真要自动判，得先定义
   什么算答到点上，并且拿真人语料量它的错判率——那是另一个产品决定。
3. **导出层的 `promoted` 这个词仍可能被误读。** 它表示「这句话是他在会话里说的」，不表示
   「他认可了这条结论」。`dao_life.py` 把它写成 `他的原话`，语义是对的；但一个只看
   `promoted: true` 的读者会不会读成「他点头了」，这一片没有量过。
4. **主讨论轮仍不调分类器**（第 4 片记的既有边界，本片没碰）：`stop` 只在四件追问里生效。
5. **`status` 仍不进 payload**（#3383 建议），本片没碰。
6. **轨迹里的字段名仍叫 `collected`。** 它的含义是「按原话收下的材料」（`scripts/dao_session.py`
   的 `answered()` 就是这么读的），不是「答对了」；库下游按这个语义用，所以不改名。但一个
   只看 `session_end.elicitation.collected` 的读者，仍可能把它读成「四件他都答上了」——
   这正是本片在屏幕上修掉的那种误读，只是换了个地方。改名会牵动 `--resume` 状态与导出，
   不在这一片的范围里。
