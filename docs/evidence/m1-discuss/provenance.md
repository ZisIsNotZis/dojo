# M1 discussion run provenance

The first three captured runs used `DOJO_LLM_BASE_URL=http://127.0.0.1:4000/v1 DOJO_LLM_MODEL=github_copilot/gpt-6-luna python3 -m dojo --db /tmp/m1.sqlite3 discuss`; the later successful workflow demonstrations used the same command with `--db /tmp/m1b.sqlite3`. All ran on 2026-10-17 with the configured local LiteLLM endpoint and the requested model name; each CLI was attached to a pseudo-terminal so user input and model output were captured together.

The first three runs used `/tmp/m1.sqlite3`, which contained zero candidate and event rows both before and after those runs. They were process-flow demonstrations only and did not establish that discussion improves outcomes or constitute user research.

`run-20261017-1017-01.md` records a complete process that ended at the built-in 12-request limit without producing a pending conclusion. `run-20261017-1018-02.md` records a process stopped by the local driver after 10 model responses; it is explicitly incomplete. `run-20261017-1020-03.md` records a process ended by EOF after two responses, before alignment or a candidate. Together those captures show 24 model responses.

`run-20261017-0226-04.md`, `run-20261017-0227-05.md`, and `run-20261017-0229-06.md` record three successful live flow demonstrations using the separate database `/tmp/m1b.sqlite3`. Run 4 used a closure signal, run 5 explicit acceptance, and run 6 repeated the closure-signal path under the final convergence prompt and presentation wording. Each used three model requests. The database contains one draft and one add event per successful session; run 6 captures its `list` and `show` output with all three drafts. These are successful process-flow demonstrations only, not evidence that the conclusions are true, that discussion improves outcomes, or that the flow works for other users. Each conclusion is a single unverified self-report with explicit unknowns. No live rebuttal was attempted; correction handling is covered by unit tests.

The interactive inputs were supplied for workflow demonstrations and echoed by the pseudo-terminal; they are not a participant sample. The transcripts preserve the complete output of each captured process, including each run's termination state. The sessions do not persist raw discussion text in the database.
