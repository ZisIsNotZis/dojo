# 走一遍：过了几天，只记得那句话的大意

2026-11-28，干净检出即可重跑。这一段只改人的屏幕和检索的读法，不改库结构，不发外部请求。
没有任何真人参与：脚本里的「他」都是写在文件里的桩回答。

下面每条命令都在仓库根目录执行。`$DB` 是你自己的库。

## 1. 真实入口：用词去找

```bash
export DOJO_LLM_BASE_URL=... DOJO_LLM_MODEL=...
DB=$(mktemp -d)/walk.sqlite3
python3 -m dojo --db "$DB" search '值班 通知 打电话'
```

在终端上，屏幕（stderr）长这样；stdout 的 JSON 不跟着倒在终端上（接管道或重定向时才打印）：

```
在这个库里找：「值班 通知 打电话」
  2 张卡的字和这些词重叠：1 张检索会交出去，1 张不会（每张下面都说了为什么）。顺序按重叠的词数，不是按意思或可信程度。
1. d-…  被人质疑过  对上 2 个词：值班、通知
  「值班通知交系统跑，只在结果会打断他时才叫醒他。」
  检索不会把它当答案交出去（这张卡被人质疑过）。这不等于库里没有它：它就在这里，条件照原样印在下面。
  什么时候成立：「他已经抽身、这条提醒的失败不会当场伤人时」
  什么时候不成立：「提醒必须发生在值班当场、人来不及时接手时」
  什么时候不成立：「第三个团队里更糟：提醒他根本没看」
  还没定的是：「他会不会真的回来看提醒」
  它靠这些前提：「系统能自己跑检查」
  它有 1 条来源记录：…
  带进一场新讨论：python3 -m dojo --db /abs/…/walk.sqlite3 discuss --card d-…
```

四件要能一眼分开：**它现在是什么状态 / 检索会不会把它交出去 / 它的条件与反例 / 它立在什么来源上**。
最后一行是可以直接粘进终端的命令，带绝对 `--db`。

## 2. 为什么一张卡会「不交出去」

`search` 只把**可以交出去的**材料给模型；屏幕另有一份完整清单，每张卡各自说原因。四种原因都来自账本：

| 原因代码 | 屏幕上说的 | 事实来源 |
|---|---|---|
| `challenged` | 这张卡被人质疑过 | 卡的 `status` 与 `contradictions` |
| `withdrawn` | 这张卡被撤回过 | 卡的 `status` |
| `no_acceptance_record` | 这个库里没有这套说法的认可记录（这不等于没人认可过它） | 事件账本里没有绑定这句的 `wording_accepted` |
| `acceptance_superseded` | 有人认可过它以前的说法，后来那句被改掉了 | 有认可事件，但绑的不是现在这句 |

被质疑的那张卡**不会消失**。这是这一片最重要的一条：以前同样的词只剩相反那条，
而剩下的那条看起来像是完整的答案。

## 3. 只记得大意

```bash
python3 -m dojo --db "$DB" search '半夜别老把人叫起来'
```

一个字都对不上时，屏幕先说清方法（只比字词，不认意思），再给出另一个办法：

```
  换个办法：下面是这个库里最近写下的 3 张卡，按写入时间排的，不是按意思找出来的。
  能不能认出你要的那句，由你看；程序不替你挑。
```

「最近写下」读的是 `snapshots.created_at`（当前这句第一次出现的版本），不是最后一次改状态的时间。
它是入口，不是搜索结果：屏幕上就这么写，也不参与排序。

## 4. 记得的是它换掉之前那句

```bash
python3 -m dojo --db "$DB" revise d-… \
  --statement '值班通知一律先等两次失败再呼叫负责人。' \
  --reason '想把做法推广到所有值班通知。'
python3 -m dojo --db "$DB" search '只有普通日报'
```

屏幕会印（先在条目开头引现在的句子，然后才是这一行）：

```
2. d-report  草稿  对上 5 个词：只有、日报、普通、有普、通日
  「值班通知一律先等两次失败再呼叫负责人。」
  你记得的字对上的是它以前的说法：「只有普通日报才等两次失败再呼叫负责人。」；
  库里这一句后来换过，卡片现在写的是本条目开头引的那句。
```

这一行只指「条目开头那句」，不说「上面」或「下面」：版式一变，方向词就会把新旧指反，
而「这句是哪句」是屏幕必须答对的事。

旧句子来自 `revise` 事件的 `from_statement`，逐字照印。**只有人的检索**会匹配旧句子：
发给模型的那次检索一个字都不变，模型不会看见一张卡「说过」它已经不说的那句话。

## 5. 机器读的那一面没有变

接管道或重定向时，`search` 的 stdout 仍是 `{query, method, matched_terms, results}`，每行的键也和以前一样。
屏幕用的两个键（`withheld`、`recent`）和每行的 `matched_on` 在打印前就被去掉；
`Store.retrieve(query)` 不带参数时的输出和上一版逐字相同。`verify.py` 的 F 段同时检查这两处。

## 6. 这一段**没有**做的事

- 不做语义检索。字不重叠就是找不到——所以才有第 3 节那个「换个办法」，而它标明自己不是匹配。
- 不替人挑哪条是「你要找的」。多条命中时只把句子、条件和来源并排摆出来。
- 不把旧句子算成一次新的到达，也不把它送进模型上下文。
- 没有真人参与，也没有真实端点评测（这个环境里没有配置端点）。
