# 回看一场讨论：把「原话留在记录里」变成他能做的事

2026-11-28。任务 #3389 的第二段：监督者复验了「四件原话写到一半断盘」的修法之后提出

> 现在回看仍要自己读 JSONL。如果我事后只想找一句原话及其上下文，入口应该能让我直接
> 做到，也别让我把材料误读成我已认可的结论。

`dojo transcript TRACE` 就是入口。只读：不开库、不写文件、不请求模型。它印三块——你在
讨论里说的话、四件追问（每件当时问的问题 + 你说的原话 + 记录把这一件记成了什么）、这场
写下的卡片与收尾方式；最后一句是「这些话是材料，不是结论：回看只说你说过什么，不判哪句
答到了点上，也不代表你认可了哪条结论。」

## 为什么要开一个新命令，而不是改 `--resume`

上一片的复核（`.scratch/3286/legacy/REVIEW-MISALIGNED.md`）量到一条：拿到「原话留在本场
记录里」之后，管道用户用现有命令读不回来——`show`/`list`/`search`/`--resume` 里原话出现
0 次，只有 `cat sessions/*.jsonl` 有，而 README 没教过。`--resume` 的正确职责是「接着谈」，
让它同时当阅读器，会让一条命令同时改状态和只读，且改动历史对话。

所以：新命令只读、独立于库、可以离线看一份拷走的轨迹。这也让本片不必动 `--resume` 的
既有行为。

## 三个词，各自对应一个真发生的事实

| 屏幕 | 轨迹里的依据 |
|---|---|
| 你说：… | `answer` 逐字，或讨论轮的 `user` 逐字 |
| 问的是：… | 该件最后一条 `elicitation.question` |
| 记录里记的是：收作原话 | `reading == "answer"`（其余：跳过 / 说到这儿为止 / 问到这儿时输入结束了 / 这句太长 / 退回了上一题…） |

一件问过多轮（含「改回上一题」）时显示**最后一条**，并注明「这一件问过不止一轮」。这是
append-only 轨迹的既有规则，也是回执和 `--resume` 用的同一条重放规则；显示第一条会把他说
过又收回的话重新算成材料。

## 断盘与不能续跑：两件不同的事

轨迹写到一半断了（监督者 11-28 量到的满盘情形）时：

- 已经写下的行照常显示；
- 最后那行只写了一半，屏幕说这一行没有算进来；
- 因为没有 `session_end` 行，**不**说「这一场没有写下卡片」——那一行正是没写成的行；
- 不为它印 `--resume` 命令：屏幕说「这一份不能接着谈：<原因>」，而那原因是拿
  `_load_resume_trace`（`--resume` 自己的校验器）量出来的，不是猜的。

## 回执里的那一句

四件问完之后，回执在「留在本场记录里」后面点名这条命令（带这一场的轨迹路径）。只在真有
记录可读时点名：`--no-trace`、以及「轨迹开过但第一行就没写成」时都不点名，因为那时没有
东西可看。

## 粘进来的回答：一条记录就是一行

监督者 11-28 在 `d7fbe00` 上量到：从文档粘来的回答带 U+2028（行分隔符），四句原话都写进了
轨迹，回看却把它当成坏 JSON 拒了——**程序自己写的会话，自己的回看看不了**。

原因在两边：`json.dumps(ensure_ascii=False)` 把 U+0085/U+2028/U+2029 原样留在字符串里
（JSON 允许），而 `str.splitlines()` 把这三个都当成换行。写对的、读错的。

修法在 `dojo/tracefile.py`，两边一起：

- **写**：这三个码点在落盘前转成 `\uXXXX`，一条记录一定是 `splitlines()`、`readline()`、
  `grep`、编辑器眼中的一行。
- **读**：只按 `\n` 切行。修之前写的轨迹（原字符未转义）照样能读——它的 JSON 字符串本来
  就接受这个字符。

读数落到了每一个读者：`discuss` 写、`--resume` 读、`transcript` 读、`scripts/dao_session.py`
与 `scripts/dao_live_session.py` 读。导出层另有一层：`note.md` 也是按行切的文本，所以
`dao_session.py` 现在遇到带这三个字符的回答会**具名拒收**（「情境: 回答里带 Unicode 行分隔符…」），
不再写出一个字段解析错位的笔记（实测过：同一条回答以前会让 `dao_life.py` 报「张力
p-T1 少了「方向」这一格」，而那句就在文件里）。

证据 G1–G5；测试 `tests/test_trace_line_breaks.py`（写入、读旧格式、真会话、`--resume`、
导出脚本五个入口）；臂 L（不转义）与 M（又用 `splitlines()`）各自单独咬住。

## 独立复核（`abe7587` 上）判不成立的三处，已修

复核报告：`.scratch/3286/legacy/REVIEW-TRANSCRIPT.md`。

1. **「收作原话」仍等于 `reading == "answer"`。** 上一轮只修了句尾语气词，最普通的
   `我不知道` / `我忘了` / `我不太清楚` / `记不清了` / `没印象` / `说不上来`（共 11 条）
   全部穿过去，真入口回执照旧「四件你都说了原话」，`dao_session.py` 还把「我忘了」写进
   `note.md` 当他的原话。现在剥离开头的主语与程度词（`我` `我也` `不太` `有点` `真的`…）
   再要求**整句**等于列表里的一条；列表补上 `记不清` / `记不起来` / `没印象` / `说不上来` /
   `不确定` / `拿不准` / `说不清楚`。带他自己从句的句子仍是回答（证据 H2）。
2. **留下未认可草稿时说「这一场没有写下卡片」。** `session_end` 同时有 `saved: []` 与
   `draft: d-…`，回看只读了 `saved`。库里那张卡的句子就是这一场谈出来的，而它恰恰是
   「没人认可过」的那张，最该被看见。现在单独一句点名草稿（证据 H5）。
3. **旧轨迹：回看说「收作原话」，`--resume` 的重放说一件都没收。** 行里存的是当时的读数，
   续跑用今天的规则重算。屏幕现在两个都说，并写明「续跑会按后者算」（证据 H6）。
   另外 `--json` 补上 `resumable` / `complete` / `draft`。

复核还留了一条方法论上的硬教训：13 条臂两层真红是真的，但**没有一条碰 `dojo/elicit.py`**——
把分类器换回旧规则，单元测试 18 红而证据脚本照样「全部成立」。现在臂 N 只改 `elicit.py`，

## 没做（别当成已解决）

- 不判「答没答到点上」。本片与上一片一样，只把材料与结论分开说。
- `collected` 这个轨迹字段名没改（语义是「收下的材料」）。
- 上一片复核提出的 `NON_ANSWERS` 精确匹配洞（`不知道啊`/`忘了诶` 被当成回答）已在本
  切片修掉（`dojo/elicit.py`，测试 `tests/test_non_answer_words.py`），但**仍有边界**：
  只剥句尾语气词与一个「了」，`嗯`/`随便`/`都行` 这类整句填充词单列；带他自己从句的句子
  一律算回答。没有真人语料，覆盖仍靠我构造的句子。主语与程度词现在也算前缀（`我`、`我也`、
  `不太`、`有点`、`真的`、`确实`），剥完仍要整句等于列表里的一条，所以「真的不知道怎么办」
  这种带从句的仍是回答。右边界同样测过：`知道了`/`明白了`/`没有问题`/`没有通知就没人知道`
  都仍是回答。**仍可能漏**：真人说法比列表多，例如台语/方言口气、夹杂外语的「我不 sure」。
  这类不进列表就仍会被收下——屏幕上的「收作原话」始终只是「这行按当时的规则判成了 answer」，
  不是「他答了」。
- 真终端（pty）视线仍没量成。`transcript` 的输出是纯文本、无 readline，所以终端与管道
  一致；但这是推理，不是量过的读数。
