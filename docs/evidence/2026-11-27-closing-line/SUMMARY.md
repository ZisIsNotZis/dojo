# 四件问完之后，他知道了哪几件算他的

日期：2026-11-27。基线：`dbda25c`（`git ls-remote` 实测远端 `master` 就是它）。
离线，不调模型、不联网、不跑真实端点，不写库。

一句话：**四句问法以前问完就没了；现在问完会说一句哪几件落在他说的上、哪几件是系统补的。**

## 问题是从哪看出来的

不是从代码猜的，是从入口跑出来的。`probe_closing.py` 在基线上跑了两场真会话（`run_discuss`，
注入客户端），一场四件全答、一场四件全跳过，然后读最后一个问题之后的屏幕：

| | 改前（`dbda25c`）四件全答 | 改前四件全跳过 |
|---|---|---|
| 最后一个问题之后 | 132 字 | 164 字 |
| 说的是什么 | 「讨论已结束。」「本场结论卡片 ID：…」「本场会话轨迹：…」 | 同上 |
| 哪几件算他的 | **没说** | **没说** |

两场的尾段**都没有一个字**提到哪一件被收下、哪一件留成系统补。也就是说：一个人答了两件、
跳过两件，最后看到的东西和四件全答**一模一样**——最自然的读法是四件都收下了，而记录里
那四件全是「系统补」。

这里要挡住一个诱人的错话：不能因此说产品在骗人。它在入场块里已经说了「答不上来就跳过」，
而且真跳过了；缺的是**结束时的回执**。少了它，「跳过」和「收下」在屏幕上无法区分。

## 改了什么

`dojo/discuss.py` 加了一个纯函数 `closing_text(collected, supplied)`，在四件问完、循环出路
那一点印一次：

- 两件答、两件跳：`四件问完了：情境、代价 是你说过的；张力、失效 没说出来，我按这条的写法补上了。卡片上的字这一版仍全算我写的。`
- 四件全答：`四件问完了：四件都落在你说过的话上。卡片上的字这一版仍全算我写的。`
- 四件全跳：`四件问完了：四件都没说出来，我按这条的写法补上了。卡片上的字这一版仍全算我写的。`

三句话都由**轨迹里真正记录的那两个列表**（`elicitation["collected"]` / `["supplied"]`）拼出来，
件名顺序取自 `PART_ORDER`，所以句子不会和记录分家。「卡片上的字…仍全算我写的」沿用入场块
同一句话，不新增承诺——这一版条目仍然记「系统的」。

`verify.py` 跑四场真入口（全答 / 全跳 / 答两跳两 / 关记录全答），把屏幕那一句和 `session_end`
里的 `collected`/`supplied` 对着比。它证明屏幕说了这句话、且与记录一致；不证明有人因此多说了一件。

## 红臂（都实跑）

1. **去掉那一次打印，函数留着**：`verify.py` 退出 1，点名「四件问完之后屏幕上没有那句「四件问完了」」。
   这一臂是故意做成不带 `ImportError` 的，否则红得没有信息。
2. **让句子撒谎（`closing_text(list(PART_ORDER), [])`）**：退出 1，点名
   「四件全跳过时不说哪件是他的」与「答两件跳两件时分开说」。只有红臂 2 才能证明这项检查

## 还证明不了什么

1. **没有人因此多答一件。** 这台机器上的轨迹仍然只有我的探针。这一格空着，和上一片一样。
2. **「答了两件」这个混合状态是我构造的输入**，不是观察到的真人会话。
3. **一行里有四个件名，可能太长。** 真实终端宽度下没量过；只有两臂分开时那一句最短。
4. **`another_rule` 那一句在真会话里从不出现。** `elicit.py` 为四件都写了
   「他答成另一条做法时接」的换问法，`scripts/dao_elicit.py` 也把它印在演练报告里，
   但 `discuss.py` 只取 `follow_ups["none"]`。`probe_second_turn.py` 在基线与本片上都复现：
   后三件的第二轮**全是** `none`；而「情境」那一件——他答成另一条做法时——根本没走到第二轮，
   因为 `classify_answer` 把一句实质回答算成 `answer`（那是它的声明设计，不是缺陷），
   于是不再换问法。所以演练报告里印的四句「接法」，真会话一句也没用过。
   这是本片**没有改**的缺口：它要动的是「怎么判断他答偏了」，属于另一件事。

## 我自己的两个错，写在这里免得下一个人重犯

1. **探针按自己的路径推仓根，测错了树。** `probe_closing.py` 起初写
   `ROOT = Path(__file__).parents[2]`，从 `.scratch/` 跑时推到了主工作树 `e4af6c6`
   （那份还有本地改动），读数看着像真的。现在必须传 `--root`，并在开头断言
   `dojo.discuss.__file__` 在被测树下，否则直接失败。
2. **红臂差点毁掉改动。** 第一次做红臂用
   `git show dbda25c:dojo/discuss.py > w3/dojo/discuss.py`，把自己的改写成基线，
   随后 `git checkout` 又把它清掉。现在红臂一律在 `git archive` 导出的 `/tmp` 副本里做，
   不碰工作树。**红臂不该修改被测的那棵树。**
3. **测试输入里一件跳过占两行，不是一行。** 第一版混合用例只写了两个空行，结果每个答案
   都错位到下一件上，测试报的「失败」是测试的错，不是产品的错。已改成每个跳过的件给两个空行。
