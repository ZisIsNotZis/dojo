日期：2026-11-27。基线：`dbda25c`。前一片：`02bd7be`（"Tell the person after the four
questions which parts were theirs"）。本片是它的更正：`02bd7be` 那一句在两处说了产品做不到的话，
这里把句子改到与现实一致，并把两处都钉进检查。

离线，不调模型、不联网、不跑真实端点，不写库。

一句话：**四句问法以前问完就没了。上一版补了一句回执，但那一句把「你答了」和「回答进了卡片」
混成一句，还在他说「跳过」时说他答了。现在这一句分开说三件事：每件怎么了、回答去了哪、卡片动没动。**

## 上一版错在哪（先写这个，因为它决定了这一版测什么）

两处都在真入口上复现，不是读代码推的：

1. **他说「先跳过这一题」，屏幕说他答了。** `classify_answer` 只把 `不知道/没有/看情况…`
   这类**整句**当非回答，`先跳过这一题` 落在 `return "answer"` 上。四件都这么说时，`02bd7be`
   的屏幕是「四件都落在你说过的话上」，轨迹里 `collected` 也真是四件——**记录与屏幕一致，
   但两者都与他说的话相反**。所以「与轨迹一致」这一条检查咬不住这个错。
2. **「我按这条的写法补上了」暗示卡片被回答改过，可卡片在提问之前就写好了。**
   实测（导出副本，逐轮 dump 全库）：`candidates`/`snapshots`/`events` 在四问前后**逐行相同**，
   第一问提出时卡片已经在库里。基线 `dbda25c` 也是这样——**顺序是旧的，新的是那句话**。
   于是「补上了」把一件从来没发生的事说成发生了。这是这一版最重的一处：
   上一版的记录还写着「这一版条目仍然记系统的」，那句自相矛盾没有被任何检查发现。

另外两处是复核时顺带量的，也都进了检查：

3. 开场块邀请「想停随时结束输入」，可那句话印在 `if raw is None: return "eof"` 之后，
   **提前结束的人一个字的回执都拿不到**。这是产品自己邀请的路径。
4. `verify.py` 的 JSON 里把 `"exit_code": 0` 写死，失败时 stdout 仍写 0。现在只认 shell 退出码，
   JSON 只给人看。

## 改了什么

`dojo/elicit.py`：新增 `is_skip_request()`，`classify_answer` 多一种读数 `"skip"`。
边界故意窄——只认**整句**是跳过请求（可带一句「我还没想好」之类的交代）：
`先跳过这一题` `跳过` `这题先跳过` `下一题` `不想说` 都算；
`我跳过这一步的时候就会出错` **不算**，因为那正是「失效」那件要的原话。

`dojo/discuss.py`：`closing_text(collected, skipped, supplied, kept=, unfinished=)`。
三种结局三种说法，件名一律按 `PART_ORDER` 排；`kept=False`（`--no-trace`）时换成
「这场不留原文，这些回答只在这次对话里用过」。屏幕实测：

| 场景 | 屏幕上那一句 |
|---|---|
| 四件全答 | `四件问完了：四件你都答了。这些回答留在本场记录里，没有写进卡片。卡片是提问前写下的那句，之后没改过，字这一版仍全算我写的。` |
| 四件都说跳过 | `四件问完了：你说跳过 情境、张力、代价、失效。卡片是提问前写下的那句，之后没改过，字这一版仍全算我写的。` |
| 答 / 跳 / 没答 各一件 | `四件问完了：你答了 情境、失效；你说跳过 张力；没答出来 代价。这些回答留在本场记录里，没有写进卡片。…` |
| 答一件后结束输入 | `问到这里停了：你答了 情境；没答出来 张力；代价、失效 没问到。…` |
| 四件全空 | `四件问完了：没答出来 情境、张力、代价、失效。卡片是提问前写下的那句…`（没有回答，所以不谈回答去了哪） |

`session_end.elicitation` 多记一个 `skipped` 列表（续跑时从轨迹里重建，`reading == "skip"`）。
「问了没答」与「说跳过」现在是两个字段，不再合成一个。

回执照旧在循环外印一次，但三条出路（正常走完 / 提前结束 / 中途 `too_large` 后走完）都印。

## 还证明不了什么

1. **没有人因此多说一件。** 这台机器上的轨迹仍然只有我的探针。这一格空着，和上一片一样。
2. **跳过识别的边界是我定的，不是量出来的。** 我只用自己写的句子试过，没有真人语料。
   把「跳过」读成 skip 也可能错过一种真回答（有人用「跳过」讲他真跳过的一步）；
   我用「必须整句」来挡，但这是判断，不是证据。真要量，需要一段真人会话记录。
3. **一行里有四个件名，可能太长。** 真实终端宽度下没量过。
4. **`another_rule` 那四句「他答成另一条做法时接」的换问法，真会话里仍然从不出现**——
   主因是 `discuss.py` 第二轮取的是 `follow_ups["none"]`，与 `classify_answer` 无关
   （就算第一件被读成 `none`，第二轮仍是 `none`；实测两种输入都是 `none`）。
   上一版把主因记成了次因。这是本片**没有改**的缺口：它要动的是「怎么判断他答偏了」。
5. **卡片有没有「该被回答改」这回事，本片没有表态。** 句子现在只说它没改。
   要不要让回答进卡片是另一件事，不在这片范围里。

## 我自己的三个错，写在这里免得下一个人重犯

1. **用 `write` 带行号范围改一个大文件，把相邻代码段写坏了。** 我按行号替换
   `print_closing` 那 14 行，结果把 `SYSTEM_PROMPT` 的开头和 `record()` 的函数头一起吃掉。
   现在改成 `.scratch/3359/patch_discuss.py`：九个锚点逐条 `assert count == 1`，对不上就整体不写。
   **改大文件不要用行号，要用唯一锚点。**
2. **我的第一版探针把「空行」当成「结束输入」。** 空行是 `classify_answer` 的 `none`，
   会继续问第二轮；真 EOF 是 `read_line` 抛 `EOFError`。我拿空行当 EOF，读出了
   「`supplied` 里有没问过的件」，差点写进记录。**测提前结束要把脚本序列走完，不要多补空串。**
3. **`closing_text` 一改，我自己写的三条断言当场真空。** 旧测试把整句文案钉死，
   新文案下它们失败——这是对的；但更容易发生的是反过来：`test_elicitation_closing.py`
   上一版有一条 `assertIn("情境、张力、代价、失效", text)`，那串字在开场块里就有，
   把回执整段删掉照样过。现在每条断言都带「这个短语只可能出现在回执里」的定位。
