# m1.5-checkpoint — 谁跑过 M1.5 的那一局，跑出来什么

owner：dojo 的 manager。用途：M1.5 用户检查点那一次落盘的记录，一局一个文件——person 亲手跑的记 `person-<YYYY-MM-DD>.md`，模型代跑的记 `rerun-<YYYY-MM-DD>.md`；两条路只会有其中一种文件。

**这里现在的状态：第 ① 路已发生，M1.5 由 person 确认。** person 2026-10-23 亲手跑过并给出判断（`person-2026-10-23.md`），他的原话是「finished experiencing the product… way better than last time, I'm satisfied with the user experience part.」。**`m2f` 不跑**：他跑过并给出判断，门就关了，再让模型跑一遍是拿模型的判断替换他的判断。

**判断的出处是他的会话，不是 trace 文件。** 那一局的 trace 路径他没有给，本目录也没有收到 trace；记录里的第 2、3、4 行因此写成「未提供／未记录」，并写明谁能补。这不阻塞 M1.5，只阻塞「事后复盘他怎么用」。

**第 ② 路不再适用**：等待窗停在两条互斥的路之一上，第 ① 路先发生了，`m2f` 的那一局（2026-10-25T12:28Z 到点才跑）不再跑。若 person 以后把 trace 交来，它原样复制进本目录、加进同一份 `person-2026-10-23.md`，不新开一份，也不把「person 确认」改写成「trace 确认」。

一个记录文件必须写下的四行，缺一项就写「未知」并写清谁能补，不拿推断填满：

- 日期与执行者（person 亲手，或模型代跑）。
- trace 路径，以及那一局的 trace 能解析出来的行数与末行 `session_end`。
- 这一局用的模型，以及换过模型时的理由（`DOJO_LLM_MODEL` 覆盖了什么）。
- 这一局的请求数与（如端点回显）用量，供下一局比较。

**没有 trace 的局，第 2 行的行数与末行不可解析，下面的验收命令不适用**：这时第 2 行写「未提供」、第 3、4 行写「未记录」，判断本身照样成立，因为判断来自 person 的会话而不是来自轨迹。本目录的 `person-2026-10-23.md` 就是这一种。

验收命令（只在记录里有 trace 路径时跑，把 `<trace.jsonl>` 换成那条路径）：

```sh
python3 -c "import json,sys;rows=[json.loads(l) for l in open(sys.argv[1])];print(len(rows), rows[-1]['event'], {r['model'] for r in rows})" <trace.jsonl>
```

第 ① 路发生时，本目录**只有一个记录文件**，没有 `m2f` 那一局：他的 trace 路径原样写进去（他没给路径时写「未提供」），trace 文件若有则原样复制进来、不改内容，上面四行按他那一局填，**他说的原话与他的判断**贴在同一文件里，另加一行写明「person 的那一局已到，`m2f` 因此未跑」。他若给了路径（`ls -t /tmp/dojo-play/*.jsonl | head -1` 打出来的那一行），那一行原样写进记录。转存他的那一局时不改写他的话、不替他解释判断；他说的原话一字不动地贴，判断写在他原话旁边并注明是谁写的。

**为什么第 ① 路不必再跑一次**：重跑只为不让 M2 盖在一扇没人关过的门上。person 亲手跑过并给出判断，门就关了；再用模型跑一遍等于拿模型的判断替换他的判断，而检查点要的正好是反过来的东西。所以第 ① 路下 `m2f` 不跑，也不为“对照”再跑一局。

**「未确认」是一个真实结果，不是失败。** person 跑完说「还是得管机制」或「说不清」，与说「很好」一样要落盘：判断本身写进去，不当成没跑过，也不为了让它好看而改问法再问一遍。一场记录的价值在于它记下了他实际怎么用，不在于给出通过。

模型代跑只保证 M2 起步时脚下有东西；「person 亲手跑过」这一句只有 person 能给，模型跑多少局都替代不了它。所以走到第 ② 路时，记录里写的是“到点无 trace，故 `m2f` 代跑”，而不是把它当作 person 的检查点。
