**1. 决定**

归系统，不归写记录的人。写者只在落笔那一刻知道自己在看哪个修订；他无法为一棵后来被重写、被另建标签的仓库持续作保。所以「引用仍解到它自称的修订」这件事必须由系统在某次真运行时**重新解一遍**并留证，而不是靠作者记得。但**承诺**归写者：记录必须把修订钉死到写者当时看到的那串字符本身——完整 40 位对象 id，不做缩写。缩写之所以是洞，不是因为 ref 太多，而是因为记录留了「让 git 自行选一个对象」的空间。

**2. `scripts/dao_life.py` 改 2–4 处**

- `_pinned_name`：只认完整 40 位十六进制。这是唯一能把「对象 id」和「可以是 ref 的名字」分开的写法（我实测：全长按对象 id 解析，只有缩写会被 ref 劫持）。现有记录全是缩写，所以这需要一次迁移，代价要写进 LOOP。
- `_names_the_object`：判据 (a) 换成 `git for-each-ref --format=%(refname)` 取末段比对，覆盖 `refs/<name>`、`refs/notes/`、`refs/remotes/<name>/HEAD`；或 `git rev-parse --symbolic-full-name <name>` 有输出即 ref。`--disambiguate` 不报 ref，别用。
- `resolves()` 的返回值带上**所查对象 id 与所查路径的 blob id**，写进 `record_checks.json` 的每条 ref。读者几年后能重跑同一句 `git cat-file`，比对的是 blob id，不是我的结论。
- 顶层判定加一档：这条检查**何时跑过**。今天 `unchecked` 是「这次没查」，读者读不出「从来没查过」。

**不做**：不加后台守护、不在提交钩子里跑全库、不缓存判定结果当证据、不改引语匹配逻辑（行号那两条缺口与本决定无关，别混进来）。

**3. 最可能错的地方**

我假设写者有能力拿到完整 id，而这也让记录更难写、更容易有人回头改成缩写，然后再没人发现。也可能正解是让工具在写记录时自动展开缩写，那我这条就是把手动活推给了人。我上一轮也承认：别人建一个同拼写标签能让正确的全长引用翻红——这是方向的代价，不是无代价。

**4. 置信度**

中。能移动它的是两个实测：真库做 40 位迁移后的成本（多少条要改、改错多少），以及 `for-each-ref` 那版判据在 `refs/<hex>`、`refs/notes/`、远端 HEAD 三种情形下是否都翻成 `moving-name`。
