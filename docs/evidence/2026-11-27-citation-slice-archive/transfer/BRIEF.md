# 经验交接：持续性检查该由谁拥有

这份文件只做一件事：把一条已经入库、能公开核对的工作经历，连同它的**适用条件**，
交给一个正在做实质决定的人。它不要求你同意；它要求你在动手之前，先把自己原本会
怎么做写下来。

## 一、经验本身（可核对）

出处（两处，同一段话；行号按 `e4af6c6:docs/proposal-knowledge-network.md` 计）：

- `e4af6c6` 第 111 行、第 307 行

  sha256（blob 内容）`dcfefc4dedb0f42cb25af8839e9170d2839c37317ef8e04bd3fa077f45e75b91`
- 工作树那一份的 sha256 是 `6e14946d…ad88`，**和 blob 不同**（工作树是脏的，
  所以行号和内容都该按 blob 读。我这轮第一次写简报时把两者混了，跑 verify.py 时
  看到两数不同才自己发现）
- 引语：`He CAN challenge later, e.g. 'did you do simulation?', but not responsible for reminding that.`

注意一处容易读错的地方：这段是**转述并照录**某位当事人的原话，不是本文作者的判断。
记录里把它标为「自述」，不是「观察」。

从这段话说出来的判断（库内 `dojo-d-001` v1，原文）：

> 在一个人已经抽身、只在自己想推翻时回来的情境里，宁可持续检查整个搬进系统也不留给
> 人，代价是系统的机器时间，以及他可能读到一条没被检验的道。

动作：**把持续检查搬进系统：自己写预测、自己跑、自己留回执；人这一侧只留「随时可推翻」。**

## 二、适用条件（这一段比结论重要）

这条道自己写着两处失效，任何一处成立，动作就不该照抄：

| 轴 | 值 | 成立时怎么办 |
|---|---|---|
| `check_kind` | 必须等世界里发生 | **扣住不印**：那一格印「未检」，降回自述；不拿人的记忆或「他说过很多次」顶替 |
| `judge` | 检查者与被检查者是同一个作者 | **反过来**：换一个独立的一方来跑，并把「谁跑的」写进回执 |

所以这条经验真正的形状是：**只有在「检查是结构或模拟、能跑」并且「跑的人不是被检查的
那个人」的时候，才把检查整个搬进系统。** 两个条件缺一个，搬进去只是让自欺变成自动的。

## 三、你要判的那件事

你手上有一个真实的坑：一份记录引用的是 git 的**缩写**对象名，而 git 解析裸名字时会走
`refs/<name>`、`refs/notes/<name>` 这些门现在没扫的命名空间——别人建一个同拼写的标签，
记录一个字没改，判定就从 `fail/absent` 翻成 `pass/found`。

问题不是「怎么补扫描」。问题是：

> **持续性检查（引文多年后是否仍解析到它指的那个修订）归谁拥有——写记录的人，还是系统？
> 记录本身必须携带什么，才能让几年后的陌生人自己判断这次检查到底跑过没有，而不必相信
> 任何人的记忆？**

## 四、先写下来，再看别的

在给答案之前先记下：**不看这条经验，你原本会怎么做？** 以及你会刻意**不**做什么。
等你看完第六节再回来对照。

## 六、这条经验在它自己的案子上先咬了自己一口

`judge` 那一格写的是「检查者与被检查者是同一个作者 → 换独立的一方来跑」。
而这份记录是**这个系统自己写的**，检查也是这个系统自己跑的。照条件读，结论不是
「系统拥有它」，而是：**系统可以跑，但「过」不能由它自己签**——回执里必须能看出是
谁跑的，而今天的回执只写了一个脚本路径和版本号（`ran.by`），那不是一个人，也不是
一个可以被追责的独立方。

这不是我事后加的注解，是从那两条 `off` 条件里读出来的。请你独立判一次：它成立吗？
如果成立，你原来的答案要改哪一句？

要说明我自己的分量：这一步到底是「直接读法」还是「换了轴」，我判不了——`judge` 那格
写的是谁更能判**一个人**的处境，而这里的检查是 `git cat-file`。把它搬过来，可能是同一条
道理，也可能是偷换。**这个「可能是偷换」就是这次要检验的东西**，不是我要你知道的答案。
