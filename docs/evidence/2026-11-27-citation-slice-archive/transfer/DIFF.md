## 被哪一句改的

**改它的那句话**（BEFORE §2 末条）：
> 顶层判定加一档：这条检查**何时跑过**。今天 `unchecked` 是「这次没查」，读者读不出「从来没查过」。

**改成它的是这一行读数**（`verify.py`，真库 `docs/dao/person-dojo`）：
> 出处核对 17 条：引语 0 条逐字落在它写的行内；commit 在本仓可解析且含有该文件 0 条，
> 按所指版本核对 0 条，不可解析 17 条 …

以及**同一份输出的第 2 行**仍然写着 `dojo-d-001  v1  合写 · 检（3/3：自洽 过 / 可反驳 过 / 落地 过）`。
（出处核对在第 18 行，与第 2 行**相隔 16 行**，由 `verify.py` 数出。我第一版写
「上面一行」，数错了，已改。）

BEFORE 猜的是「读者读不出这次检查跑过没有」，实测给出的是一件更硬的事：**检查跑过、
如实报了 0/17，而那条道的等级一个字没动。** 所以问题不在时间戳缺失，在判定与证据之间
没有连线。

## 这算不算「经验改变了行动」

算，但要说准是哪一半：

- **方法上真的变了**：从「在顶层加一档记录」改成「让出处计数成为封顶格」。这是一个会
  改代码行为的动作，不是措辞。
- **归属上没有变**：这一半是同伴原本就判对的，brief 没有移动它。把它说成「经验让人改了
  主意」会是夸大。

## 反过来的证据（如果这条经验是错的，会长什么样）

- 若把出处并入封顶格之后，真库 17 条全印「未检」，而读者因此**不再读**引文——那这条
  修正就是把诚实换成了注意力流失，该回退。
- 若某天历史没被重写、对象还在，40 位 + blob id 就足够，那 AFTER 里加的「引语字节
  sha256」是冗余。今天加它，是因为 17/17 的对象都已经不在了，不是因为它一般地必要。
