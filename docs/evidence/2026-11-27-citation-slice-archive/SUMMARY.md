# 一处不变式，和它改变的一次决定

日期：2026-11-27。基线：`e1980f8`（已发布，GitHub `master`）。本片是一个提交：让出处核对封顶单条道的等级。

一句话：**当一条道自己引的凭据在它写的那个修订上读不到时，那一行不许说「检」。**

## 为什么这条要单独成片

这条经验来自另一个现场（`docs/dao/transfer/2026-11-27-check-ownership/`）：
它说「持续复核归系统」，而这条判断有一个可测的后果——系统跑了检查、如实报了，
但读数没有连到人读的那一行。经验本身没有在这里被再论证一遍；这里只放它对代码的那一次后果。

## 改前 / 改后：同一份检出，只换 `scripts/dao_life.py`

陌生人从公开仓库检出的浅克隆（`--depth 1`，`is-shallow-repository=true`），
所以记录里引的那些修订不在本地。这不是造出来的情形，是任何人第一次拿到这个仓库时的情形。

```
$ git clone --depth 1 <this repo> && cd <repo>
$ python3 -B scripts/dao_life.py docs/dao/person-dojo --check
```

**改前（`e1980f8`）：**

```
  dojo-d-001  v1  合写 · 检（3/3：自洽 过 / 可反驳 过 / 落地 过）
  出处核对 19 条：引语 0 条逐字落在它写的行内；…按所指版本核对 0 条，不可解析 19 条…
  rc=0
```

两行相隔 16 行：第 2 行说「检」，第 18 行说按所指版本核对了 0 条。计数没有撒谎，
它只是没有碰到任何读者会读的那一行。退出码 0。

**改后：**

```
  dojo-d-001  v1  自述 · 未检（3/3：自洽 过 / 可反驳 过 / 落地 过） · 出处 未核（0/2 条按所指版本核对）
```

判词从 `合写 · 检` 降到 `自述 · 未检`，出处那一格接在同一行上。
`3/3` 保留：那三格确实是过的，封顶加的是词，不是把一个真读数改小。

在完整历史的检出里，同一行读作 `合写 · 检（3/3…） · 出处 过（2/2 条按所指版本核对）`，
判词不变。**同一个不变式，两种检出都成立**——这是它值得写成不变式而不是写成一个补丁的原因。

## 真正改动的代码

`scripts/dao_life.py`：新增 `sources_cell()`，`status_of()` 在它不为 `pass`/`not_run` 时把
`mark` 降到 `未检`，并把那一格接进同一行。只算这条道自己挂着的 episode，
所以邻道的缺口不会牵连它；作者自己写的模拟材料（`commit_state="not-required"`）不封顶，
欠修订的不是失败，是不适用。

## 还开着的三处（知道，没修）

出处核对在三种 ref 写法上仍然偏松：一条 ref 里写多个行号时任一个对上就算过；
写了数字却解析不出行号时静默退回最松的读法；以及除了 `refs/tags`/`heads`/`remotes` 之外
还有 git 会解析的命名路径没被扫到。

它们不影响本片的不变式（本片问的是「这一行有没有夸大」，不是「门够不够严」），
所以没有在这一片里改。写在这里是为了让下一个人知道它们还开着，而不是以为门已经收紧了。
具体的复现方式不在公开交付里。

## 这份记录还证明不了什么

1. **只有一次决定。** 同一条经验只在「检查归属」这件事上被用过一次，改了一处代码。
   这不是「这条经验一般地有用」的证据。
2. **判者是我。** 改哪一处、怎么封顶，是我选的；没有第二个独立的人判过这个改法对不对。
3. **封顶的代价没有测。** 若某天一批真实记录全因修订取不到而齐刷刷印「未检」，
   读者可能不再读引文。那时该回退的是封顶的呈现方式，不是不变式本身。
4. **`未核` 与 `不过` 是两个词。** 前者是「问不到」，后者是「对不上」。合成仓库里我能造前者
   也能造后者；真实库里我只见过前者。
