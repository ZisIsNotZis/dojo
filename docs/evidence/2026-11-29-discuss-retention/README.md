# 从自己的讨论草稿，到另一场可以借用的材料

在仓库根目录运行 `python3 -B scripts/verify_discuss_retention.py`。脚本通过公开的 `python3 -m dojo` 入口使用临时库和本机回环补全；材料全是合成的，不继承凭据，也不访问真实模型。产物路径会印在终端。

| 谁在操作 | 怎么做 | 实际结果 |
| --- | --- | --- |
| 作者：认可措辞、决定哪些原话可带走 | 像平常一样 `discuss`。核对屏上的主持人拟写和它的前提，再决定是否输入 `/认可`。追问结束后，核对逐字的回答；例如输入 `/附答 情境 失效`，只附这两条。 | 结束输入但不选时，卡上没有新增附答；明确选的两条可另场读到。原场收尾仍可回看完整本地轨迹，包括主持人的追问；读卡和另场只拿所选原话及出处，不拿整句追问或整场路径。 |
| 作者：找回自己的草稿 | 从原场回执复制「找回本场先前的拟写」。选一轮，把你的原话和拟写并排读；可以「略过」后再回来，也可补边界，用 `/留下` 认可屏上版本。 | 回找、略过和留下均未请求模型。略过不改变库；留下后，准确措辞和补上的边界才成为可供另一场借用的卡片。 |
| 读者：只带需要的卡 | 在同一库里搜索，并明确选中一张可借用的卡开始自己的讨论。 | 普通检索和新场不带未认可的讨论措辞；另场模型只收到所选卡的已认可措辞、边界和明确附答。例中的乐器点收者借用「先隔离损坏件」，不照搬刮刀袋和编号一一对应的前提。这个取舍由合成角色人工作出。 |
| 作者：继续自己的个人档案 | 仅在继续自己的工作时运行 `discuss --with-profile`。 | 同库默认新场既不读取旧档案、也不追加档案。显式启用时，开场提示档案会发给模型、且可能被追加；已有内容仍保留。 |

可以对照 `first.stdout.txt`（措辞和附答核对）、`transcript.stdout.txt`（作者本地回看）、`reader-request.json`（另场确实收到的材料）、`draft-skip.stdout.txt`／`draft-retained.stdout.txt`（略过与留下）以及 `own-profile.stdout.txt`（档案告知）。脚本也检查默认不使用档案、普通检索和新场不显示未选原话，未认可版本不会触发模型请求，以及原场的追问不出现在读卡数据、另场屏幕、模型请求或另场轨迹里。

**边界。** 尚无已确认配置且获授权的真实模型入口；本机回环只验证程序交付的内容，不证明真实主持质量或不同的人能稳定采用资料。`/附答` 不是对已认可措辞的脱敏，认可前仍要读清整张卡。旧库里没有明确选择记录的附答保留在本地，不进入普通检索或新场。这里区分普通分享和本地恢复，不做多人认证：本来能读同一份数据库或轨迹文件的人，仍然能在本地打开它。
