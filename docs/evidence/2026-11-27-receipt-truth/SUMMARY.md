# 回执说的是真发生的那件事

日期：2026-11-27。基线：`c768fd0`。上一片：`docs/evidence/2026-11-27-closing-line/`。

离线，不调模型、不联网、不跑真实端点，不写库。

一句话：**回执以前有六种真事、只有四个词。**「他到某一问就不想继续了」被说成「没答出来」，
「这几件先不问了」被说成「你答了」或者被扩大成「四件全不问」。现在一件一个词，范围按他说
的读，读不出来就不替他决定。

## 怎么发现的（都是真入口，不是读代码）

这些是有人拿着产品自己说的两句话走进去撞出来的，不是我推的：

| 他做的事 | 屏幕以前说 | 轨迹以前记 |
|---|---|---|
| 答完第一件，在第二问直接结束输入 | `没答出来 张力` | `collected=['情境']`，`supplied=[]` |
| 在任意一问说「这几题我想先跳过」 | `你答了 情境、张力`，后面的照问 | `张力` 进了 `collected` |
| 在第一件回答里说「剩下的流程我都不讲给新人听」 | 当成停止提问，材料丢掉、这场提前结束 | `collected=[]` |
| 「接下来两题先跳过」 | 四件全搁下 | 没有数量概念 |

第二行的形状最糟：屏幕与轨迹一致，因为两边都错在同一个地方——那句请求被 `classify_answer`
读成 `answer`。所以「屏幕与轨迹一致」这类检查**结构上咬不住**它，只有拿他说的话本身去核查才行。

## 改了什么

`dojo/elicit.py`：多一种读数 `skip_rest`，由 `skip_scope()` 判定。它不再在句子里找词，
而是**解析**：

1. 剥掉句尾的动作词（跳过／略过／不答／不讲…，可带 了／吧／一下）。
2. 剥掉范围词与虚词（接下来／剩下／其余／这两题／都／先／我…）。
3. **还剩实词就不是请求**——`剩下的流程我都不讲给新人听` 留下 `流程`、`新人听`，所以它是原话。
4. 剥完还有数字就读出来：`接下来两题` → 2；数字大于剩下的按「剩下的全部」；没有数字而只剩下
   范围词（`这几题`）→「剩下的全部」。

只有当前这一问的「跳过」「先跳过这一题」仍是 `skip`：他说不出数量，就不替他扩大。

`dojo/discuss.py`：回执 `closing_text()` 现在有六种结局词，一件只出现一次：

```
你说跳过 张力 · 问到 张力 时你结束了输入 · 你说接下来 2 题先不答 代价、失效
你说剩下的先不答 代价、失效 · 没答出来 代价 · 没问到 代价、失效
```

`session_end.elicitation` 多记 `declined`（被搁下的几件）与 `declined_count`（他说出的数量），
续跑时从轨迹重建；`session_end.reason` 多一个 `declined`，与 `eof` 一样留下未认可草稿。

如果请求覆盖了**全部**剩下的问题，这场就在那里结束（`declined`）；如果只覆盖了前几件，
后面照问，最后照常打印收尾回执。

## 第三轮：一句我写了但程序做不到的话（监督者发现）

认不出的说法被收成原话时，屏幕说「要是你想跳过这一件，直接说「跳过」」。他照做之后，
那一件已经是 `collected`，回执只会再说一遍「你答了」，这个提示等于骗人。

两处一起改：

- **短指令在需要之前说。** 开场块现在写「想略过就说「跳过」；说错了，下一句说「改回上一题」。」
- **「改回上一题」是真的。** 它撤销上一件的结果（答了／跳了／搁下了都算），把那件重新问一遍，
  并记一条 `reading="undo"` 的事件。回执随后不再提那一件的旧结局。

这一处我自己写坏了三次，两次是“看起来对”：`continue` 只推进内层轮次循环，那件根本没重问；
改成插入又把被打断的那件漏掉。两次轨迹都正常。第三次是 `is_back_request` 的正则每组都可选，
所以**空行**也被读成「改回上一题」，「全部空着」那场在同一件上无限循环——被老测试抓到。

## 第四轮：续聊接回来的是另一个故事（监督者发现）

当场回执对了，关掉再 `--resume` 却把两件改了回来：撤回后跳过的情境又算答过；说了
「接下来两题」之后真的答了的失效又算搁下。

根因不是某个字段忘了存，而是**同一件事有两份重建**：当场用 `elicitation` 里的几个列表，
续聊用扫轨迹重新推一遍，而扫描只看「有没有过一条 answer 事件」，不看后来被撤回了。

现在只有一份：`elicitation_state(events)` 按顺序重放事件，**每件的最后一次记录说了算**。
当场的回执与 `_load_resume_trace` 都读它，`session_end` 里的 summary 是它的快照而不是
输入——否则又会变成两个真相。顺带改了两处：

- 「接下来两题」只覆盖一部分时不再当场结束（因此有机会改口），只有覆盖了剩下一整段才结束。
- 他走进了被搁下的那一件，那一件就不再算搁下，数量也不再重复。

当场与续聊的对照（`probe_resume_state.py`）：两个监督者场景都是 `SAME True`。

## 还证明不了什么

1. **没有人因此多说一件。** 这台机器上的轨迹仍然只有我的探针。
2. **范围解析是我定的写法，不是从真人语料量的。** 我用的句子是自己写的；`碰上的实词`
   一律按原话处理，所以宁可少识别、不替用户结束一场。真要提高覆盖率需要一段真人会话。
3. **数字只认中文一字到十。** 「再问两三个就不要了」这种含糊量词读不出来，按「剩下的继续问」。
4. **一行里可能列出四件名。** 真实终端宽度下没量过。
5. **卡片要不要被回答改，本片仍然没有表态。** 回执只说它没改。
6. **短指令只有说法，没有保证。** 「跳过」「改回上一题」是产品读得懂的两种短句；其他说法
   可能被当成原话收下。屏幕会当场说它理解成了什么，但不保证覆盖全部自然语言——那是这一版
   故意不做的（不写能懂所有句式的解析器）。
7. **「改回上一题」只退一件。** 连续退两件不行；说出两件之前的名字也不行。
