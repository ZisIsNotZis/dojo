# 理念、用户明确优先事项与临时 POC 设计

本文把用户明确说明的优先事项，与为了让一人能运行试验而暂拟的流程设计分开。`idea.md` 是较早的用户草案，不是当前产品承诺；只有下表列出的明确事项优先于草案冲突。

## 用户明确的优先事项

| 主题 | 明确事项 | 对原草案的修正 |
|---|---|---|
| 收集对象 | 道场匿名汇集理由、想法、经验主张及其关系，不限于已验证经验。纯抽象想法能揭示 AI 盲点，也有内在讨论价值。 | 不要求每个候选都来自真实实践。 |
| 可论与真 | 自洽只能使讨论有意义，不能证明真实或适用。讨论应顾及前提、适用性、替代解释和矛盾；矛盾可能有价值。 | 不把“逻辑自洽”当真理认证，不强迫所有矛盾收敛为一个答案。 |
| 经验证据 | 经验报告可能伪造。核对时必须区分独立来源和重复传播；不能据此编造成功概率。 | 不以重复次数、引用或声称替代核验。 |
| 匿名追踪 | 匿名 session ID 可支持推理、版本及反馈追踪，不建立公开个人归因。 | 匿名不是断绝论证/版本连续性。 |
| 场景与目标 | 面向陌生人的独立方法论讨论，不以共同团队或共同项目作为前提；主题可含空间整洁、软件开发与执行方法。一个人可扮演多个案例，不要求 5–8 名参与者；目标是澄清业务价值、痛点与别扭之处。当前 Demo 的具体方向与验收要求统一见 [current-demo-direction.md](current-demo-direction.md)。 | 不以多人招募、UI 或规模化假设作为启动前提，也不把道场等同于共同项目的技术排障助手。 |
| 角色和证据边界 | 角色要有具体知识、动机、信念、私有约束及披露触发点；actor 应留在角色内，不能自动变成有求必应的助手。 | 虚构角色只能测试流程脚本，不代表真实用户研究。 |

## 可撤销的 POC 设计选择（不是额外确认的产品决定）

最初的手工纸面试验及当前本地 CLI 都是 POC，不是新增的产品政策。以下流程与本地实现细节是为让单人可演练而选的临时做法，不能倒写成用户已确认的产品政策：

- **讨论方式的解释**：把“精确、可讨论的想法”和“可操作的应用”分开，是对用户要求的操作化；SMART 与否不是用户另行确认的规范。候选可保持抽象，不必硬转成行动目标。
- **流程与记录**：纸面阶段先提出 `abstain`、候选状态、可逆的 discussable confirmation、add/alias/link/split/merge 和 JSON 字段；当前 CLI 将其做成 SQLite 事务与版本/事件快照，是这轮授权的可运行 POC，而非既定产品数据契约。确认只表示“当前值得检索/继续讨论”，不代表真理。
- **留存默认值**：当前 CLI 将数据库与导出放在本机私有目录，不上传内容、不保存原始聊天；SQLite 记录只由操作者明确新增的候选/来源摘要产生。数据库会留存至操作者手动移除，本轮没有实现自动删除或 7 天 TTL。纸面规格提到的 7 天上限、如何删除、是否保存结构化摘记，以及未来公开/opt-in 规则仍是可改操作假设；不能把它们说成实现功能或用户已确认的产品政策。
- **实验方法**：CLI 可导出不含 seed 的 B 和带操作者所选摘录的 C；普通提示、强提示的完整同模型 A/B/C 流程、空/无关检索控制、随机顺序和评分表仍是人工实验方案，不是产品承诺或效果结论。默认演示不调用聊天 LLM；显式配置并选择实时模式时才允许 HTTP 模型请求。真实远端端点尚未验收。相关的可迁移 seed 是正向检索材料；无关 seed 只用于负控制。held-out 指独立编写、预先冻结且没有目标答案泄漏，不代表语义上必须和 seed 无关。
- **时间和样本**：先做 15–20 分钟的已有小包生命周期演练；之后可选做独立的 30–45 分钟转移比较。演练包自带 4 个候选，避免首跑前要求用户撰写 8–12 条种子；若以后扩展，数量另行试定。
- **评分及判读**：0–2 评分锚点及任何“几例值得再试”的门槛仅是探索性工作表，不是统计证明、成功率或产品效能。

## 保留的概念张力

抽象想法的讨论价值与经验可信度是不同维度。一个没有例证的观点可以有思想价值，但不可冒充实证建议；有细节的经验报告仍可能无法核验。不同主张可保留并相连，不需要用“常被重复”来推断更真。候选是否适用应回到其条件、来源和反例。

## 本 POC 不承诺

不承诺任何主张为真、已独立核验、能提高项目成功率或适用于普遍情境；不宣称市场契合或网络效应；不建设 UI、社交网络、公开排行榜、常驻数据库服务或计费系统；本地 SQLite 文件仅是当前 CLI POC 的私有存储；不以合成角色扮演代替真实实践证据。
