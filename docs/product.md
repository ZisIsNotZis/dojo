# 产品

本文是产品方向的事实入口，取代 `current-demo-direction.md` 此前对"当前产品方向"的声明；后者收窄为已实现 Demo 的说明。来源状态：本页方向由用户在 2026-10 对话中明确指示，交互与机制的细节仍是待实现、待检验的设计。

## 一句话

道场是一个对话式的真相蒸馏网络：用户像使用普通聊天产品一样说话，面向用户的主持 agent 负责引导、对齐与提炼，后台 agent 管线负责把结论归类、连接并在知识网络中上下传播。

## 结构性选择：两类 agent，都侍奉真相

| | 叶子 agent（面向用户） | 工作 agent（面向知识网络） |
|---|---|---|
| 职责 | 引导用户思考，对齐出带边界的结论，写入后台 | 分类、定位、批判、上下传播、合并建议 |
| 雇主 | 真相 | 真相 |
| 用户的位置 | 起点、信息提供者、被引导到高水平输出的思考者 | 不直接可见 |
| 可以牺牲 | 措辞、顺序、时机、包装 | — |
| 不可牺牲 | 实质结论 | 实质结论 |

判据：当"用户满意"与"真相"冲突时，叶子 agent 只能用表达方式解决冲突，不得用让步解决。

## 主循环

1. 用户以自然语言提出困扰、想法或经验。
2. 主持人引导：镜映 → 锐化 → 溯源 → 设界 → 升维。
3. 双方自然达成一致（用户一句反驳即可推翻），主持人复述带边界的结论。
4. 结论无声写入后台，用户不执行任何确认动作。
5. 会话结束触发管线：分类、定位、质询。
6. 结论与关系进入库；后续会话通过广播把它作为材料带回。

## 质量维度

| 维度 | 含义 | 观察方式 | 层级 |
|---|---|---|---|
| 引导力 | 一次会话能否产出带边界、可迁移的结论 | 会话结束的结论清单（用户过目即可，无需确认） | 接受 |
| 对齐真实性 | 结论是否真的经过质疑或修正 | 对话中的反驳/修正痕迹；用户接受或反对 | 接受 |
| 不奉承 | 面对错误主张是否退让 | 负控制场景：用户坚持明显过窄/过宽主张，观察是否让步 | 接受 |
| 体验对等 | 是否不低于现有聊天产品 | 用户动作数、表单数、失败降级是否清晰 | 接受 |
| 广播价值 | 他人结论是否改变了讨论 | 带广播 / 不带广播对照会话 | 接受 |
| 留存 | 用户是否愿意再用 | 回访率、反驳率（越高越好） | 目标，人工评审 |

保留的张力：一个没有例证的观点可以有思想价值，但不可冒充实证建议；重复出现不加权，独立来源才加权。

## 已知的条件保证

- 写入时机：只有**同意发生的那一轮**写入。空行与 EOF 只是“没有输入”，不请求模型、不写入、不消耗预算。
- 写入门槛：已有待处理结论、当轮 candidate 与它完全相同、且模型报告 `user_stance = "accept"`。旧的 `objection_gate` 已删除。
- 同一会话再次形成结论时，与已有结论相同或只有轻微措辞差异就不重复建卡；边界、前提或含义实质变化时，修订同一张卡的新版本。
- 对话中不展示 candidate 或后台处理提示；开场披露本地轨迹，结束时展示结论卡片 ID 与轨迹路径。
- 该保证的条件是**模型正确识别用户是否同意**。代码保证的是“模型说同意之后才写”，不保证模型不会把反对误报为 `accept`。
- 在零结构交互下，从自由文本推断同意只能依赖模型；要完全消除这条路径就必须让用户显式确认，那会破坏零结构负担的产品承诺。当前选择：接受这一条件风险，并以**可审计、可撤销**作为补偿——每次写入都在会话轨迹里对应着触发它的用户原话，判断错了能事后查出，可用 `revoke` 撤销。
- 未做的负控制：用户用真实文本反对、而模型误报 `accept` 的情形尚未实测（见 `plan.md` 的 M5 验收 ④）。在产品层，这只能作为风险证据，不得写成可靠性保证。

## 非目标

- 不建 UI、服务器、登录、社交、排行榜、信息流、计费系统。
- 不做真理裁判，不认证真假，只记录讨论状态与出处。
- 不做多节点联邦与公开注册。
- 阿里云部署与 token 商业模式在价值环被证明之后再议。
- 不以合成角色扮演代替真实用户研究。

见 `need.md` 的"非需求"与 `design.md` 的防风暴、防污染规则。
