# 产品

本文是产品方向的事实入口，取代 `current-demo-direction.md` 此前对"当前产品方向"的声明；后者收窄为已实现 Demo 的说明。来源状态：产品方向来自 2026-10 的讨论。2026-11-28 的对话门槛更新为先核对、再明确认可；下节说明这项交互变化。

## 一句话

道场是一个对话式的真相蒸馏网络：用户像使用普通聊天产品一样说话，面向用户的主持 agent 负责引导、对齐与提炼，后台 agent 管线负责把结论归类、连接并在知识网络中上下传播。

## 还没被挣得的主张

到 2026-10-23 为止，道库里只有一位真人的具体经历（`docs/dao/person-dojo`；第二份材料是我们自己写的模拟语料）。
所以「人类之间『道理』的数据库」仍然是**目标**，不是现状；第三条承诺（跨用户、公共）没有任何跨人的证据。
在第二个真人的材料进入之前，这个产品应当被读成**一个人的思想整理器**，不是「人类的道」。
凡是把这两句读成同一句的页面，以本段为准；实现到哪里、回执长什么样，看 `docs/dao/README.md` 与 `docs/plan.md` 的 K1 一节。

## 结构性选择：两类 agent，都侍奉真相

| | 叶子 agent（面向用户） | 工作 agent（面向知识网络） |
|---|---|---|
| 职责 | 引导用户思考，对齐出带边界的结论，写入后台 | 分类、定位、批判、上下传播、合并建议 |
| 雇主 | 真相 | 真相 |
| 用户的位置 | 起点、信息提供者、被引导到高水平输出的思考者 | 不直接可见 |
| 可以牺牲 | 措辞、顺序、时机、包装 | — |
| 不可牺牲 | 实质结论 | 实质结论 |

判据：当"用户满意"与"真相"冲突时，叶子 agent 只能用表达方式解决冲突，不得用让步解决。

## 主循环

1. 用户以自然语言提出困扰、想法或经验。
2. 主持人引导：镜映 → 锐化 → 溯源 → 设界 → 升维。
3. 主持人提出带边界的结论，程序并排展示原话、拟写内容、前提与未知。用户用自然语言纠正或补充。
4. 用户愿意保存屏上这一版时，单独输入 `/认可`。程序在本地保存版本和认可事件。未认可的说法可以留作草稿，从原场回执在本地复核；不进入普通搜索或另场交接。新场默认也不读取人物档案，只有明确选择继续自己的工作才启用。
5. 会话结束触发管线：分类、定位、质询。
6. 结论与关系进入库；后续会话通过广播把它作为材料带回。

## 质量维度

| 维度 | 含义 | 观察方式 | 层级 |
|---|---|---|---|
| 引导力 | 一次会话能否产出带边界、可迁移的结论 | 屏上可核对的拟写清单及条件 | 接受 |
| 对齐真实性 | 结论是否真的经过质疑或修正 | 对话中的反驳/修正痕迹；用户接受或反对 | 接受 |
| 不奉承 | 面对错误主张是否退让 | 负控制场景：用户坚持明显过窄/过宽主张，观察是否让步 | 接受 |
| 体验对等 | 是否不低于现有聊天产品 | 用户动作数、表单数、失败降级是否清晰 | 接受 |
| 广播价值 | 他人结论是否改变了讨论 | 带广播 / 不带广播对照会话 | 接受 |
| 留存 | 用户是否愿意再用 | 回访率、反驳率（越高越好） | 目标，人工评审 |

保留的张力：一个没有例证的观点可以有思想价值，但不可冒充实证建议；重复出现不加权，独立来源才加权。

## 写入与认可

讨论仍用自然语言。早期方案依据主持人判断自动写结论，实跑看到它把用户的收束话误判为同意。当前版本只在完整展示后收到单独的 `/认可` 才写认可，动作在本地完成。空行和模型给出的同意判断都不会写认可。结束时可以保留未认可草稿。

一次认可绑定实际展示的七个字段与保存时的卡片版本。原卡和新提议的适用范围不同时，各自保留来源与历史。仅因归一化相同而触发重复判断时，程序提示实际冲突。写入与认可在一次事务中完成。已有过的认可可以从会话轨迹、版本与事件逐项核对。

认可卡片和附上追问原话是两件事。被认可的是主持人拟写的版本；所选原话独立附在卡上，不改写拟写，也不算独立佐证。追问原话默认只在本场轨迹里，输入 `/附答` 明确选中的整句才随卡被读到，不从卡片反向暴露整场记录。见[离线入口复跑](evidence/2026-11-29-discuss-retention/README.md)。

这是用一次明确的确认换取准确的版本和出处。真实体验与实际做法的效用仍需各自验证。[离线复跑与真实线路证据](evidence/2026-11-28-review-before-accept/EXACT-VERSION.md)

## 非目标

- 不建 UI、服务器、登录、社交、排行榜、信息流、计费系统。
- 不做真理裁判，不认证真假，只记录讨论状态与出处。
- 不做多节点联邦与公开注册。
- 阿里云部署与 token 商业模式在价值环被证明之后再议。
- 不以合成角色扮演代替真实用户研究。

见 `need.md` 的"非需求"与 `design.md` 的防风暴、防污染规则。
